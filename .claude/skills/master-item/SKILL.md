# 마스터 아이템 추가 (마스터 데이터 → 아이콘 → 번들)

아이템 한 종을 추가하는 데 필요한 5단계를 **한 번의 요청으로** 처리한다. 각 단계는 `tools/master_item_tool.py`가 강제하는 규칙 위에서 돌아가므로, 이 문서의 순서를 그대로 따르면 정본 간 불일치가 생기지 않는다.

```
① 입력 해석 → ② 마스터 데이터 추가 → ③ 아이콘 생성 → ④ 이름 연결 → ⑤ 번들 갱신
```

## ① 입력 해석

사용자가 주는 것은 보통 **이름 · 종류 · 등급**이고, 장비면 **슬롯 · 직업**이 더 붙는다. 부족한 값은 아래 규칙으로 채우고, **되묻지 않는다**(정말 애매할 때만 묻는다).

| 항목 | 값 | 비고 |
|---|---|---|
| `item_type` | 1 장비 · 2 재료 · 4 소모품 | 재화(3)는 골드 1종 고정이라 추가하지 않는다 |
| `grade` | 1 노말 · 2 고급 · 3 희귀 · 4 영웅 · 5 전설 | |
| `equip_slot` | 1 무기 · 2 보조무기 · 3 투구 · 4 갑옷 · 5 장갑 · 6 신발 | 장비만 |
| `class_req` | 0 공용 · 1 기사 · 2 레인저 · 3 마법사 · 4 슬레이어 | 방어구는 보통 0(공용), 무기·보조무기는 직업 전용 |
| `item_code` | **자동 채번** | 지정하지 말 것 |
| `level_req`·`base_price` | **등급에서 자동 파생** | 명시 요청이 있을 때만 덮어쓴다 |
| 스탯 | 사용자가 안 주면 아래 "스탯 잡기" 참고 | 비장비는 전부 0 |

**스탯 잡기** — 같은 슬롯·등급의 기존 아이템을 `master-data-값.md` §6 (B) 표에서 찾아 **그 근처 값**으로 맞춘다. 직업 성향(§6 표 아래 설명)을 지킨다: 기사=고 공격력(대검은 `cooldown` 감소) · 레인저=공격력+치명확률 · 마법사=공격력+치명피해 · **슬레이어=최고 공격력+치명 계열** · 방패=체력·방어 · 슬레이어 갈고리=방어/체력 없이 공격·치명만.

## ② 마스터 데이터 추가

```bash
python tools/master_item_tool.py add --name "심연의 대도끼" --item-type 1 --grade 5 \
    --slot 1 --class-req 4 --atk 118 --crit-chance 0.09 --cooldown -0.1
```

여러 개면 JSON 배열로 한 번에 넣는다(`--json path.json`). 자신이 없으면 `--dry-run`으로 삽입될 줄을 먼저 확인한다.

이 명령이 하는 일 — 코드 채번 · 등급 파생값 · **`master-data-값.md` (A)(B) 표와 `master-data-schema.sql` INSERT에 코드 순서대로 삽입** · §6 「규모/현황」 개수 갱신 · **반영 직후 자동 재검증** · `tools/item-icon-manifest.json`(아이콘 작업 지시서) 출력.

실패하면(중복 이름·코드 소진 등) 메시지대로 고쳐 다시 실행한다. **파일을 직접 손으로 고치지 말 것** — 두 정본이 어긋나는 원인이 된다.

## ③ 아이콘 생성

지시서 `tools/item-icon-manifest.json`의 각 항목에 대해 **`pixel-item-icons` 스킬을 그대로 따라** PNG를 만든다. 그 스킬의 규칙(절차적 생성·수치 검증·팔레트 레지스트리 재사용)은 하나도 건너뛰지 않는다. 이 스킬이 추가로 요구하는 것은 두 가지뿐이다.

- **저장 위치**: `com2us-taskbar-hero-client/Assets/Art/Icon/Item/` (지시서 `_iconDir`)
- **파일명**: 지시서의 `iconSourceName` = **아이템 이름 그대로**(예: `심연의 대도끼.png`). 코드 이름으로 저장하지 않는다 — 이름으로 저장해야 pixel-item-icons의 세트 일관성 규칙과 팔레트 레지스트리가 그대로 동작한다. 코드 이름으로 바꾸는 것은 ④가 한다.

지시서에는 아이콘 컨셉을 잡는 데 필요한 정보(`gradeName`·`equipSlotName`·`classReqName`)가 함께 들어 있으므로 그것으로 모양·팔레트를 정한다.

## ④ 이름 연결

```bash
python tools/master_item_tool.py link-icons          # --dry-run 으로 먼저 확인 가능
```

지시서를 읽어 `<이름>.png` → `item_{code}.png`로 옮긴다. **`.meta`가 있으면 함께 옮겨 GUID를 보존**하므로 기존 참조가 끊기지 않는다. 이미 `item_{code}.png`가 있으면 건너뛰고, 원본을 못 찾으면 그 항목을 보고하고 종료 코드 1을 낸다(③으로 돌아간다).

## ⑤ 검증과 마무리

```bash
python tools/master_item_tool.py verify              # 오류 0 · 경고 0 확인(아이콘 존재 포함)
```

여기까지가 이 스킬의 책임이다. 마지막 반영은 **사용자가 Unity 에디터에서 메뉴 `TaskbarHero > 마스터 데이터 > 최신화 (DB→JSON)`** 를 한 번 실행하면 끝난다고 안내한다 — 그 메뉴가 `master_data_export.py`(schema.sql 재적용 + 클라 JSON 번들)와 **아이템 아이콘 DB 재생성까지 이어서** 수행한다. 에디터 조작은 사용자 몫이므로 대신 실행하려 하지 않는다.

- 사용자가 **CLI로 먼저 돌려 달라고 하면** `python tools/master_data_export.py`를 실행한다. 이 경우 MySQL과 `pymysql`이 필요하며, DB가 없거나 접속이 안 되면 **거기서 멈추고 그 사실을 알린다** — 앞 단계(정본·아이콘)는 이미 정상 반영된 상태다. 이때 아이콘 DB는 갱신되지 않으므로 Unity 메뉴 `TaskbarHero/UI/아이템 아이콘 DB 빌드`를 따로 안내한다.
- 아이템이 **가챠 풀·전리품 드롭·큐브 레시피**에 들어가야 한다면 그건 별도 마스터 테이블(`gacha_item_pool`·`stage_reward_drop`·`cube_recipe_ingredient`)이라 이 도구 범위 밖이다. 필요하면 사용자에게 알리고 해당 기획서를 따라 따로 처리한다.

## 보고 형식

작업이 끝나면 표로 짧게 정리한다 — **코드 · 이름 · 종류/등급 · 아이콘 경로 · 검증 결과**. 중간에 판단으로 채운 값(스탯·직업 등)은 무엇을 근거로 정했는지 한 줄씩 덧붙인다.

## 하지 말 것

- `master-data-값.md`·`master-data-schema.sql`을 손으로 편집(도구가 두 곳을 동시에 맞춘다)
- `item_code`를 임의로 지정(체계가 깨진다 — 필요하면 `next-code`로 확인만)
- 아이콘을 처음부터 `item_{code}.png`로 저장(pixel-item-icons의 세트 일관성 규칙이 깨진다)
- 검증(`verify`)에서 **오류**가 남은 상태로 완료 보고(경고는 사유를 적고 남겨도 된다)
