# 기획서 작성 스킬

Taskbar Hero 모작 프로젝트의 게임/서버 기획서를 작성한다. 모든 문서는 **한글**로 작성한다.

## 작성 위치

- 기획서는 저장소 루트의 `docs/` 폴더에 마크다운으로 저장한다. 폴더가 없으면 생성한다.
- 파일명은 `docs/<기능명>-기획서.md` 형식(kebab-case, 예: `docs/account-login-기획서.md`).

## 작성 절차

1. **범위 확인** — 무엇에 대한 기획인지(게임 콘텐츠 / 서버 기능 / 시스템)와 대상 서버(AccountServer, GameServer, Game.Common)를 먼저 명확히 한다. 불명확하면 사용자에게 질문한다.
2. **기존 문맥 반영** — CLAUDE.md, 관련 코드(`Program.cs`, `ErrorCode.cs` 등), 기존 `docs/` 문서를 읽고 일관성을 유지한다.
3. **템플릿에 맞춰 작성** — 아래 템플릿을 기준으로 하되, 해당 기획에 불필요한 섹션은 생략한다.
4. **계약 정합성 확인** — 서버-클라이언트 공유 요소(에러 코드, API 응답 구조 등)는 `Game.Common`의 기존 정의와 충돌하지 않는지 확인하고, 새 에러 코드가 필요하면 명시한다.

## 기획서 템플릿

```markdown
# <기능명> 기획서

## 1. 개요
- 목적: 이 기능이 왜 필요한가 (한 문단)
- 대상 서버: AccountServer / GameServer / Game.Common
- 관련 기획서: [[다른 문서]]

## 2. 게임/기능 설명
- 사용자 관점에서 무엇을 할 수 있는가
- 방치형(idle) 게임 특성상 고려사항(오프라인 보상 계산 등)이 있으면 명시

## 3. 요구사항
- 기능 요구사항 (목록)
- 비기능 요구사항 (성능, 동시성, 저장 주기 등)

## 4. 데이터 모델
- 저장해야 할 데이터와 필드(타입 포함)
- 클라이언트-서버 공유 DTO는 Game.Common 배치 여부 명시

## 5. API 명세
각 엔드포인트마다:
- Method + 경로 (예: `POST /account/login`)
- 요청 파라미터 / 바디
- 응답 바디 (성공/실패)
- 사용하는 GameErrorCode 값

## 6. 처리 흐름
- 주요 시나리오의 단계별 흐름 (필요 시 순서도/의사코드)
- 예외/엣지 케이스

## 7. 에러 코드
- 신규로 필요한 GameErrorCode 항목과 제안 값 (기존 값과 중복 금지)

## 8. 미결 사항 / TODO
- 아직 결정되지 않은 부분
```

## 원칙

- 결정된 사실과 미결 사항을 명확히 구분한다. 임의로 수치·정책을 확정하지 말고, 정해지지 않은 것은 "8. 미결 사항"에 남긴다.
- 에러 코드 숫자 값은 클라이언트와의 계약이므로 신규 제안 시 기존 `GameErrorCode`와 겹치지 않게 한다.
- 코드 구현이 아니라 명세 정리가 목적이다. 요청이 없으면 실제 코드는 작성하지 않는다.
