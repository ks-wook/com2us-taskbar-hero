# 전투 연출 개선 아이디어 (관전 재미)

> **성격**: 제안 문서. 항목의 상태 기호는 착수·완료에 맞춰 갱신한다(☐ 미착수 · ◐ 진행 중 · ☑ 완료 · ✗ 미채택).
> **작업 위치**: 전투는 `BattleDevScene`이 정본이다. 여기서 만들고 에디터 메뉴
> **`TaskbarHero/UI/던전 전투 배선`**을 다시 실행해 GameScene에 복제한다(GameScene을 직접 손대지 않는다).

## 1. 진단 — 때리는 연출은 있고, 맞는 반응이 없다

전투 코드를 훑은 결과, **연출 훅은 이미 구현돼 있는데 호출하는 코드가 없는 상태**였다.
이펙트·사운드(공격하는 쪽)는 풍부한데 **피격 측 반응이 전무**해서, 데미지 숫자만 뜨고 몬스터는 태연히 걸어왔다.
이것이 "보는 재미가 부족하다"의 직접적 원인이다.

| 항목 | 현재 상태 |
|---|---|
| `SpumCharacterAnimator.PlayDamagedOnce()` | **몬스터 피격에 배선됨**(`MonsterUnit.PlayHitReaction`). 아군 피격은 아직 호출자 없음 |
| `MonsterUnit.TakeDamage()` | HP 차감 + 데미지 관문이 피격 반응 3종(모션·틴트·넉백)을 재생한다 |
| 카메라 흔들림 | 스킬 타격·처치에만 3단 진폭으로 흔든다(`BattleDevController.RequestShake`) + 상시 미세 스웨이 |
| 히트스톱 | 큰 타격(치명타·스킬·보스)에 걸린다(`BattleDevController.RequestHitStop`). 클리어·패배 슬로우모션(`DungeonBattleFlow`·`BattleDefeatOverlay`)과는 서로 침범하지 않는다 |
| 적 HP바 | 위치 추적 + 지연 고스트 바·피격 흔들림(`UpdateEnemyHpBars()`) |
| 데미지 숫자 | 흰색 / 치명타는 노란색 + 큰 팝 + `!`. 좌우 산포·광역 시차·피해 비중 크기 적용 |
| 근접 공격 | 평타마다 앞으로 파고들었다 복귀(lunge) |
| 처치 | 붉은 플래시 + 뒤·위로 날아가며 회전·페이드 후 소멸 |
| 보상 획득 | 스테이지 클리어 오버레이가 닫힐 때 보상 칸이 HUD(가방·편성)로 날아 들어간다(`RewardFlyFx`) |
| 보스 리듬 | 공격 0.6초 예고(발밑 마커 + 뒤로 웅크리는 준비 동작) · HP 70%/30% 페이즈 전환(포효·주기 단축·비네트) |

## 2. 1순위 — 「타격감 패치」

훅이 `MonsterUnit`·`BattleDevController` **두 파일에 모여 있어** 변경 범위가 좁고, 근본 원인을 직접 때리므로
체감 대비 비용이 가장 낮다.

| 상태 | 항목 | 내용 · 배선 지점 |
|---|---|---|
| ☑ | **피격 반응 3종** | ① `PlayDamagedOnce()` ② **붉은 틴트**(SPUM 파트 2~3프레임) ③ **넉백 슬라이드** — **기본공격은 밀지 않고**, 스킬 0.9유닛 · 기사 방패 돌진 3.2유닛. `MonsterUnit.PlayHitReaction(heavy, knockback)`에 모아 두고 데미지 단일 관문(`DoDamageAfter`·`DoAreaDamageAfter`)에서 호출한다 → 기본공격·스킬·투사체·돌진 전 경로에 적용. 자세한 결정은 [§2.1](#21-피격-반응-3종-구현-메모) |
| ☑ | **히트스톱** | 큰 타격(치명타·스킬·보스 피격)만 `timeScale 0.05`로 0.06초(보스 0.09초). `BattleDevController.RequestHitStop`이 쿨다운·중복·다른 슬로우모션을 걸러 낸다. 자세한 결정은 [§2.2](#22-히트스톱-구현-메모) |
| ☑ | **카메라 셰이크** | **스킬 타격 + 처치에만** 건다 — 기본공격(치명타 포함)에는 없음 / 일반 0.08 / 보스·스킬 광역 3체 이상·처치 3체 이상 0.18(월드 유닛, 0.18초 감쇠). 팔로우 결과 위에 오프셋으로 얹는다 |
| ☑ | **HP바 juice** | 흰색 **지연 고스트 바**(0.18초 유지 후 따라 내려오며 방금 깎인 양 노출) + 피격 시 바 3px 흔들림. 상태는 <b>몬스터에</b> 두고(`HpGhostRatio`·`HpBarShake01`) `UpdateEnemyHpBars()`가 읽는다 |
| ☑ | **데미지 숫자 산포** | 시작 위치 좌우 ±0.32·상하 ±0.12 흩기 + 수명 동안 좌우 ±0.28 흐름 + 광역 대상별 0.05초 시차 + **피해 비중에 따른 크기**(0.9~1.35배) |

자세한 결정은 [§2.3](#23-셰이크hp바-juice데미지-숫자-구현-메모).

- **넉백 복귀는 `MonsterUnit`의 전진 로직이 그대로 처리한다** — `_targetX`를 향해 스스로 걸어오므로 되돌아오는 동작을 따로 만들 필요가 없고, 속도 배수만 얹으면 된다.

### 2.1 피격 반응 3종 구현 메모

`MonsterUnit.PlayHitReaction(bool heavy, float knockback)` 하나에 3종을 모았고, 데미지 단일 관문에서만 호출한다.
넉백 거리는 **관문 인자로 받는다**(`DealDamageAfter(..., knockback)`) — 그래서 공격 종류마다 세기를 다르게 줄 수 있다.

| 공격 | 넉백 |
|---|---|
| 기본공격 | **없음(0)** — 초당 여러 번 들어오는 평타마다 밀리면 몬스터가 전선에 붙지 못하고 계속 떠 있는 것처럼 보인다 |
| 일반 스킬 | `MonsterUnit.SkillKnockback` = 0.9(몸 폭 하나) |
| 기사 **방패 돌진**(스킬 101) | `MonsterUnit.ChargeKnockback` = 3.2(화면 폭의 1/5) + **전방의 적 전부**를 함께 밀어낸다 |

| 결정 | 값 · 이유 |
|---|---|
| **플래시는 흰색이 아니라 붉은 틴트** | `SpriteRenderer.color`는 텍스처에 **곱**해지므로 흰색을 넣으면 아무 변화가 없다(정점 색이 `Color32`로 클램프되어 1을 넘길 수 없어 밝게 만들 수 없다). 흰 실루엣을 만들려면 전용 셰이더 + Always Included 등록 + 파트 30개마다 머티리얼 교체가 필요하다 — 붉은 틴트 `(1, 0.42, 0.38)`는 곱 연산만으로 "맞았다"로 읽히고 비용이 0이다 |
| **틴트 0.08초 · unscaled 시간** | 약 2~3프레임. `Time.unscaledDeltaTime`으로 재므로 일시정지 중에 붉은 틴트가 굳지 않고, 나중에 히트스톱(`timeScale` 감속)을 넣어도 점멸이 20배로 늘어지지 않는다 |
| **넉백은 순간이동이 아니라 슬라이드** | 처음엔 `0.22`를 즉시 더했는데 **눈에 보이지 않았다**(몸 폭 0.885의 1/4을 1프레임에 이동 = 사실상 텔레포트). 지금은 맞은 순간 밀릴 거리를 예약해 미끄러뜨린다 — 기본 `9유닛/초`이고, **먼 거리는 속도를 올려 0.28초 안에** 밀어낸다(3.2유닛을 기본 속도로 밀면 0.36초가 걸려 "날아갔다"가 아니라 "끌려갔다"로 보인다) |
| **최대 밀림 3.5(강한 밀치기는 그 거리+0.6) · 복귀 3배 속도** | 연타로 무한히 밀려나지 않게 목표 라인 기준 한계를 두고(화면 폭 17.8 안), 밀림이 끝나면 평소 이동속도의 **3배**로 전선까지 되돌아온다. 보스는 `×0.35`만 밀린다(무게감). 한계 밖(=아직 멀리서 접근 중)인 적은 위치를 건드리지 않는다 |
| **방패 돌진은 데미지가 아니라 밀치기만 확장** | "밀치는 것"이 스킬 정체성이라 방패에 부딪힌 전방 적 전부가 날아가야 한다. 그렇다고 광역 데미지로 바꾸면 **전투 수치가 달라지므로**, 데미지는 그대로 단일 대상이고 `ShoveEnemiesAhead`가 사거리+1.8 안의 적들을 **데미지 없이** 밀어낸다(피격 모션·틴트·숫자도 붙이지 않는다 — 맞은 게 아니라 부딪혀 밀린 것이다) |
| **넉백이 전투 효율을 바꾸지 않게 한 두 가지** | ① **아군 DPS는 원래 거리 무관** — 공격 대상은 `FrontMonster`라 멀리 밀려도 그대로 맞는다 ② **몬스터 공격 주기는 밀려 있는 동안에도 계속 찬다**(`_attackTimer`를 위치와 무관하게 누적) — 주기가 멈추면 맞을수록 몬스터가 덜 때려서 넉백이 곧 난이도 하향이 된다. 단 **때리는 위치는 그대로 전선**이고, 접근 중(전선에 한 번도 닿지 않은 동안)에는 누적하지 않아 도착 즉시 때리는 일은 없다 |
| **피격 모션 생략 조건 2가지** | ① **공격 모션 중**(0.5초) — 피격 모션이 공격을 끊어 몬스터가 때리지도 못하고 계속 움찔거린다 ② **이미 움찔거리는 중**(0.3초) — 연타·광역에서 모션이 매 프레임 재시작해 자세가 굳어 보인다. 두 경우 모두 틴트는 갱신되므로 피드백은 남는다 |
| **피격 후 걷기 모션 복원** | SPUM은 피격 모션이 끝나면 IDLE로 떨어지는데 `_moving`은 그대로여서 `SetMoving`이 아무것도 보내지 않는다 → **걷는 몬스터가 차렷 자세로 미끄러진다.** 모션이 끝나는 시점에 그때의 상태(`PlayMove`/`PlayIdle`)를 다시 보낸다 |
| **광역은 대표 1회 + 나머지 틴트만** | `heavy: hit == 0` — 피격음이 첫 대상만 울리는 것과 같은 기준(제약 §5) |
| **프레임당 1회 제한** | 같은 프레임에 여러 타격이 겹쳐도 연출은 1회(상주 소형 창 — 과한 점멸 금지) |
| **죽은 대상은 제외** | 마지막 타격의 피드백은 사망 모션·사망음이 맡는다(피격 모션을 겹치면 사망 모션이 끊긴다). 사망 시 틴트를 즉시 걷어내 붉은 채로 죽지 않게 한다 |

**스크립트만 바뀌므로 `던전 전투 배선` 빌더 재실행은 필요 없다** — 씬·프리팹 오브젝트나 직렬화 필드가 늘지 않았고, GameScene의 복제본도 같은 스크립트를 참조한다.

**검증**(BattleDevScene 플레이 모드): 틴트 적용 `(1, 0.42, 0.38)` · 모션 전이 `0_move → 0_Damaged` · 0.08초 뒤 색 복귀와 `0_move` 복원 · 같은 프레임 재타격 시 추가 반응 없음 · `heavy: false`는 틴트만(넉백 0 · 모션 유지) · 죽은 대상은 반응 없음.
넉백은 `timeScale 0.05`로 늘려 슬라이드를 샘플링했다 — 타격 프레임에는 위치 변화 0(순간이동 아님), 이후 프레임에서 `+0.34 → …`로 밀려나고, 원속도로 되돌린 뒤에도 몬스터가 전선(아군과 1~2유닛)에서 정상적으로 죽는 것을 확인했다(전투가 늘어지지 않음).
공격별 넉백 세기도 실측했다 — **기본공격 +0**(밀림 없음) · 스킬 밀림 발생 · **방패 돌진 밀치기 +2.872유닛**(요청 3.2, 대상이 이미 약간 밀려 있어 한계에서 잘림. 진행 곡선 `0.06 → 2.71`로 약 0.26초에 걸쳐 미끄러짐).

### 2.2 히트스톱 구현 메모

`BattleDevController.RequestHitStop(seconds)` + `HitStopRoutine` (같은 데미지 관문에서 호출).

| 결정 | 값 · 이유 |
|---|---|
| **큰 타격에만** | 치명타 · **스킬 타격** · 보스 피격. 평타 연타에 걸면 전투가 계속 끊겨 보이고 "강한 한 방"이라는 대비가 사라진다 |
| **스킬 여부는 명시 인자로 판단** | `DealDamageAfter(..., bool bigHit = false)` — 라벨 문자열을 파싱하거나 "광역이면 스킬"로 추정하지 않는다(**광역 평타**가 실제로 있다: 사거리 내 다중 명중 평타). 스킬 호출 지점 7곳(강타류·화살비·내려찍기·돌진·투사체 스킬·자기중심 광역)만 `bigHit: true`를 넘긴다 |
| **0.05배 × 0.06초(보스 0.09초)** | `timeScale`을 완전히 0으로 두면 애니메이터가 굳어 부자연스럽다. 사운드는 `AudioSource`라 배율과 무관하게 정상 속도로 울린다 |
| **쿨다운 0.3초 · 중복 금지** | 히트스톱은 그 시간만큼 전투를 실제로 멈추므로, 무제한이면 전투가 늘어진다. 실측 6초 구간에서 정지 2회 · 총 0.132초(2.2%)였다 |
| **다른 슬로우모션에 끼어들지 않음** | 시작 조건에 `timeScale ≈ 1`을 넣어 클리어·패배 슬로우모션(`DungeonBattleFlow`·`BattleDefeatOverlay`) 중에는 걸지 않고, 정지 도중 그런 연출이 시작되면 원복하지 않는다(우리 값 `0.05`일 때만 1로 되돌린다) |
| **끝날 때 반드시 원복** | 대기는 `WaitForSecondsRealtime`(정지 중에는 스케일 시간이 거의 안 흐르므로 스케일 대기를 쓰면 풀리지 않는다). `OnDestroy`에서도 원복해 씬 전환·플레이 종료로 0.05배가 남는 것을 막는다 |
| **지연 사운드는 스케일 시간을 유지** | §5의 "임팩트음 대기를 `WaitForSecondsRealtime`으로 바꿔야 한다"는 **적용하지 않았다.** 애니메이션도 같은 배율로 느려지므로 스케일 대기가 오히려 **소리와 동작을 붙여 준다**(실시간으로 바꾸면 스윙이 멈춘 채 타격음이 먼저 난다). 밀리는 양도 정지 1회당 ≤0.06초다. 히트스톱을 길게(0.3초+) 늘릴 때 다시 검토할 지점 |

**검증**(BattleDevScene 플레이 모드): 프레임 단위로 `Time.timeScale`을 6초간 700프레임 샘플링 — 정지 구간 2회 · 정지 프레임 13 · 정지 총 0.132초 · 최소 배율 0.05 · **종료 시 1.0으로 복귀**. 컴파일 오류 없음.

### 2.3 셰이크·HP바 juice·데미지 숫자 구현 메모

| 결정 | 값 · 이유 |
|---|---|
| **셰이크는 스킬 타격·처치만(치명타·보스 피격 제외)** | 처음엔 히트스톱과 같은 조건(치명타·스킬·보스)으로 걸었는데, **기본공격에도 치명타가 자주 떠서** — 보스전에서는 평타마다 — 화면이 거의 상시 흔들렸다. 히트스톱은 그대로(치명타 포함) 두고 셰이크만 `bigHit`(스킬)로 좁혔다. 광역도 **평타 광역**이 있어 같은 기준으로 가른다 |
| **처치는 평타로 쓰러뜨려도 흔든다** | 치명타를 뺀 대신 남긴 타격감 지점. 치명타(평타의 일정 확률 = 초당 여러 번)와 달리 처치는 몬스터 한 마리를 없애야 발동하므로 빈도가 낮고, "성과가 났다"는 신호와 결이 맞는다. 진폭은 **일반 처치 0.08(약)** · 보스 처치·3체 이상 동시 처치만 0.18(강). **슬로우모션은 여기에 얹지 않는다** — 시간 배율은 전투를 실제로 멈추므로 웨이브 종료(마지막 한 마리)에만 걸린다([§3](#3-2순위--전투의-리듬-만들기)) |
| **셰이크는 펄린 노이즈 대신 감쇠 사인** | 처음엔 펄린 노이즈로 넣었는데 값이 0.5 근처에 몰려 **지정 진폭의 20%만 나왔다**(0.06 지정 → 실측 최대 0.013유닛 ≈ 1px로 사실상 안 보임). 사인으로 바꾸니 같은 조건에서 0.0437유닛까지 나온다. 0.18초 버스트라 주기성은 눈에 띄지 않는다 |
| **가로 위주(세로 70%)** | 횡스크롤 전투라 가로 흔들림이 타격 방향과 맞는다. x·y는 주파수·위상을 달리해 같은 대각선만 왕복하지 않게 한다 |
| **팔로우 위에 오프셋으로 얹기** | 카메라 x는 매 프레임 팔로우가 다시 계산하고 y는 `_camBaseY`에서 다시 잡으므로 흔들림이 누적되지 않는다(카메라가 떠내려가지 않는다). `_camBaseY`는 `Start`에서 씬이 잡아 둔 프레이밍 y를 캡처한다 |
| **HP바 상태는 몬스터에 둔다** | HP바 오브젝트는 **인덱스로 재사용되는 풀**이라 같은 몬스터가 매 프레임 같은 바를 쓴다는 보장이 없다(죽거나 스폰하면 인덱스가 밀린다). 고스트 비율·흔들림 강도를 `MonsterUnit`에 두면 바가 어느 인덱스로 가든 값이 따라간다 |
| **고스트는 채움보다 먼저 만든다** | 같은 부모에서 자식 순서 = 그리기 순서. 고스트(흰색)가 아래에 깔리고 붉은 채움이 그 위를 덮으므로, 덮이지 않고 남는 오른쪽 구간이 곧 "직전 → 현재" 차이가 된다 |
| **바 흔들림 3px** | 바가 96×18px이라 크게 흔들면 숫자·프레임이 읽히지 않는다. 세로는 가로의 60%만 |
| **숫자 크기는 절대 데미지가 아니라 피해 비중** | 절대값은 성장에 따라 3자리 → 6자리로 계속 커져 "큰 타격" 기준이 사라진다. 최대 체력의 절반을 날린 한 방은 어느 구간에서든 큰 타격이다 |
| **광역 시차는 실시간 대기** | 0.05초씩 미루는데 히트스톱(0.05배) 중이라면 스케일 대기로는 20배(1초)로 늘어져 숫자가 한참 뒤에 뜬다 |
| **연출 시간은 모두 unscaled** | 셰이크·바 흔들림·숫자 시차 모두 히트스톱 중에도 진행돼야 "시간이 멈춘 채 화면만 흔들리는" 임팩트가 산다 |
| **`StopAllCoroutines` 지점마다 시간 배율 원복** | 재시작(`ResetBattlefield`)이 코루틴을 모두 죽이므로 히트스톱 코루틴도 함께 죽는다 → 원복 코드가 실행되지 않아 **0.05배로 멈춘 채 재시작**된다. `CancelTimeEffects()`를 재시작·`OnDestroy` 양쪽에서 부른다 |

**검증**(BattleDevScene 플레이 모드): 셰이크 — 6초/1062프레임 중 흔들림 29프레임·1구간, 최대 y편차 0.0437유닛(화면 높이의 0.44%), 종료 후 편차 0. HP바 — 1뎀 후 같은 프레임에 `고스트 1.000` vs `현재 0.974`(지연 유지 확인) · `바흔들림 1.0`. 숫자 — 같은 좌표에 5개 요청 시 x가 −0.318~0.242로 흩어지고 크기 1.265~2.048로 갈리며, 시차 때문에 상승 진행도(y 0.194~0.775)가 서로 달랐다.

> **측정 주의** — **플레이 중에 스크립트를 고치면 도메인 리로드로 `ObjectManager`의 추적 목록이 끊겨 전투가 조용히 깨진다**(광역 반경 100에도 `0체`, 데미지·연출이 전혀 발생하지 않음). 실제로 이 상태에서 "셰이크 0회"를 관측했다. 코드를 고친 뒤 측정할 때는 **플레이를 껐다 다시 켜고** 재측정한다.

| ☑ | **근접 lunge** | 근접 평타마다 0.32유닛 앞으로 파고들었다(0.06초) 복귀(0.12초). `PlayerCombatant.BasicAttack()`의 근접 분기 |

| ☑ | **보스 페이즈 전환** | HP **70% · 30%** 통과 시 포효(`SoundId.BossRoar`) + 공격 주기 ×0.78 + 화면 가장자리 붉은 비네트 플래시(0.55초) |

### 3.1 2순위 구현 메모

| 결정 | 값 · 이유 |
|---|---|
| **예고 마커·비네트는 절차적 스프라이트** | 둘 다 "반경에 따른 알파 그라디언트"일 뿐이라 아트·임포트·에디터 배선 없이 코드로 굽는다(`BattleFxTextures`, 64²·96², 정적 캐시로 전 전투 공유). 아트 의존이 없으니 텍스처 미배선으로 연출이 조용히 빠지는 일도 없다 |
| **애니메이터를 멈춰 예고를 만들지 않는다** | 처음엔 `PlayCastHold`(공격 애니를 중간 프레임에서 정지 → 지정 시간 뒤 재개)를 재사용했는데 **"때리려다 마는" 동작**이 됐다. 실측 원인 3가지 — ① 정지 지점 `nt 0.14`가 마법사용 값이라 몬스터 클립에서는 거의 시작점(살짝 들었다가 멈춤) ② `Animator.speed = 0`이 애니메이터 **전체**를 멈춰 피격·이동 모션까지 굳음 ③ 재개가 타격보다 늦어 스윙과 타격이 어긋남. 지금은 예고 동안 애니를 건드리지 않고 **마커 + 위치·크기 준비 동작**만 주고, 예고가 끝나는 순간 `PlayAttackOnce`를 보내 스윙과 타격을 같은 프레임에 맞춘다(부수 효과: "magic" 클립을 찾던 홀드 대신 몬스터의 **정상 공격 클립** `0_Attack_Normal`이 재생된다) |
| **예고 중에는 이동 판정을 하지 않는다** | 준비 동작이 뒤로 밀어내는 것과 "목표 라인으로 되돌아가기"가 매 프레임 맞서면 `0_move ↔ 0_idle`이 프레임마다 토글돼 캐릭터가 떠는 것처럼 보인다(실측). 빙결과 같은 방식으로 예고 중 이동 분기를 건너뛴다. 준비 동작 위치는 lunge처럼 **차이만 더해** 넉백과 싸우지 않게 한다 |
| **SPUM 홀드 코루틴의 중단 버그도 고쳤다** | `StopCoroutine(nameof(...))`은 **문자열로 시작한 코루틴만** 멈춘다 — `PlayCastHold`·`PlayArrowRain`이 이 패턴이라 연속 호출 시 이전 홀드가 살아남아 `Animator.speed`를 0/1로 엎어쓰다 **애니메이터가 멈춘 채 남을 수 있었다**(마법사 캐스트·레인저 화살비도 해당). 코루틴 핸들로 중단하고 중단 시 `speed = 1`을 복구한다 |
| **예고 중에도 공격 주기는 그대로** | 주기 누적은 위치·예고와 무관하게 진행되므로(넉백 때와 같은 이유) 예고 0.6초가 보스 DPS를 깎지 않는다 — 실측 5초에 6회 타격 |
| **마커는 보스마다 1회 생성** | 공격마다 만들면 보스 한 마리가 전투 내내 수십 개를 생성/파괴한다. 만들어 두고 켜고 끄며, 보스가 3배로 확대돼 있으므로 왕관과 같은 방식으로 부모 스케일을 나눠 보정한다 |
| **처치 연출은 죽은 몬스터 자신을 날린다** | 새 오브젝트를 만들지 않으므로 웨이브 전멸(동시 최대 12마리)에서도 생성/파괴가 늘지 않는다(제약 §5의 풀링 요구를 이 방식으로 충족). 알파는 이미 캐시해 둔 SPUM 파트 배열을 재사용해 낮춘다 |
| **플래시 → 페이드 순서** | 사망 순간 0.08초 붉은 플래시 뒤 0.15초부터 알파를 내린다. 순서를 겹치면 플래시가 반투명해져 "마지막 한 방"이 약해진다 |
| **보상 오브는 처치가 아니라 클리어 시점에** | 이 게임은 **처치당 보상이 없다** — 골드·경험치는 스테이지 클리어 시 서버 응답으로 지급된다(`DungeonBattleFlow`·`StageClearOverlay`). 처치마다 오브가 날아가면 **받지 않은 보상을 받은 것처럼** 보이므로, 지급 구조는 그대로 두고 **클리어 오버레이가 닫히는 순간** 보상 칸을 HUD로 날려 보낸다(`RewardFlyFx`) |
| **목표는 그 값을 확인하는 곳으로** | 경험치 → **편성**(캐릭터), 골드·전리품 → **가방**. 메뉴 바가 접혀 있으면 버튼이 폭 0으로 눌려 있어 어디로 갔는지 알 수 없으므로 항상 보이는 **토글 손잡이**로 보낸다 |
| **비행 연출은 오버레이 밖의 독립 오브젝트** | 오버레이는 닫히는 순간 파괴되므로 그 자식으로 만들면 날아가는 도중 함께 사라진다. `RewardFlyFx`는 자기 Canvas(`UiSortingOrder.Topmost`)를 가진 싱글턴이고, 오버레이는 **위치·아이콘을 값으로 캡처**해 넘긴다. 오브는 풀로 재사용한다 |
| **HUD 목표는 델리게이트로 주입** | 어셈블리 참조가 `UI → Battle` 한 방향이라 전투 코드가 HUD를 직접 찾을 수 없다. HUD가 `RewardFlyFx.TargetProvider`에 자기 목표 제공 함수를 등록하고(파괴 시 해제), 전투 쪽은 "누가 주는지 모르는 목표"만 받는다 — 순환 참조 없이 해결 |
| **lunge는 절대 좌표가 아니라 차이만 적용** | 대형 추격·돌진이 같은 transform을 움직이므로, 절대 위치로 복귀시키면 그 이동을 취소해 캐릭터가 뒤로 끌린다. `_lungeApplied`와의 차이만 더한다 |
| **카메라는 lunge를 따라가지 않는다** | 카메라 x는 최전방 아군을 그대로 따라가므로, lunge(0.32유닛을 0.18초에 왕복)가 팔로우 기준에 들어가면 **기본공격마다 카메라가 왕복해 셰이크처럼 보인다**(2026-08-05 수정). 팔로우 기준을 `transform.position.x`에서 **`PlayerCombatant.CameraFollowX`**(= 위치 − `_lungeApplied`)로 바꿔 연출 오프셋만 뺀다. 대형 이동·돌진처럼 **실제로 이동한 결과**는 그대로 따라간다. 세로 흔들림(내려찍기 점프 등)은 카메라 y가 `_camBaseY` 고정이라 애초에 영향이 없다 |
| **웨이브 슬로우는 쿨다운을 보지 않는다** | 히트스톱과 창구(`RequestTimeScale`)는 공유하지만, 마지막 처치의 히트스톱 쿨다운에 삼켜지면 정작 마무리 박자가 사라진다. 대신 "다른 연출이 시간 배율을 잡고 있으면 안 건다"는 규칙은 그대로 지킨다 |
| **비네트는 전투 밴드 안에만** | `GameAreaRect`로 붙여 좌우 UI 패널 영역까지 붉어지지 않게 한다. 시간은 unscaled — 같이 터지는 셰이크·히트스톱과 결을 맞춘다 |

**검증**(BattleDevScene 플레이 모드)
- 텔레그래프: 마커 노출 확인(최대 알파 0.55까지 점점 진해짐) · 예고 이후 실제 타격이 들어가 아군 체력이 5초에 **6회** 감소.
- 텔레그래프(모션 수정 후 재측정): `Animator.speed = 0` 프레임 **0개** · 예고 중 `move/idle` 토글 **1회**(진입 전환뿐) · 준비 동작 크기비 **1.000~1.050** · 사이클이 `마커 ON → 준비 동작 → 마커 OFF → 0_Attack_Normal nt=0.00`로 이어지고 아군 피격도 정상 발생.
- 처치 연출: Δx **+2.12** · Δy **+1.07** · 회전 **137°** · 알파 1 → **0.27**(측정 창 0.3초, 이후 소멸).
- 보상 획득 연출(GameScene): 목표 해석 — 메뉴 펼침 시 골드·전리품 `InventoryButton` / 경험치 `PartyButton`, 접힘 시 `MenuToggleButton` 폴백. 샘플 클리어 오버레이를 닫으면 오브 **최대 4개**가 동시에 날아가고(궤적이 목표 방향으로 진행), 비행 종료 후 활성 오브 **0개**(풀 회수 정상, 풀 크기 7).
- 웨이브 종료 슬로우: 마지막 처치 순간 `timeScale` **0.3** → 이후 **1.0** 복귀.
- 근접 lunge: 프레임당 최대 전진 **0.0329유닛**(lunge 속도 ≈5.3유닛/초 상당, 평소 대형 추격보다 큼).
- 카메라가 lunge를 따라가지 않는지(2026-08-05): 4초 599프레임 중 **lunge 진행 30프레임 · 최대 lunge 0.320유닛**인 구간에서 `|camX − (CameraFollowX + camOffsetX)|` 최대 **0.095유닛**(상시 스웨이 0.06 + 셰이크 x성분으로 설명되는 값)이고, 같은 구간을 옛 기준으로 재면 `|camX − (transform.x + camOffsetX)|`가 최대 **0.318유닛** = lunge 진폭 그대로 어긋난다(수정 전이라면 카메라가 그만큼 왕복했다는 뜻). 프레임 간 카메라 후퇴는 최대 **0.038유닛**.
- 보스 페이즈: HP 70% 통과 시 비네트 캔버스·이미지 생성 + 최대 알파 **0.55**, 포효·주기 단축 동작.

### 4.1 3순위 구현 메모

| 결정 | 값 · 이유 |
|---|---|
| **분기는 스킬 코드로** | 이 연출들은 마스터 데이터 수치(계수·범위)로는 구분되지 않는 **연출 고유 특성**이다. 스킬 코드는 마스터의 고정 키라 이름 문자열보다 안전한 분기 기준이다(`PlayerCombatant`의 상수 5개: 103·302·303·401·402) |
| **빙결은 이동만 멈춘다** | 공격 주기까지 멈추면 **연출이 난이도를 바꾼다**(넉백에서 세운 기준과 같다). 파란 틴트는 기존 피격 틴트 경로를 공유하고, 빙결 중에 맞아 붉은 틴트가 덮으면 **원색이 아니라 파란 틴트로 복귀**한다(그러지 않으면 아직 얼어 있는 몬스터가 멀쩡한 색으로 풀린다) |
| **섬광은 옅게·짧게** | "1프레임 백색 플래시"를 불투명하게 넣으면 상주 소형 창에서 눈이 피곤하다(제약 §5). 알파 0.35 × 0.09초로 낮췄다 |
| **데칼은 갈라진 바닥이 아니라 그을린 눌림 자국** | 프로젝트에 균열 아트가 없다. 절차적 부드러운 타원을 어둡게·납작하게 깔아 대체했다(아트가 생기면 스프라이트만 갈아 끼우면 된다). 풀로 재사용하고 정렬 순서를 −50으로 둬 캐릭터·이펙트 뒤(바닥)에 깔린다 |
| **킬 콤보는 제거했다** | 3연속부터 표시하고 등급 상승 때만 팝하도록 절제해서 넣었지만, 방치형에서는 **처치가 끊이지 않아 결국 상시 표시**가 되어 "연속"이 정보 가치를 갖지 못했다. 코드·오브젝트 모두 제거했다 |
| **지속되는 화면 착색은 쓰지 않는다** | 광전사의 힘에 지속 비네트를 넣어 봤지만 재사용 대기시간이 짧아 **거의 상시 붉은 화면**이 되어 시야를 방해했다(제거). 비네트·플래시는 보스 페이즈 전환처럼 **순간 연출**에만 쓴다 |
| **스웨이는 위치만, 줌은 안 건드린다** | 그래서 **줌 고정 정책(`_baseOrtho` 강제)에 예외를 둘 필요가 없었다**(원래 계획의 우려 지점). 진폭 x ±0.05 · y ±0.03(화면 높이의 0.3~0.5%)이라 흔들린다고 느끼지 못하면서 고정 구도의 정적인 느낌만 사라진다. 일시정지 중에는 멈춘다 |
| **패럴랙스는 보류** | `ScrollingBackground`는 **스프라이트 1장을 타일링하는 단일 레이어**다. 패럴랙스는 원경/근경으로 **분리된 배경 아트**가 있어야 성립하므로, 아트 없이 넣으면 같은 그림을 두 번 겹쳐 흐릿하게 스크롤하는 결과만 나온다. 배경 아트가 레이어로 준비되면 그때 착수한다 |

**검증**(BattleDevScene 플레이 모드)
- 빙결: `IsFrozen=True` · 파트색 **(0.55, 0.76, 1.00)** · 정지 구간 이동량 **0**.
- 섬광: 오버레이 활성 + 최대 알파 **0.30**(샘플링이 피크 프레임을 놓친 값, 상한 0.35).
- 데칼: 활성 2개(직접 호출 1 + 전투 중 스킬 1) · scale **(2.40, 0.77)** · 색 (0.12, 0.09, 0.07, 0.5) · order **−50** · 스프라이트 `FxSoftEllipse`.
- 스웨이: 카메라 y 진폭 **0.0672유닛**(스웨이 0.06 + 전투 중 셰이크 일부 포함).

## 5. 반드시 지킬 제약

- **상주 소형 창이다**(`TaskbarWindow`). 셰이크·플래시의 진폭을 작게 잡고, 사운드의 같은 클립 0.05초 쿨다운처럼
  **시각 효과도 프레임당 1회로 제한**해야 장시간 켜 두는 사용 패턴에서 눈이 피곤하지 않다.
- **히트스톱은 지연 사운드를 밀어낸다.** 임팩트음이 `WaitForSeconds` 기반이라 `timeScale`을 따른다
  ([사운드 리소스 정의서](../../docs/세부/사운드-리소스-정의.md) §9.3에 적힌 지점). 현재 히트스톱(0.06~0.09초)에서는
  **스케일 대기를 그대로 두는 것이 옳다** — 애니메이션도 같이 느려지므로 소리와 동작이 붙어 있고, 밀리는 양도
  정지 1회당 그 길이 이하다(§2.2). 히트스톱을 0.3초 이상으로 늘리면 `PlayerCombatant.PlaySfxAfter()`·
  `SlamImpactAfter()`를 `WaitForSecondsRealtime`으로 바꿀지 다시 판단한다.
- **시간 배율은 한 번에 하나만 잡는다.** 클리어·패배 슬로우모션과 히트스톱이 겹치면 서로의 값을 덮어써 연출이
  깨지므로, 새 시간 연출을 추가할 때도 "시작 시 배율이 1인지 확인 + 내가 넣은 값일 때만 원복"을 지킨다.
- **동시 다수 처리**: 사운드 정의서 §9.3 기준 웨이브당 최대 12마리가 동시에 죽을 수 있다. 플래시·오브 연출은
  `DamageNumberPool`과 같은 **풀링**으로 만든다(매 피격 생성/파괴 금지).
- **SPUM 모션 충돌**: `PlayDamagedOnce()`는 진행 중인 공격 모션을 끊는다. 공격 중에는 모션을 생략하고
  틴트만 적용한다(§2.1에서 적용 완료). 또한 **피격 모션이 끝난 뒤 IDLE로 떨어지므로** 걷던 몬스터는
  이동 모션을 다시 걸어 주어야 한다.
- **광역 피격 중복**: `DoAreaDamageAfter()`는 대상 수만큼 루프를 돈다. 피격 연출을 대상마다 전부 재생하면
  화면·소리가 찢어지므로, 사운드가 이미 그렇게 하듯 **대표 1회 + 나머지는 가벼운 반응**으로 나눈다.

## 6. 권하는 진행 순서

**1~3순위 항목을 모두 검토해 적용했고, 보류 1건(배경 패럴랙스) · 미채택 2건(킬 콤보 · 버프 지속 비네트)이 남았다.**

> **눈에 거슬리는 연출은 빼는 것이 기본이다.** 상주 소형 창을 장시간 켜 두는 게임이라 "상시 켜져 있는 연출"은
> 정보가 아니라 피로가 된다 — 킬 콤보(상시 표시)·버프 비네트(상시 붉은 화면)·기본공격 셰이크(상시 흔들림)가
> 모두 이 이유로 제거·축소됐다. 새 연출을 넣을 때는 **얼마나 자주 발동하는지**를 먼저 계산한다.

| 보류 항목 | 착수 조건 |
|---|---|
| **배경 패럴랙스**(3순위) | 배경 아트가 **원경/근경 레이어로 분리**되어야 한다(§4.1) |

> **처치당 보상 지급은 도입하지 않기로 했다**(2026-08-04 확정). 골드·경험치는 스테이지 클리어 시 서버가
> 일괄 지급하는 현재 규약을 유지하고, 연출로만 클리어 시 HUD 비행을 넣었다(§3.1). 처치마다 API를 호출하면
> 스테이지당 호출이 약 12배로 늘고(스테이지 몬스터 중간 11마리), 서버가 전투를 재현하지 않아 **처치 보고에
> 상한을 걸 수 없다**(무제한 골드 위조 가능)는 두 가지가 결정 근거다.

그 밖에 더 얹을 만한 것: 아군 피격 반응(현재 `PlayDamagedOnce` 호출자가 몬스터뿐이다) · 스킬별 색 연출 확장
(파이어볼 = 잔열 데칼, 프로스트 노바 = 바닥 서릿결) · 보스 등장 컷 강화.
전투를 고칠 때는 **`BattleDevScene`에서 만들고**, 씬·프리팹을 건드렸다면 `던전 전투 배선` 빌더를 다시 실행한다
(스크립트만 바뀐 변경은 재실행이 필요 없다).
