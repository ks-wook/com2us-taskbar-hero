# 전투 연출 개선 아이디어 (관전 재미)

> **성격**: 제안 문서(미확정). 아래 항목은 전부 **미착수**이며, 착수할 때 이 문서의 상태 기호를 갱신한다
> (☐ 미착수 · ◐ 진행 중 · ☑ 완료).
> **작업 위치**: 전투는 `BattleDevScene`이 정본이다. 여기서 만들고 에디터 메뉴
> **`TaskbarHero/UI/던전 전투 배선`**을 다시 실행해 GameScene에 복제한다(GameScene을 직접 손대지 않는다).

## 1. 진단 — 때리는 연출은 있고, 맞는 반응이 없다

전투 코드를 훑은 결과, **연출 훅은 이미 구현돼 있는데 호출하는 코드가 없는 상태**가 확인됐다.
이펙트·사운드(공격하는 쪽)는 풍부한데 **피격 측 반응이 전무**해서, 데미지 숫자만 뜨고 몬스터는 태연히 걸어온다.
이것이 "보는 재미가 부족하다"의 직접적 원인이다.

| 항목 | 확인된 현재 상태 |
|---|---|
| `SpumCharacterAnimator.PlayDamagedOnce()` | **구현돼 있으나 `Assets` 전체에서 호출자 0곳** — 몬스터·아군 모두 피격 모션이 재생되지 않는다 |
| `MonsterUnit.TakeDamage()` | HP만 차감한다. 틴트·넉백·피격 모션 없음 |
| 카메라 흔들림 | 프로젝트에 `Shake` 관련 코드가 없다 |
| 히트스톱 | `Time.timeScale`은 **클리어·패배 슬로우모션에만** 쓰인다(`DungeonBattleFlow`·`BattleDefeatOverlay`) |
| 적 HP바 | `BattleDevController.UpdateEnemyHpBars()`가 매 프레임 위치만 따라간다(피격 반응 없음) |
| 데미지 숫자 | 흰색 / 치명타는 노란색 + 큰 팝 + `!`. 광역기에서 **여러 숫자가 한 점에 겹친다** |
| 근접 공격 | `PlayAttackAnim()` 후 제자리 스윙(전진·복귀 동작 없음) |
| 처치 | `PlayDeathOnce()` + 잠시 뒤 소멸. 플래시·날아감·전리품 연출 없음 |

## 2. 1순위 — 「타격감 패치」

훅이 `MonsterUnit`·`BattleDevController` **두 파일에 모여 있어** 변경 범위가 좁고, 근본 원인을 직접 때리므로
체감 대비 비용이 가장 낮다.

| 상태 | 항목 | 내용 · 배선 지점 |
|---|---|---|
| ☐ | **피격 반응 3종** | ① `PlayDamagedOnce()` 호출 ② **화이트 플래시**(SPUM 파트 `SpriteRenderer`를 2~3프레임 흰색 → 복귀) ③ **마이크로 넉백**(x를 0.15~0.3 뒤로). 모든 데미지가 `BattleDevController.DoDamageAfter()`·`DoAreaDamageAfter()` **단일 관문**을 지나므로 그 한 곳만 고치면 기본공격·스킬·투사체·돌진 전 경로에 적용된다 |
| ☐ | **히트스톱** | 큰 타격(치명타·스킬·보스 피격)만 `timeScale 0.05`를 0.05~0.08초. 임팩트가 "멈춰서 보이는" 효과가 넉백보다 체감이 크다 |
| ☐ | **카메라 셰이크** | `BattleDevController`가 `_cam`을 이미 들고 있어 컴포넌트 하나로 붙는다. 강도 3단(평타 없음 / 스킬 약 / 내려찍기·보스 강) |
| ☐ | **HP바 juice** | 흰색 **지연 고스트 바**(0.25초 뒤 따라오며 방금 깎인 양을 보여줌) + 피격 시 바 미세 흔들림. `UpdateEnemyHpBars()`에 얹는다 |
| ☐ | **데미지 숫자 산포** | 좌우 랜덤 오프셋(겹침 방지) + 광역 대상별 시차 + 데미지 크기에 따른 폰트 스케일. `DamageNumber.Play()` |

- **넉백에 복귀 코드가 필요 없다** — `MonsterUnit`이 `_targetX`를 향해 스스로 전진하므로, 뒤로 밀면 다시 걸어오는 복귀가 자동이다.

## 3. 2순위 — 전투의 리듬 만들기

| 상태 | 항목 | 내용 · 배선 지점 |
|---|---|---|
| ☐ | **보스 텔레그래프** | 공격 0.6초 전 바닥 붉은 예고 마커 + 무기 치켜들기 → 임팩트. "예고 → 폭발"이 관전 재미의 본질인데 현재 보스는 일반몹과 같은 리듬으로 때린다. `MonsterUnit.TickAttack()`에 선행 구간 추가 |
| ☐ | **처치 연출** | 흰 플래시 + 맞은 방향으로 크게 날아가며 페이드 + **골드·경험치 오브가 HUD로 날아가기**. 방치형은 처치 빈도가 높아 투자 효율이 가장 좋다. `MonsterUnit.Die()` |
| ☐ | **근접 lunge** | 평타 시 0.1초 앞으로 찔러 들어갔다 복귀. 제자리 스윙과 체감차가 크다. `PlayerCombatant.BasicAttack()` |
| ☐ | **웨이브 종료 슬로우** | 마지막 한 마리 처치에만 0.15초 0.3배 슬로우 + 셰이크. 클리어 슬로우모션 선례가 있어 위험이 낮다 |
| ☐ | **보스 페이즈 전환** | HP 70%/30%에서 포효(`sfx_boss_roar` 이미 배선됨) + 붉은 비네트 플래시 + 공격 주기 단축 |

## 4. 3순위 — 스킬 개성 살리기

| 상태 | 항목 | 내용 |
|---|---|---|
| ☐ | **스킬별 화면 효과** | 프로스트 노바 = 적 파란 틴트 + 이동 0.5초 정지(빙결 시각화) · 라이트닝 볼트 = 1프레임 전체 백색 플래시 · 광전사의 힘 = 지속 중 화면 가장자리 붉은 비네트 |
| ☐ | **지속 데칼** | 강타·내려찍기 자리에 갈라진 바닥이 3~5초 남아 전투가 지나간 흔적이 보인다 |
| ☐ | **킬 콤보 표시** | 연속 처치 카운터 + 등급(Nice/Great/Insane). 방치형의 "내 파티가 세졌다"를 시각화한다 |
| ☐ | **미세 카메라 스웨이·패럴랙스** | 구도가 늘 고정인 것이 지루함의 숨은 원인이다. ±0.05 정도의 흔들림만으로 화면이 살아난다. 단 현재 **줌 고정 정책**(`_baseOrtho` 강제)이 있어 예외를 명시적으로 둬야 한다 |

## 5. 반드시 지킬 제약

- **상주 소형 창이다**(`TaskbarWindow`). 셰이크·플래시의 진폭을 작게 잡고, 사운드의 같은 클립 0.05초 쿨다운처럼
  **시각 효과도 프레임당 1회로 제한**해야 장시간 켜 두는 사용 패턴에서 눈이 피곤하지 않다.
- **히트스톱은 지연 사운드를 밀어낸다.** 임팩트음이 `WaitForSeconds` 기반이라 `timeScale`을 따른다
  ([사운드 리소스 정의서](../../docs/세부/사운드-리소스-정의.md) §9.3에 적힌 지점). 히트스톱을 넣으면
  `PlayerCombatant.PlaySfxAfter()`·`SlamImpactAfter()` 등의 대기를 `WaitForSecondsRealtime`으로 바꿔야 한다.
- **동시 다수 처리**: 사운드 정의서 §9.3 기준 웨이브당 최대 12마리가 동시에 죽을 수 있다. 플래시·오브 연출은
  `DamageNumberPool`과 같은 **풀링**으로 만든다(매 피격 생성/파괴 금지).
- **SPUM 모션 충돌**: `PlayDamagedOnce()`는 진행 중인 공격 모션을 끊을 수 있다. 몬스터가 공격 중일 때는
  모션을 생략하고 틴트만 적용하는 편이 안전하다.
- **광역 피격 중복**: `DoAreaDamageAfter()`는 대상 수만큼 루프를 돈다. 피격 연출을 대상마다 전부 재생하면
  화면·소리가 찢어지므로, 사운드가 이미 그렇게 하듯 **대표 1회 + 나머지는 가벼운 반응**으로 나눈다.

## 6. 권하는 진행 순서

**1순위 5개를 한 배치로** 먼저 넣는 것을 권한다 — 변경 파일이 2개뿐이고, "맞는 반응이 없다"는 근본 원인을
직접 해소하므로 체감 상승이 가장 크다. 이후 2순위(보스 텔레그래프·처치 연출)로 전투의 리듬을 만들고,
3순위는 스킬별 개성 강화를 원할 때 선택적으로 진행한다.
