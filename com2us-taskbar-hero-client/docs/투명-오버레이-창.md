# 투명 오버레이 창 (원작형 배경 투명화)

원작 **TBH: Task Bar Hero**처럼, Windows 빌드에서 게임 창의 배경을 **픽셀 단위 투명(per-pixel alpha)** 으로 만들어
게임이 그리지 않은 영역에 **바탕화면·다른 앱이 그대로 비쳐 보이게** 하는 구현 문서.

## 동작 개요

- 전투 씬(**GameScene**, **BattleDevScene**)에서 카메라를 알파 0으로 클리어하고, 배경은
  **화면 하단의 길(도로) 스트립만** 그린다 → 캐릭터의 머리·상체는 스트립 위 투명 영역에 노출되고
  상단은 전부 투명(원작의 "길 스트립 + 투명 하늘" 구성). 노출 비율은 `ScrollingBackground.visibleBottomFrac`
  (BattleDevScene 정본 값 0.25)로 조절한다.
- 커서가 게임 콘텐츠(uGUI·2D 콜라이더·**길 스트립 밴드**) 위가 아니면 **마우스 클릭이 창을 통과**해 뒤의 바탕화면/앱에 전달된다.
- **창 크기 모드**: **GameScene은 패널/ESC 메뉴 여부와 무관하게 항상 확장 창**(9:16 설계 기준 폭의 정사각형)을 쓴다 —
  평상시 HUD가 ESC 메뉴가 열렸을 때와 동일한 화면 구성이 되도록 통일(구 "스트립 모드" 소형 창은 HUD가 잘려 폐기, 2026-07-27).
  BattleDevScene 등 개발용 투명 씬만 패널이 없을 때 낮고 넓은 16:9 창을 쓴다.
  **TitleScene은 화면비가 깨지지 않도록 항상 16:9 고정 창**(높이는 확장 창과 동일 기준, 패널·모달 유무 무관, 2026-07-27).
- **창 크기**는 작업영역 높이에 비례하며, 비율은 `TitleAspect`(16:9)·`BattleAspect`(16:9)·정사각형(1:1)이 결정하고
  **크기는 계수 두 개**(`ExpandedHeightFrac` 0.907 = 타이틀·확장 공통, `BattleHeightFrac` 0.60 = 전투 씬)가 정한다.
  이 계수만 조절하면 각 모드가 비율을 유지한 채 함께 커지거나 작아진다.
  1080p 작업영역(1920×1040) 기준 실제 크기 — 타이틀 **943×531** / GameScene **531×531** / BattleDev **1109×624**.
  작업영역보다 커지면 각 모드가 **비율을 유지한 채** 축소된다(폭이 넘치면 폭을 맞추고 높이를 비율로 재계산, 정사각형은 1:1 유지).
- **길 스트립(또는 캐릭터, 로고·배경 같은 비인터랙티브 UI)을 LMB로 잡고 드래그하면 창이 이동**한다
  (6px 임계값). 버튼·입력필드 등 **클릭을 소비하는 인터랙티브 uGUI와 IMGUI 컨트롤 조작 중에만 시작 안 함** —
  타이틀 씬처럼 화면 전체가 UI인 씬에서도 드래그가 되도록 "UI 위인가"가 아니라 "인터랙티브 UI 위인가"로 판정한다
  (`IsPointerOverInteractiveUi`). 타이틀의 "아무 곳이나 클릭해 시작"은 릴리스 시점 판정 + `TaskbarWindow.DraggingWindow`
  참조로 창 드래그와 구분된다. 옮긴 위치는 기억되어 이후 모드 전환 시에도 좌측 x·하단선을 유지한 채 작업영역 안으로 클램프된다.
- **창 위치**: 기본은 작업영역 **중앙 하단**(가로 중앙 · 작업표시줄 위 밀착)이며, 다음 순서로 결정된다.
  1. **부팅(검은 로딩 화면)** — 저장된 사용자 위치가 있어도 **항상 중앙 하단**. 어디서 실행해도 로딩 창이 같은 자리에 뜨게 한다.
     이를 위해 창 제어기를 `RuntimeInitializeLoadType.BeforeSplashScreen`에 생성해 **첫 씬이 로드되기 전에** 창을 배치한다
     (늦게 만들면 그 구간 동안 창이 OS가 정한 자리에 떠 있다).
  2. **TitleScene이 한 프레임 그려진 뒤**(= 로딩 완료) 사용자가 마지막으로 드래그해 둔 위치가 있으면 그 자리로 옮긴다.
     없으면(첫 실행) 중앙 하단에 머문다.
  3. 드래그로 옮긴 위치는 `PlayerPrefs`(`TaskbarWindow.UserLeft`/`UserBottom`)에 즉시 저장돼 **다음 실행에도 기억**된다.
  좌표는 물리 픽셀이며 복원 시 **주 모니터 작업영역 안으로 클램프**된다(보조 모니터에 두었던 위치는 주 모니터로 당겨진다).
- 초상화·스킬 슬롯·아군 HP바 블록(`SkillUICanvas`)은 **화면 좌측**, 길 스트립 상단선에서 `dockMargin`(40)만큼
  띄운 위치에 도킹된다. 이 값은 **아군 캐릭터의 머리가 길 상단선 바로 위까지 올라오는 한계**에 맞춘 것이라,
  더 줄이면 초상화·슬롯이 캐릭터와 겹친다. 도킹 위치는 **매 프레임 목표를 계산하되 오차가 40단위를 넘을 때만
  다시 놓는다**(카메라 셰이크 ≈16단위·스웨이 ≈4단위에는 무반응 + 잘못 굳은 위치는 자동 교정 —
  종전에는 "창 크기 변화 시에만 재계산"이라 첫 계산이 어긋나면 UI가 화면 최상단에 그대로 남았다).
  슬롯에 커서를 올리면 **스킬 정보 툴팁**
  (이름·설명·계수·쿨타임)이 슬롯 옆에 뜨며, 오버레이 특성상 **창이 포커스를 잃어도 동작**한다
  (uGUI 판정·툴팁 모두 EventSystem 이벤트가 아닌 수동 레이캐스트/폴링 방식).
- 타이틀·캐릭터 생성 씬은 불투명 UI가 화면을 채우므로 투명 처리 대상이 아니다(클릭 통과도 항상 꺼짐).
- **에디터에서는 전부 비활성** — 배경 타일·카메라 클리어가 그대로 유지되어 기존 개발 환경에 영향이 없다.
  실제 확인은 Windows 스탠드얼론 빌드에서만 가능하다.

## 구현 구조

| 층위 | 처리 | 위치 |
|---|---|---|
| 창(HWND) 투명화 | `DwmExtendFrameIntoClientArea(-1)` + `WS_EX_LAYERED` + `SetLayeredWindowAttributes(255)` | `Assets/Scripts/Managers/TaskbarWindow.cs` `InitTransparency()` |
| 클릭 통과 | 커서가 콘텐츠(uGUI·콜라이더·길 스트립 밴드) 위가 아니면 `WS_EX_TRANSPARENT` 토글(매 프레임). 밴드는 `ScrollingBackground`가 `ReportContentBand()`로 보고 | 같은 파일 `Update()` / `IsPointerOverContent()` |
| 창 드래그 이동 | 콘텐츠를 LMB로 누른 채 6px 이상 이동 시 `SetWindowPos`로 창을 커서에 붙여 이동, 놓으면 위치 기억(`Apply`가 유지) + `PlayerPrefs` 저장 | 같은 파일 `UpdateDrag()`/`BeginDrag()`/`EndDrag()`/`SaveUserPosition()` |
| 창 위치 결정 | 기본 중앙 하단, 로딩 구간은 저장 위치 무시(`_bootPlacement`), 타이틀 첫 프레임 뒤 저장 위치로 복원 | 같은 파일 `Apply()`/`InitWindow()`/`RestorePositionAfterLoading()`/`LoadUserPosition()` |
| 스킬 UI 스트립 도킹 | 생성물을 `DockRoot`로 묶고, 길 스트립 상단선(월드→스크린 환산) 바로 위로 매 프레임 이동 | `Assets/Scripts/Battle/SkillCooldownUI.cs` `LateUpdate()` |
| 카메라 클리어 | 전투 씬 진입 시 `ClearFlags=SolidColor`, `RGBA(0,0,0,0)` 런타임 강제(씬 에셋은 그대로) | 같은 파일 `ApplyTransparentSceneCamera()` |
| 배경 하단 크롭 | `visibleBottomFrac`(기본 1/3)만큼 커버 영역 하단만 남기고, 스프라이트도 같은 비율로 아래쪽만 잘라(서브 렉트, 텍스처 복사 없음) 배치 — 에디터·빌드 공통 적용 | `Assets/Scripts/Battle/ScrollingBackground.cs` `Build()` |

배경 크롭은 투명 모드 전용이 아니라 항상 적용된다(에디터에서도 동일한 프레이밍 확인 가능). 스테이지 전환 시
`DungeonBattleFlow.ApplyBackground → SetSprite → Build`가 다시 불려도 같은 크롭이 적용된다. GameScene의 배경 설정은
`TaskbarHero/UI/던전 전투 배선`(DungeonBattleBuilder)이 BattleDevScene에서 `visibleBottomFrac`을 포함해 이식한다.
`TaskbarWindow.TransparentOverlayActive`(Windows 빌드에서만 true)는 씬 코드가 투명 모드 여부를 판단할 때 참조할 수 있다.

## 전제가 되는 프로젝트 설정 (변경함)

| 설정 | 값 | 이유 |
|---|---|---|
| `ProjectSettings.asset` → **그래픽 API = Direct3D11 고정** (`m_BuildTargetGraphicsAPIs`, `m_Automatic: 0`) | **D3D11** | **D3D12는 flip 모델 스왑체인이 강제라 알파가 무시되어 검은 배경이 된다**(Unity 6의 Windows 기본이 D3D12여서 실빌드로 재현·확인함) |
| `ProjectSettings.asset` → `useFlipModelSwapchain` | **0** | D3D11에서도 flip 모델 스왑체인은 레이어드 창 투명과 비호환(켜져 있으면 알파가 무시되어 검은 배경) |
| `Assets/Settings/UniversalRP.asset` → `m_SupportsHDR` | **0** | HDR 중간 버퍼 기본 포맷(B10G11R11)은 **알파 채널이 없어** 최종 알파가 파괴됨 |
| Fullscreen Mode | Windowed(기존 유지, `fullscreenMode: 3`) | 전체화면은 DWM 합성을 우회 |
| Run In Background | 1(기존 유지) | 오버레이 특성상 포커스를 잃어도 계속 실행 |

포스트 프로세싱은 전 씬에서 미사용(`m_RenderPostProcessing: 0`)이라 URP 알파 출력(`m_AllowPostProcessAlphaOutput`) 설정은 불필요.

## 검증 방법

에디터 메뉴 **`TaskbarHero/Build/투명 오버레이 검증 빌드 & 실행 (BattleDevScene)`** (`Assets/Editor/TransparentOverlayBuilder.cs`)로
원클릭 수행한다 — 서버 없이 전투가 도는 BattleDevScene 단독 빌드를 `Builds/TransparencyTest/`(git 무시)에 만들어 곧바로 실행하며,
빌드 전에 전제 설정(D3D11 고정·flip 스왑체인 off)이 되돌아갔으면 콘솔에 경고를 남긴다.
실행 후 창 빈 영역에 바탕화면이 비치는지, 빈 영역 클릭이 뒤 창으로 통과하는지 확인한다.

## 검증 결과 (2026-07-27, 실빌드 확인)

BattleDevScene 단독 Windows 빌드로 실기 검증 완료:

- **D3D12(최초 빌드)**: 창 스타일·클릭 통과는 정상이나 배경이 **불투명 검정** — flip 모델 강제 때문. → 그래픽 API를 D3D11로 고정 후 재빌드.
- **D3D11(수정 빌드)**: 배경 픽셀에 뒤 화면(다른 앱 창·바탕화면)이 그대로 비침. 캐릭터·스킬 이펙트·데미지 텍스트·전투 UI·IMGUI 하네스만 렌더링됨.
  2D 조명(Global Light 2D) 경로에서도 알파 훼손 없음.
- 창 확장 스타일에 `WS_EX_LAYERED | WS_EX_TRANSPARENT`(빈 영역 클릭 통과) 적용 확인.
- 참고: GDI 캡처(`CopyFromScreen`)로는 레이어드 창이 제외되거나 알파 미적용 원본(검정)으로 찍히므로,
  투명 여부 확인은 **눈으로 보거나 DXGI Desktop Duplication 계열 캡처**로 해야 한다.

## 알려진 한계 / 트러블슈팅

- **검은/회색 배경이 보이면**(원작에도 같은 이슈 존재): ① 그래픽 API가 D3D12로 바뀌지 않았는지(핵심 원인, 위 검증 참조),
  ② flip 스왑체인·HDR 설정이 되돌려지지 않았는지, ③ exe 속성에서 "전체 화면 최적화 사용 안 함"·高DPI 설정 순으로 확인.
- **패널/오버레이의 `Dim`은 전부 완전 투명(알파 0)** 이다(2026-07-27 변경) — 오버레이 창 위에서 바탕화면이 어두워지는
  필터를 걸지 않기 위해, 딤은 색 없이 **입력 차단/밖 클릭 닫기용 레이캐스트 차단막**으로만 동작한다
  (UIManager 패널 6종·ESC 메뉴·오프라인 보상·스테이지 클리어/패배 오버레이·공용 모달·로딩 블로커).
  **주의: 패널·모달·로딩 UI는 프리팹(baked)으로 소비되므로 실제 적용값은 `Assets/Prefabs/UI/*.prefab`의
  `Dim`/`WinDim`/`Blocker` Image 색이다**(코드의 `BuildDim`류는 프리팹 미배선 시 폴백). 어둡게 까는 연출을
  되살리려면 프리팹의 해당 알파 값을 올린다(코드 폴백도 함께).
- **클릭 통과 판정은 근사치**: uGUI 레이캐스트 대상 + `Physics2D.OverlapPoint` + 길 스트립 밴드(월드 y 구간) 기준.
  스트립 위쪽의 콜라이더 없는 장식 스프라이트 위에서는 클릭이 바탕화면으로 통과한다(상호작용이 없는 요소라 실용상 문제 없음).
