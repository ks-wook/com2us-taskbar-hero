# 스테이지 선택 UI 기획서

> 서버 계약 정본: [`../../../docs/세부/stage-battle-기획서.md`](../../../docs/세부/stage-battle-기획서.md)
> 이 문서는 **클라이언트 화면 구성과 배경·경로 리소스 규칙**만 다룬다. 해금 판정·보상은 서버 기획서를 따른다.

## 1. 두 단계 구조 (`StagePanelController`)

| 단계 | 화면 | 내용 |
|---|---|---|
| 1 | **월드맵** | `dungeon_map_bg` 위에 5개 지역 핫스팟. hover 시 노랗게 빛나고 하단에 지역명, 지역별 상태 아이콘(클리어 별 / 진행 중 해골 / 잠금) |
| 2 | **지역 창** | 그 지역의 스테이지 10개를 경로로 이어 보여준다. 창 바깥을 누르면 지도로 돌아간다(별도 닫기 버튼 없음) |

지역은 `평원 · 얼음 · 화산 · 사막 · 묘지`(1~5)이고 지역당 10스테이지이며 **10스테이지가 보스**다(노드를 조금 크게 그린다). 클리어 시퀀스 `(지역−1)×10 + 스테이지`는 서버 `StageCoords.StagesPerAct`와 같은 값을 쓴다.

## 2. 지역별 배경

- 리소스: `Assets/Art/Background/stage_ui_bg/stage_ui_bg_{1~5}.png` — **파일명 숫자가 곧 지역 번호**다(1 평원 … 5 묘지). 2816 × 1536 풍경 아트.
- **창 비율을 아트 비율에 맞췄다** — 지역 창은 990 × 540(= 1.8333 = 2816/1536)이다. 비율이 어긋난 채 `Simple`로 늘리면 풍경이 왜곡된다. 폭은 우측 패널 여백(`GameViewLayout.WidestRightPanel` 1040) 안에 들어가는 값이다.
- 배경은 `OpenRegion(region)`이 `ApplyRegionLayout`에서 갈아 끼운다. 지역 아트가 없으면 기본(모달) 배경으로 폴백한다.
- 배선: 에디터 메뉴 **`TaskbarHero/UI/스테이지 선택 패널 생성`**(`StageUiBuilder`가 폴더를 훑어 5장을 순서대로 넣는다).

> **주의 — 아트 파일의 내부 스프라이트 이름이 파일명과 다를 수 있다.** `stage_ui_bg_3.png`의 서브 스프라이트 이름이 `stage_ui_bg_4_0`, `stage_ui_bg_4.png`가 `stage_ui_bg_3_0`으로 서로 바뀌어 있다(임포트 후 파일명을 바꾼 흔적). **파일 내용·배선은 정상**이고 Inspector에 보이는 이름만 어긋난다. 임포트를 고치면 그 스프라이트를 참조하는 곳이 끊길 수 있어 건드리지 않았다 — 배선을 검증할 때는 스프라이트 이름이 아니라 **에셋 경로**로 확인한다.

## 3. 지역 창 테두리(액자)

배경 아트가 **프레임 없는 풍경 그림**이라 그것만 깔면 창의 경계가 화면에서 그냥 잘려 보인다. 그래서 배경 위에 **가운데가 빈 9-slice 프레임**을 얹어 액자를 만든다.

| 항목 | 값 / 이유 |
|---|---|
| 리소스 | `Assets/Art/UI/Trade/01_Frames_Panels/window_frame_hollow.png` (64 × 64, 9-slice 경계 20px). 같은 폴더의 `window_frame.png`는 **가운데가 불투명**해 배경을 덮으므로 쓸 수 없다 |
| 두께 | **40px** — 원본 경계 20px은 990 × 540 창에서 지나치게 얇다. `Image.pixelsPerUnitMultiplier`로 키우며, 이 값은 **낮출수록 두꺼워진다**(`BuildRegionFrame`이 `원본 경계 ÷ FrameThickness`로 계산하므로 아트가 바뀌어도 두께가 유지된다) |
| `fillCenter` | `false` — 가운데를 그리지 않아 배경·노드를 가리지 않는다 |
| `raycastTarget` | `false` — 창 전체를 덮으므로 켜 두면 노드·입장 버튼 클릭을 전부 삼킨다 |

### 그리는 순서 (같은 부모에서 자식 순서 = 그리기 순서)

`경로선 → 노드 → 테두리 → 제목 명패 · 스테이지 이름표 · 입장 버튼`

테두리를 노드보다 **뒤에** 만들어 창 밖으로 흐르는 노드를 덮게 하고, 명패·버튼은 테두리보다 **더 뒤에** 만들어 테두리 위에 얹힌다 — 제목은 액자 위쪽 가장자리(y 0.94), 이름표·입장은 아래쪽 가장자리에 걸려 **액자에 걸린 명패**처럼 보인다.

노드는 이 40px 테두리에 닿지 않아야 한다. 5지역 × 10노드를 검산한 결과 창 경계까지 최소 여유가 **+21px**(평원·사막 1번 노드)이라 침범이 없다 — 좌표를 고칠 때 이 여유도 함께 확인한다.

## 4. 지역별 스테이지 경로

전에는 다섯 지역이 모두 같은 **'ㄷ' 자**(5칸 두 줄 뱀 모양)였다. 배경이 지역별 풍경으로 바뀌었으므로 경로도 지역마다 다르게 두어 "다른 곳"이라는 인상을 준다.

| 지역 | 경로 모양 | 배경 구도와의 관계 |
|---|---|---|
| 1 평원 | 완만한 **S 곡선** | 강·흙길을 따라 오르는 흐름 |
| 2 얼음 | **지그재그 계단** | 설원을 오르내려 오른쪽 **오두막**이 보스 자리 |
| 3 화산 | **둘레를 돌아 정상으로** | 가운데 밝은 **분화구**를 비켜 아래 → 왼쪽 사면 → 정상(보스) |
| 4 사막 | **모래언덕 물결**(좌→우 파형) | 오른쪽 **오아시스** 방향으로 끝난다 |
| 5 묘지 | 바깥에서 안으로 감기는 **나선** | 묘지를 헤매다 가운데에서 보스와 마주친다 |

### 구현 방식

- 좌표 정본은 `StagePanelController.RegionNodeLayouts` — 지역마다 `Vector2` 10개(창 기준 정규화, **y는 아래에서부터**).
- **오브젝트를 다시 만들지 않는다.** 노드 10개와 경로선 9개는 프리팹에 구워 두고, `ApplyRegionLayout(region)`이 지역을 열 때 위치·길이·각도만 다시 잡는다(지역을 여닫아도 쓰레기가 생기지 않는다).
- **경로선은 임의 각도를 지원한다.** `PlacePath`가 두 노드의 중점에 놓고 길이 = 두 점 거리, 각도 = `Atan2`로 회전시킨다. 대각선·수직이 같은 코드로 처리되므로(예전에는 수평·수직 전용 함수 두 개였다) 어떤 모양의 경로도 표에 좌표만 넣으면 된다.
- 경로선은 노드보다 **먼저** 만들어 노드 아래에 깔린다(같은 부모에서 자식 순서 = 그리기 순서).

### 좌표를 정할 때 지켜야 하는 여백

노드가 다른 UI에 가리지 않도록 세 영역을 피한다(창 990 × 540, 노드 76 · 보스 92 · 경로선 굵기 14).

| 영역 | 위치 | 노드 중심의 한계 |
|---|---|---|
| 제목 이름표 | y 0.94, 400 × 60 | 일반 y ≤ 0.814 · 보스 y ≤ 0.799 |
| 창 테두리 | 사방 40px | 노드 외곽이 창 경계에서 40px 이상 떨어져야 한다 |
| 스테이지 이름표 | x 0.34, y 0.09, 400 × 56 | 그 x 범위에서 y ≥ 0.212 |
| 입장 버튼 | x 0.74, y 0.09, 200 × 62 | 그 x 범위에서 y ≥ 0.217 |

- 이름표와 입장 버튼은 **위아래로 쌓지 않고 창 맨 아래에 나란히** 둔다 — 두 줄로 쌓으면 경로를 그릴 세로 공간이 사라진다.
- 노드끼리도 겹치지 않아야 한다(중심 거리 ≥ 두 노드 반지름 합). 좌표를 고친 뒤에는 이 여백·간격을 **수치로 검산**한다 — 5개 지역 × 10노드를 눈으로 보면 놓친다(실제로 화산 3번이 이름표에 2px 걸치고, 화산 6↔7·사막 8↔9가 겹치는 것을 검산으로 잡았다).
