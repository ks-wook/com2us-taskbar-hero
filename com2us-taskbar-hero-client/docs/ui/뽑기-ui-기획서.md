# 뽑기(가챠) UI 기획서

> 서버 계약 정본: [`../../../docs/세부/gacha-기획서.md`](../../../docs/세부/gacha-기획서.md) (API·확률·천장 규칙)
> 이 문서는 **클라이언트 화면 구성과 리소스 규칙**만 다룬다. 확률·천장·비용 정책은 서버 기획서를 참조한다.

## 1. 진입

- GameScene 하단 HUD의 **[뽑기]** 아이콘(오른쪽에서 8번째 칸, `Assets/Art/Icon/뽑기.png`)으로 진입한다.
  `GameSceneHudController.OnGachaButton` → `UIManager.ToggleGacha()`.
- 하단 바에 칸이 하나 늘면서 간격·버튼 폭을 줄였다(`MenuSlotStep 180 → 164`, `MenuButtonWidth 160 → 152`).
  바는 전투 화면 밴드(`GameViewLayout.GameWidth = 1440`) 안에 있어야 하므로 **칸을 더 늘릴 때는 이 폭을 다시 계산**한다
  (현재 7 × 164 + 152 + 좌우 여백 48 = 1348).
- 패널은 다른 패널과 같은 규격의 오버레이(`UiSortingOrder.Panel`)이며 전투 화면 **왼쪽**에 붙는다
  (`SidePanel.Side.Left`, 폭 1120 = 좌측 패널 최대 폭).

## 2. 화면 구성 (`GachaPanelController`, 1120 × 1090)

**배너 이미지가 화면의 주인공이다**(940 × 731 — 원본 718 × 558 비율 유지). 기간·픽업 안내와 뽑기 버튼·천장 표시,
`확률 보기`·`뽑기 기록` 버튼까지 **모두 배너 위에** 얹고, 등급 확률은 팝업으로 빼서 기본 화면을 차지하지 않게 했다.
**배너 밖에는 보유 골드와 배너 탭만 남는다** — 제목·닫기(X) 버튼·하단 안내 메시지 줄은 두지 않는다.

| 영역 | 내용 | 출처 |
|---|---|---|
| 상단 (y 22~78) | **보유 골드**(좌). 제목과 닫기(X)는 미관상 두지 않고 **창 밖(딤) 클릭으로 닫는다**(스테이지 지도·지역 창과 같은 규칙) | 세션 캐시 |
| **천장 픽업 상자**(창 우측 상단, 380×80 · 우측 36 · 상단 12) | `천장 N회 확정` + **공용 아이템 슬롯**(64) + 아이템 이름(등급색). 확정 횟수는 번들 마스터의 **하드 천장**(`pityType 2`), 이름·등급은 `item_master`. 슬롯 **hover 시 공용 상세 팝업**으로 등급·부위·요구·스탯까지 확인한다. 픽업이 없는 상시 배너(`pickupItemCode = 0`)에서는 상자를 숨긴다 | 번들 `pickupItemCode`·`pityRules` + `item_master` |
| 배너 탭 (y 100~256) | 열려 있는 배너 수만큼 가로로. 아트에 배너 이름이 새겨져 있어 **텍스트를 겹쳐 그리지 않는다** | 서버 목록 + 배너 아트 |
| **배너 이미지** (y 268~999) | 940 × 731, 가로 중앙 | 배너 아트 |
| └ 안내 띠(배너 안쪽 **위**) | 1줄: 상시 배너는 "상시 진행", 한정 배너는 **남은 기간 카운트다운** · 2줄: 픽업 설명 | 서버 `openAt`·`closeAt`·`serverTime` / 번들 `pickupItemCode` |
| └ 뽑기 버튼(배너 안쪽 **우측 하단**, x 392~928 · y 32) | **가로로 나란히 — 왼쪽 `1연 뽑기`, 오른쪽 `10연 뽑기`**(무게가 큰 상품을 시선 흐름의 끝에). 각 260 × 92로 제목 / 비용 2줄. 배너 아트의 캐릭터가 왼쪽을 차지하므로 묶음을 **오른쪽 끝에 붙인다** | 번들 `costSingle`·`costMulti` |
| └ 10연 보장 안내 (x 480 · y 168) | 뽑기 버튼 **위**에 `10회 · 희귀 이상 1개 보장` | 번들 `multiCount`·`multiGuaranteedGrade` |
| └ **천장 잔여 횟수** (x 480 · y 221) | 보장 안내 **위**에 `천장까지 53회 (37 / 90)`, 소프트 구간에서는 `· 확률 상승 중`. **게이지 바는 두지 않는다 — 텍스트 한 줄** | 서버 `counters` + 번들 `pityRules` |
| └ `확률 보기` 버튼(배너 **우측**, 창 기준 우측 109 · 상단 650) | 등급 확률 팝업 토글 | — |
| └ `뽑기 기록` 버튼(배너 **좌측**, 창 기준 좌측 104 · 상단 387) | 기록 화면으로 전환 | — |

- 배너 안에 얹는 세 텍스트(안내 띠·보장 안내·천장)는 모두 **반투명 검정 판**을 깔아 밝은 배너 아트 위에서도 읽히게 했다.
- **등급 확률 팝업** — 기본은 **닫힘**이며 `확률 보기`로만 연다(500 × 430). 팝업은 **창 우측 상단**(우측 36 · 상단 86)에
  떠서 우측 하단 뽑기 버튼을 가리지 않는다 — `확률 보기` 버튼이 배너 우측에 있어 그 아래로 펼치면 창을 넘어가므로
  **버튼 위치와 독립적으로** 배치한다. 전설 → 노말 순으로 `확률% (후보 N종)`을 보여 주고, 값은
  **번들 마스터**에서 읽으므로 서버 조회가 없다. X 버튼이나 `확률 닫기`로 닫고, 기록 화면으로 넘어가면 자동으로 닫힌다.
- **안내·오류는 패널 안 메시지 줄이 아니라 공용 모달**(`ModalManager.ShowConfirm`)로 띄운다 — 로그인 필요·골드 부족
  (금액은 `GoldFormat.Highlight`로 노란색 볼드) · 뽑기 실패 · 배너 종료(`GachaNotAvailable`) · 클라이언트 갱신 필요
  (`GachaNotFound`) · 기록 조회 실패. 열린 배너가 없을 때의 "진행 중인 뽑기가 없습니다"만 화면 가운데 텍스트로 남긴다.
- **기록 화면**(`뽑기 기록` → 배너 화면과 교체)의 목록 상자는 **배너와 같은 폭 940**(창 좌우 여백 90씩, 높이 632)으로 둔다 —
  창 폭을 꽉 채우면 한 줄이 너무 길어 읽기 나쁘다. 행 안쪽 텍스트 폭도 이 값에서 여백을 뺀 876으로 따라간다.

- **남은 기간은 로컬 시계로 계산하지 않는다.** 응답의 `serverTime`을 받은 시점(`Time.unscaledTime`)을 기준점으로 잡고
  경과 시간을 더해 쓴다. 기간이 끝나면 안내로 바꾸고 **패널을 연 동안 한 번만** 목록을 다시 받는다(시계 오차로 무한 재조회 방지).
- 열린 배너가 없으면 "진행 중인 뽑기가 없습니다"만 남기고 위젯을 감춘다(에러 아님).
  서버가 번들에 없는 `gachaCode`를 내려주면 **조용히 건너뛰고**, 그려낼 배너가 하나도 없으면 클라이언트 갱신 안내를 띄운다.

## 3. 뽑기 요청

- `POST /api/game/gacha/pull` 하나로 1연·10연을 처리하며 요청에는 **`gachaCode`와 `pullType`만** 담는다 —
  뽑는 횟수·확률·결과는 서버 소유 값이다.
- 요청 전 클라이언트가 **미리 안내만** 한다(최종 판정은 서버).
  - 골드 부족: 번들 비용과 세션 잔액 비교 후 요청하지 않는다.
  - 가방 빈 칸 부족: 1연은 0칸, 10연은 4칸 미만이면 "그래도 진행할까요?" 확인 모달.
    10연은 스택 병합으로 칸을 덜 쓰는 경우가 많아 "10칸 필요"로 막지 않는다.
- 성공 응답의 `balance`·`inventoryDelta`·`counters`를 세션과 화면에 반영하고 **재조회하지 않는다**.
- `GachaNotAvailable`(닫힌 배너)이면 목록을 다시 받고, `GachaNotFound`면 클라이언트 갱신 안내를 띄운다.

## 4. 결과 연출 (`GachaResultOverlay`)

패널 안의 자식이지만 **자기 캔버스**(`UiSortingOrder.RewardOverPanel = 120`)를 가져 패널 위에 그려진다.

1. 결과 **최고 등급**에 해당하는 영상을 재생한다 — `3성연출.mp4`(희귀) · `4성연출.mp4`(영웅) · `5성연출.mp4`(전설).
   3등급 미만이면 영상을 생략한다. 준비(`Prepare`)가 1.5초 안에 끝나지 않으면 연출을 건너뛴다(코덱 문제로 멈추지 않게).
2. 별빛 배경(`gacha_result_bg`) 위에 결과 칸을 **왼쪽부터 하나씩** 띄운다(5열 × 2행, 마지막 줄은 가운데 정렬).
   제목은 문구가 아니라 **명판 이미지**(`gacha_result_ui`)이며, 결과 화면이 열리는 순간 **원본의 0.25배에서 원본
   크기까지** 커지며 등장한다(원본 크기를 살짝 넘겼다가 제자리로 오는 back-out, 0.32초, unscaled 시간 — 칸 등장과
   병행 재생하고 스킵하면 즉시 원본 크기). 명판은 창 **위쪽 테두리에 걸치도록** 얹어(액자 다음 형제로 그려 테두리에
   가려지지 않게) 결과 칸 영역을 침범하지 않으며, 아트가 배선돼 있지 않을 때만 텍스트 제목("뽑기 결과" ·
   "N연 뽑기 결과")으로 폴백한다.
3. 칸은 공용 `ItemSlot` 프리팹을 재사용해 아이콘·수량·hover 상세를 그대로 얻고 프레임만 `gacha_result_slot`으로 교체한다.
   천장(`isPity`)·10연 보장(`isGuaranteed`)으로 확정된 칸은 아래에 `천장`·`보장` 배지를 단다.
4. **아무 곳이나 누르면** 영상을 건너뛰고, 결과가 다 드러난 뒤 누르면(또는 `확인`) 닫힌다.

### 4.1 슬롯 글로우 (`Assets/Art/Effect/UI`)

- **4·5등급 칸에만** 방사형 글로우를 칸 뒤에 깐다(등급이 곧 연출의 크기).
  `FourStarSlotGlow_01~30` / `FiveStarSlotGlow_01~30`(각 800 × 800)을 `SpriteSequenceAnimator`로 20fps 순환 재생하며,
  크기는 칸의 1.9배라 빛이 밖으로 번진다.
- 프레임은 **파일명 순서**로 배선하므로(0 패딩) 프레임을 추가할 때도 이름 규칙만 지키면 된다.

### 4.2 사운드 ([사운드 리소스 정의서](../../../docs/세부/사운드-리소스-정의.md) §7)

| 시점 | 사운드 |
|---|---|
| 뽑기 응답 수신 → 연출 시작 | `sfx_gacha_pull_single` / `sfx_gacha_pull_multi` (`pullType` 분기) |
| 등급 연출 영상 시작 | `sfx_gacha_grade3/4/5` — **묶음 안 최고 등급 하나만** 재생 |
| 결과 요약판 표시 | `sfx_ui_panel_open` |
| 칸 1개 공개 | `sfx_gacha_slot_reveal` (등급 1·2는 이것만) |
| 연출 스킵 | `SoundManager.StopAllSfx()`로 등급 연출음(최대 4초)을 끊고 `sfx_ui_click` |
| 배너 전환 / 기록·더 보기 / 오류 | `sfx_ui_tab` / `sfx_ui_click` / `sfx_ui_error` |

- **비용 차감음(`sfx_gold_spend`)은 쓰지 않는다** — 뽑기 시전음과 겹친다(정의서 §7).
- 천장·보장 회차에 전용음을 두지 않는다(등급 연출음이 그 역할을 하고, 사실은 배지·게이지로 표시).
- `PlayOneShot`은 개별 정지가 불가하므로 스킵용으로 `SoundManager.StopSfx()`(정적 래퍼 `StopAllSfx`)를 추가했다.

## 5. 리소스 규칙 (`Assets/Art/UI/Gacha`)

| 파일 | 용도 |
|---|---|
| `gacha_banner_<가챠코드>.png` | 배너 이미지(배너 이름이 아트에 포함). 아래 프레임 폴더가 없을 때 쓰는 정적 배너 |
| `BannerFrames_<가챠코드>/frame_000.jpg …` | **움직이는 배너** 프레임(파일명 순서 = 재생 순서). 있으면 정적 이미지 대신 반복 재생 |
| `gacha_btn_normal_<가챠코드>.png` | 배너 탭(비선택) |
| `gacha_btn_selected_<가챠코드>.png` | 배너 탭(선택) |
| `gacha_result_bg.png` | 결과 배경 |
| `gacha_result_slot.png` | 결과 칸 프레임 |
| `gacha_result_ui.png` | 결과 창 제목 명판("뽑기 결과") — 텍스트 제목 대신 노출 |
| `{3,4,5}성연출.mp4` | 등급별 결과 연출 영상 |

- **배너 아트는 파일명의 가챠 코드로 찾는다.** 마스터의 `banner_image`(리소스 키)가 아니라 **코드**를 쓰는 이유는
  실제 파일명이 코드 기준이기 때문이다. 배너를 추가할 때는 위 3장을 같은 규칙으로 넣고
  에디터 메뉴 **`TaskbarHero/UI/뽑기 패널·씬 배선`** 을 다시 실행하면 코드 수정 없이 배선된다.
- 아트가 없는 배너는 탭·배너 자리에 **이름 텍스트 폴백**으로 그려진다(빈 버튼이 되지 않게).
- **움직이는 배너는 GIF를 그대로 쓰지 않는다 — 프레임을 뽑아 스프라이트 시퀀스로 돌린다.** Unity는 `.gif`를
  텍스처로 임포트하긴 하지만 **첫 프레임짜리 정지 이미지**로만 읽으므로 애니메이션이 살지 않는다. 그래서 원본
  GIF(`gacha_banner_<코드>.gif`)에서 프레임을 뽑아 `BannerFrames_<코드>/`에 넣고, `GachaBannerArt.bannerFrames`에
  배선해 `SpriteSequenceAnimator`로 반복 재생한다(60002 = 111프레임 · 12fps · 9.25초 루프).
  - 프레임은 **화면 표시 크기에 맞춰 540 × 420**으로 저장한다(배너는 940 × 731 논리 크기 × 패널 캔버스 배율
    0.563 ≈ 529 × 412). 원본 718 × 558을 그대로 쓰면 화면보다 큰 텍스처를 111장 들고 있게 된다.
  - 가로·세로를 **4의 배수**로 맞춘다 — 블록 압축(DXT) 조건이라, 어긋나면 프레임마다 무압축 RGB로 올라가
    메모리가 6배 이상 커진다.
  - 배너는 알파가 없고 원본이 256색 GIF라 **JPEG(품질 92)** 로 저장한다(총 9.0MB · 평균 오차 1.88/255).
    같은 프레임을 PNG로 두면 31.9MB로 불어난다.
  - 프레임을 줄이지 않는다 — 이 GIF는 프레임마다 화면의 약 38%가 바뀌는 완전 동영상형이라 간격을 늘리면
    끊겨 보인다.
- 빌더는 **임포트 설정을 바꾸지 않는다**(공용 아트 규칙). 이 폴더 텍스처는 `Multiple`로 임포트돼 있어
  `LoadAssetAtPath<Sprite>`가 실패하므로 서브 스프라이트를 집는 폴백으로 읽는다.

## 6. 마스터 데이터 번들

배너 이름·비용·등급 확률·후보 수·천장 기준은 **클라이언트 번들**에서 읽는다(서버가 같은 값을 다시 내려주지 않는다).

- 공유 POCO: `TaskbarHero.Common/MasterData/MasterDataModels.cs`의 `GachaMaster`
  (자식 3종을 `gradeWeights`·`itemPool`·`pityRules` 배열로 중첩).
- 번들 파일: `Assets/Resources/MasterData/gacha_master.json` (배너 2건 · 후보 105행).
- 조회 헬퍼: `MasterDatabase.GachaOf` · `GachaGradeChance` · `GachaPoolCount` · `GachaPityThreshold`.
- 추출기: `tools/master_data_export.py`의 `export_gacha`(EXPORTERS 목록에 `gacha_master` 추가).
  마스터 값이 바뀌면 에디터 메뉴 **`TaskbarHero/마스터 데이터/최신화`** 로 다시 내보낸다.

## 7. 에디터 도구

- **`TaskbarHero/UI/뽑기 패널·씬 배선`**(`Assets/Editor/GachaUiBuilder.cs`) — 패널 프리팹
  (`Assets/Prefabs/UI/GachaPanel.prefab`, 결과 오버레이 포함)을 굽고, Title/GameScene의 `UIManager`에 프리팹을,
  GameScene HUD에 뽑기 아이콘을 배선한다. **패널 계층을 고치면 이 메뉴를 다시 실행**한다.
- 프리팹에 구워 둔 고정 버튼의 `onClick`은 비영구 리스너라 직렬화되지 않으므로
  `Awake`의 `WireRuntime()`에서 매 실행마다 다시 연결한다.
