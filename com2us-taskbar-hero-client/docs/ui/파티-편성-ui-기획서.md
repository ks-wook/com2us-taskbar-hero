# 파티 편성 UI 기획서 (TeamListScene)

GameScene 하단 HUD의 **[편성]** 버튼으로 진입하는 **파티 편성 전용 씬**. 보유 캐릭터를 파티 자리(1~3)에 배치·제외·교체하며, 모든 조작은 즉시 서버에 **파티 전체 스냅샷**으로 저장한다(서버 기획서 `세부/save-data-기획서.md` §5.5 / `POST /api/game/party/arrange`).

## 1. 왜 팝업이 아니라 씬인가

편성은 캐릭터 초상화를 크게 보여주고 자리를 옮기는 조작 화면이라, GameScene 위에 얹는 작은 오버레이보다 전체 화면이 맞다. 따라서 `UIManager`의 패널 종류에서 편성을 빼고(옛 `PartyPanel` 팝업 제거) 독립 씬으로 다룬다.

- 씬: `Assets/Scenes/TeamListScene.unity` (카메라 · EventSystem · `TeamListCanvas`)
- 컨트롤러: `Assets/Scripts/UI/TeamListController.cs` (계층을 코드로 구성)
- 생성·아트 배선: 에디터 메뉴 **`TaskbarHero/UI/편성 씬(TeamListScene) 생성`** (`Assets/Editor/TeamListSceneBuilder.cs`)
- 작업용 열기: 에디터 메뉴 **`TaskbarHero/씬/TeamListScene (파티 편성)`**(`Alt+4`, `Assets/Editor/SceneSwitcher.cs`)
- 창 형태: `TaskbarWindow`의 확장(정사각) 창을 그대로 쓴다(별도 비율 지정 없음).

## 2. 화면 구성

```
 ┌ 뒤로 ─────────── 🧑‍🤝‍🧑 파티 편성 ────────────────────────────┐
 │        자리를 눌러 선택 → 다른 자리를 누르면 교체 · [제외] …    │  ← 조작 안내(머리말)
 │ ┌ 보유 캐릭터 ─┐ ┌ 파티 구성원 ────────────────────────────┐ │
 │ │ [초상] 기사   │ │  1번 자리     2번 자리     3번 자리      │ │
 │ │  Lv.12·편성1  │ │ ┌────────┐  ┌────────┐  ┌────────┐    │ │
 │ │ [초상] 마법사 │ │ │ (얼굴)  │  │ (얼굴)  │  │ 빈 자리 │    │ │
 │ │  Lv.5·미편성  │ │ │  기사   │  │ 레인저  │  │        │    │ │
 │ │               │ │ │ Lv.12   │  │ Lv.9    │  │ 배치안내│    │ │
 │ │ ＋ 캐릭터 추가│ │ │ [제외]  │  │ [제외]  │  └────────┘    │ │
 │ └──────────────┘ │ └────────┘  └────────┘                 │ │
 │                  └────────────────────────────────────────┘ │
 │            (상태 문구: 저장 결과·차단 안내)                    │  ← 꼬리말
 └──────────────────────────────────────────────────────────────┘
```

- **좌측(보유 캐릭터)** — 계정의 모든 캐릭터를 초상화 + 직업 · 레벨 · 편성 상태로 나열한다. 이미 편성된 캐릭터는 흐리게 표시하고 클릭을 막는다. 하단에 **[＋ 캐릭터 추가]**.
- **우측(파티 구성원)** — 자리 1~3을 **왼쪽부터 차례로 세로로** 놓는다. 칸마다 위에서 아래로 자리 번호 → **슬롯 액자 아트(안쪽 창에 얼굴 초상화)** → 직업 → 레벨 → **[제외]**.
  슬롯 아트(`party_slot.png` 191×319)에 `AspectRatioFitter`(FitInParent, 191:319)를 걸어 창 비율이 달라져도 액자가 늘어나지 않으며, 칸 내부는 비율 좌표로 배치한다.
  **빈 자리는 아트에 그려진 물음표 실루엣이 그대로 빈 자리 표시**가 되고(덧그리는 문구 없음) 아래에 배치 안내만 둔다. 선택된 자리는 아트를 금색으로 물들여 강조한다.
- **조작 안내는 머리말, 상태 문구는 꼬리말**에 둔다(패널 9-slice 프레임 아트와 겹치지 않게).

### 초상화

인벤토리와 같은 방식 — 화면 밖 격리 위치에 캐릭터 프리팹을 두고 전용 카메라가 `RenderTexture`에 렌더해 `RawImage`로 보여준다(`CharacterPortrait`, 격리 레이어 28). 목록을 다시 그릴 때 렌더러는 재사용하고 `Retarget`으로 새 `RawImage`에만 연결한다(카메라·RT 재생성 없음). 프리팹은 `CharacterPrefabDatabase.PrefabOf(classCode, gender)`.

프레이밍은 **얼굴 위주 클로즈업** — 전투 초상화(`PortraitCameraRig`)와 같은 `aimOffset (0, 0.48)`에 `orthographicSize 0.33`(액자 대비 여유를 둔 크기 — 값을 키우면 캐릭터가 작아진다)을 쓴다. 카드 초상화 RT는 **슬롯 아트 안쪽 창과 같은 비율(288×492)** 로 만들고(창 위쪽이 아치형이라 초상화 사각형은 실제 창보다 살짝 좁게 놓는다), **카메라 배경을 투명(alpha 0)으로 클리어**해 배경판 없이 **캐릭터만 슬롯 아트 위에 겹쳐** 보이게 한다(RT는 알파를 가진 ARGB32). 좌측 목록 행은 작은 칸이라 배경을 채우고(어두운 남색), 같은 프레이밍을 조금 넓게(`0.32`) 잡아 얼굴로 구분되게 한다.

## 3. 조작 규칙

| 조작 | 동작 |
|---|---|
| 좌측 캐릭터 클릭 | 선택된 자리가 있으면 **그 자리에 배치**(있던 캐릭터는 미편성), 없으면 **첫 빈 자리에 추가**. 빈 자리가 없으면 안내만 |
| 우측 카드 클릭 (빈 자리 아님) | 그 자리를 **선택**(카드·초상화 테두리 금색 강조 + "선택됨") |
| 선택된 자리를 다시 클릭 | 선택 해제 |
| 선택 후 다른 자리 클릭 | 두 자리 **교체**(대상이 빈 자리면 **이동**) |
| 카드의 [제외] | 그 자리 캐릭터를 파티에서 뺀다(보유는 유지 = `slot 0`) |
| [＋ 캐릭터 추가] | 생성 비용 안내 모달 → `CreateCharacterScene` 이동(복귀도 이 씬) |
| [뒤로] | `GameScene` 복귀 |

- 자리 번호는 조작 후에도 유지한다(2번만 제외하면 1·3번이 남는다 — 서버는 자리 부분 점유를 허용).
- **미편성(slot 0) 캐릭터는 전투에 나가지 않는다.** GameScene 전투(`BattleDevController.InitSelection`)는 `serverMode`에서 **slot 1~3인 캐릭터의 직업만** 스폰 대상으로 삼으므로, 편성에서 뺀 캐릭터는 전장·초상화·스킬 슬롯에 나타나지 않는다(성장·장비는 보존).
- **마지막 1명 제외는 클라이언트에서 차단**한다(서버가 `CannotRemoveLastCharacter`로 거부하는 조건을 미리 막아 왕복을 줄인다).
- 모든 직업을 보유하면 [캐릭터 추가]를 차단한다(직업당 1명).

## 4. 서버 연동

- 요청: `POST /api/game/party/arrange` — `ArrangePartyRequest { userId, token, data:{ members:[{ characterId, slot }] } }`
- **저장 후의 파티 전체**를 보낸다(이동 절차가 아니라 최종 상태). members에 없는 보유 캐릭터는 서버가 미편성으로 만든다 → 추가 · 제외 · 교체 · 자리 바꾸기가 이 하나로 표현된다.
- 응답 `ArrangePartyResultData.characters`(자리 순 전체)를 `Session.ApplyCharacters`로 캐시에 반영하고 화면을 다시 그린다(재로드 없음).
- 실패는 `ErrorMessages.ToKorean(err)`로 상태 문구에 표시한다(`CannotRemoveLastCharacter` · `CharacterNotFound` · `PartySlotOccupied`).

## 5. 캐릭터 추가 흐름

1. 마스터 `character_create_cost`에서 **다음 생성 순번의 비용**을 읽어 모달로 안내한다(골드는 `GoldFormat.Highlight`로 노란 볼드).
2. 보유 골드가 부족하면 **서버 요청·씬 이동 없이 차단**한다.
3. 확인 시 `Session.CreateCharacterFromGame = true`, `Session.CreateCharacterReturnScene = "TeamListScene"`을 세우고 `CreateCharacterScene`으로 이동한다. 생성 완료·뒤로가기 후 **편성 씬으로 복귀**한다(생성·골드 차감은 그 씬에서 서버 권위로 처리).
