# 빌드 옵션 (배포 패키지)

클라이언트 빌드 옵션은 **배포 패키지 하나뿐**이다. 유니티 프로젝트 구조를 모르는 사람이 **폴더째 받아서 바로 플레이**할 수 있도록, 게임 본체를 한 단계 아래 `Game/`에 넣고 그 **한 단계 위**에 플레이 가이드를 놓는다.

## 빌드 방법

에디터 상단 메뉴 **`TaskbarHero/Build/배포 패키지 빌드 (게임 + 플레이 가이드)`** 하나를 실행한다. 구현은 [`Assets/Editor/GameDistributionBuilder.cs`](../Assets/Editor/GameDistributionBuilder.cs)이며, 빌드가 끝나면 탐색기로 결과 폴더를 열어 준다.

```
Builds/TaskbarHero/               ← 이 폴더를 통째로 압축해 전달한다
  게임-플레이-가이드.html         ← 스크린샷까지 내장한 단일 HTML(브라우저로 연다)
  Game/                           ← 유니티 빌드 결과물
    com2us-taskbar-hero-client.exe  ← 받는 사람이 누르는 게임 실행 파일
    com2us-taskbar-hero-client_Data/ · UnityPlayer.dll · …
```

**배포 루트에 런처(실행 버튼) exe를 따로 만들지 않는다.** 받는 사람은 `Game` 폴더의 게임 exe를 직접 실행하며, 그 방법은 가이드 1장 **「게임 실행 방법」** 에 그림 없이 3단계로 적혀 있다. 예전 빌드가 배포 루트에 런처를 남겨 뒀다면 빌드할 때 **그 파일들을 지운다**(이 빌더가 만들던 정확한 이름만 지우므로 사용자가 넣어 둔 파일은 건드리지 않는다).

### 플레이 가이드

[`docs/게임-플레이-가이드.html`](게임-플레이-가이드.html)을 그대로 옮기지 않고, 배포용으로 두 가지를 바꿔서 쓴다.

- **스크린샷을 data URI로 본문에 내장**한다 — `images/guide/` 폴더를 함께 옮기지 않아도 되게(파일 하나만 건네도 그림이 보인다). 현재 13장, 결과물 약 4.8MB.
- **말미에 「개발 문서」 링크 목록이 있으면 떼어 낸다** — 저장소 안 `.md`를 가리켜 배포본에서는 전부 깨진다.

원본에서 이미지를 찾지 못했거나, 앵커·외부 URL이 아닌 **로컬 링크가 남아 있으면** 어떤 것인지 콘솔 경고로 알린다(빌드는 계속 진행 — 문맥을 모르는 링크를 임의로 지우지는 않는다). 가이드 내용 자체는 원본만 고치면 다음 빌드에 반영된다.

## 접속 서버

배포본의 접속 환경은 **QA(원격 서버) 고정**이다 — 남에게 건네는 빌드라 로컬 서버 주소로는 아무것도 할 수 없다. 접속처는 게임 안에서 바꿀 수 있다(아래 「실행 중 전환」).

| 환경 | AccountServer | GameServer | 정의 심볼 | 언제 쓰이나 |
|---|---|---|---|---|
| **Dev** | `http://localhost:5160` | `http://localhost:5247` | 없음 | **에디터 플레이의 기본값**. 배포본에서는 톱니바퀴로 직접 고를 때 |
| **QA** | `https://ksu864-1.tail961c4e.ts.net` | `https://ksu864-1.tail961c4e.ts.net:8443` | `TH_QA` | **배포 패키지 빌드의 기본값** |

## 구현

- **주소 정본: [`Assets/Scripts/Managers/ServerEnvironment.cs`](../Assets/Scripts/Managers/ServerEnvironment.cs)** — 환경별 계정·게임 서버 base URL을 `const`로 정의한다. **서버 주소를 다른 곳에 하드코딩하지 않는다**(주소가 바뀌면 이 파일만 고친다).
- **기본 환경 판정**: `ServerEnvironment.BuildDefault`가 스크립팅 정의 심볼 `TH_QA` 유무로 결정한다. 배포 패키지 빌드는 `GameDistributionBuilder`가 `BuildPlayerOptions.extraScriptingDefines`로 `TH_QA`를 넣으므로 **Player Settings나 에디터 컴파일 상태를 건드리지 않는다**(빌드 후 되돌릴 것도 없다). 그래서 에디터 플레이는 항상 Dev가 기본이다.
- **빌드 씬 목록**: `GameDistributionBuilder.GameScenes`(Title → CreateCharacter → Game → TeamList, 첫 항목이 부팅 씬). 개발 전용 하네스 씬(`BattleDevScene`·`AnimDevScene`·`CharacterDevScene`)은 넣지 않는다. **빌드에 포함되는 씬을 새로 만들면 이 목록에도 함께 추가**한다(빠지면 런타임 `LoadScene`이 실패한다).
- **투명 오버레이 전제 검사**: 빌드 전에 그래픽 API가 D3D11 고정인지·`useFlipModelSwapchain`이 꺼져 있는지 확인해 어긋나면 경고를 남긴다(빌드는 계속 진행). 근거는 [투명 오버레이 창](투명-오버레이-창.md).
- **적용**: `NetworkManager.Awake`가 인스펙터 값이 아니라 **이 빌드에 구워진 환경**(`ServerEnvironment.BuildDefault` — 에디터 플레이는 항상 Dev)을 정본으로 삼아 계정·게임 base URL을 덮어쓰고, 그 환경에 저장된 `호스트:포트` override가 있으면 이어서 얹는다(인스펙터의 두 문자열은 표시용). 적용 결과는 `[NET] 접속 환경=…(빌드 옵션)` 로그로 남는다.

## 실행 중 전환

접속처를 바꾸는 화면([`ServerSelectPanelController`](../Assets/Scripts/UI/ServerSelectPanelController.cs))은 **환경 버튼(Dev / QA)**, 선택된 환경의 프리셋 주소 두 줄, 그리고 **계정·게임 서버 주소를 각각 `호스트:포트`로 입력하는 칸**으로 구성된다. 여는 경로는 하나다.

| 경로 | 언제 뜨나 | 에디터 플레이(Dev 기본) | 배포 패키지(QA 기본) |
|---|---|---|---|
| **로그인 직전 자동 노출** | — | **뜨지 않는다**(곧바로 로그인 UI) | **뜨지 않는다** |
| **타이틀 우측 하단 톱니바퀴** | 톱니바퀴를 누를 때 | 열린다 | **열린다** |

- **접속 서버 선택 화면은 자동으로 뜨지 않는다**(`ServerEnvironment.ShowServerSelectOnStart`가 어느 빌드에서도 false) — 시작 접속처가 빌드에 구워진 환경으로 정해져 있으므로(에디터 플레이는 **Dev**) 매 실행 물을 이유가 없다. 자동 노출을 되살리려면 이 값만 true로 되돌린다.
- **톱니바퀴는 어디서든 노출**된다 — 배포본에 접속처를 바꿀 통로가 없으면 잘못된 주소에 갇히기 때문이다. 이 화면에는 **'취소'** 가 있어(ESC도 같다) 아무것도 바꾸지 않고 닫을 수 있다.
- 톱니바퀴는 **타이틀에서 게임을 시작하면 사라진다**(로그인 이후에는 접속처를 바꿀 수 없다). 구현은 [`ServerSettingsButton`](../Assets/Scripts/UI/ServerSettingsButton.cs) — 아이콘은 `Assets/Art/Icon/환경설정.png`이며 에디터 메뉴 `TaskbarHero/UI/환경설정 패널·씬 배선`이 `TitleScreen`에 배선한다.

### 환경은 매 실행 초기화되고, 주소 override만 유지된다

**시작 환경은 언제나 빌드에 구워진 값**이다 — 에디터 플레이·Dev 빌드는 **Dev(로컬)**, 배포 패키지는 QA. 톱니바퀴에서 고른 환경은 **그 실행에만 적용**되고 다음 실행에 되살아나지 않는다(에디터에서 한 번 QA를 골랐다는 이유로 다음 플레이가 조용히 원격 서버에 붙어 버리는 것을 막는다). 화면의 기본 선택도 지금 접속 중인 환경이므로, 실행 직후에는 **Dev**가 골라져 있다.

'확인'으로 확정한 값 중 **다음 실행까지 저장되는 것은 `호스트:포트` override뿐**이다.
- 직접 입력 칸은 **계정·게임 서버마다 하나씩** 있고 **포트까지 함께** 입력한다(`호스트:포트`). 두 서버는 포트가 다르므로(Dev 5160/5247 · QA 443/8443) 호스트 하나로는 접속처를 표현할 수 없다. **스킴(http/https)은 선택된 환경 값을 유지**하고, 포트를 비우면 그 환경의 프리셋 포트가 유지된다(포트 자리에 숫자가 아닌 값이 오면 경고를 남기고 프리셋 포트를 쓴다). 이 주소 override는 **서버별·환경별로 따로** 저장되며(`th_server_account_dev`·`th_server_game_dev`·`th_server_account_qa`·`th_server_game_qa`), 환경을 되돌리면 그 환경에 저장해 둔 주소도 함께 되살아난다. 단 **환경 프리셋과 같은 주소면 저장하지 않고 지운다**(환경 키와 같은 규칙). 포트 없이 호스트만 저장했던 옛 키(`th_server_host_*`)는 새 키가 없을 때만 호스트로 읽고, 다음 '확인' 시점에 지운다.
- 접속처를 실제로 바꾸면 **자동 로그인을 새 서버 기준으로 다시 검증**한다. 저장 세션 자체는 지우지 않으므로(환경까지 함께 보관한다) 원래 서버로 되돌리면 자동 로그인이 다시 살아난다. 검증이 **연결 불가로 실패한 경우에도 저장 세션을 지우지 않는다** — 토큰이 무효라는 근거가 아니라 그 주소에 서버가 없다는 뜻일 뿐이다.
