# 유니티 픽셀아트 VFX 생성기

유니티 프로젝트의 레퍼런스 에셋과 동일한 픽셀아트 느낌(각진 가장자리, 안티앨리어싱 없음, 작은
네이티브 해상도에서 니어리스트 네이버 방식으로 업스케일)으로 투명 배경 PNG 프레임 시퀀스를
생성한다.

**핵심 원칙**: 이 이펙트들은 이미지 생성 모델이 아니라 파이썬(PIL/numpy/hashlib)으로 절차적으로
그려진다. 절차적 생성 방식이어야 프레임 단위의 정밀한 애니메이션, 완벽한 루프(seamless loop),
그리고 사용자의 빠른 파라미터 수정 요청(색상, 속도, 크기 등)에 대응할 수 있다.

이 파일 하나로 완결된다 — 별도의 references/scripts 파일이 필요 없다. 아래 §2에 있는
`vfx_common.py` 코드를 작업 시작 시 그대로 파일로 써서 재사용한다.

## 1. 요청 파악하기

모든 이펙트 요청에는 **형태/동작 유형**과 **타이밍 유형**이 내포되어 있다. 코드를 작성하기 전에
두 가지를 먼저 파악한다. 정말로 모호한 경우에만(단순히 "명시 안 됐지만 기본값으로 충분한" 경우가
아니라) 짧게 한 가지만 질문하고, 대부분의 요청은 합리적인 기본값을 골라 바로 진행한다.

### 타이밍 유형
| 유형 | 동작 | 루프 여부 |
|---|---|---|
| **1회성 공격/충돌** | 차징 → 이동/스윙 → 충돌 → 소멸 | 아니오 (유니티에서 `Loop Time` 끔) |
| **지속형 버프/오라** | 시작도 끝도 없이 계속 흔들리는 상태 | 예 — **완전한 루프**여야 함 (§4) |
| **반복형 앰비언트** (걷기 먼지, 상시 반짝임 등) | 게임플레이 주기(예: 발걸음 타이밍)에 맞춰 반복 | 예 — 완전한 루프 |
| **UI 요소** (스피너, 게이지 등) | 계속 반복되지만 전투 이펙트만큼 거칠 필요는 없음 | 예 — 완전한 루프 |

### 형태/동작 유형 (참고 레시피)
- **방사형 폭발** (폭발, 마법 버스트): 중심에서 사방으로 뻗는 화염/에너지 촉수, 해시 기반 랜덤
  드롭아웃으로 각진 테두리, 뜨거운 중심부→차가운 외곽부 색상 그라데이션. 커졌다가 흩어짐.
- **이동형 투사체** (화염구, 냉기 화살, 화살, 에너지파): 발사 지점에서 차징 → **가로로 긴 캔버스**를
  가로질러 가속 이동 → 머리 뒤로 흩날리는 잔상/트레일 → 도착 지점에서 충돌 폭발 → 소멸.
- **초승달형 베기** (검격, 도끼 검기): 피벗을 중심으로 두 각도 사이를 휩쓰는 각도 밴드, 선두
  가장자리가 가장 밝고 후미로 갈수록 옅어짐.
- **세로형 캐릭터 오버레이** (화염 버프, 레벨업 광휘): 몸통/머리 부분이 가장 크고 양옆이 작으며,
  발밑에 잔불 글로우, 머리 위로 솟는 불티. **반드시 완전한 루프**여야 함 (§4). 서 있는
  캐릭터를 덮을 수 있는 세로로 긴 캔버스.
- **지면 충돌** (방패 돌진, 대지 강타): 흙먼지 + 스피드 라인/충격파 링 + 선택적으로 **영구적으로
  남는 균열** (충돌 시 한 번 그리고 이후 모든 프레임에서 계속 보이도록 유지 — 반드시 남아있어야
  하는 요소를 페이드아웃시키지 않는다).
- **캐릭터 부착형 반복 이펙트** (걷기 먼지): 발 높이에 맞춘 짧고 낮은 캔버스. 펄스 주기를 전체
  프레임 수의 약수로 설정해 루프가 끊기지 않게 하고, 캐릭터의 이동 방향에 맞춰 입자의 움직임을
  편향시킨다 (§7에 실수 사례 있음).
- **UI 스피너/게이지**: 회전 기반. 주기를 전체 프레임 수에 걸쳐 정확히 한 바퀴로 맞추면 자동으로
  완전한 루프가 됨.
- **축하 연출** (스테이지 클리어, 팡파레): 중앙 플래시 + 방사형 빛줄기(선버스트) + 중력을 받는
  다채색 컨페티 + 반짝이는 트윙클. 단일 원소 색상이 아니라 **다채로운 색상 팔레트**를 쓰는
  유일한 유형.

### 기본값 (사용자가 다르게 요청하지 않는 한 이 값을 따른다)
- **프레임 수**: 30프레임, 파일명은 `Prefix_01.png` … `Prefix_30.png` (사용자가 명시적으로
  정한 표준 기본값 — 다른 수를 요청하지 않는 한 항상 적용).
- **캔버스**: 방사형/근접 피벗 이펙트는 정사각형, 좌→우로 이동하는 것은 가로로 긴 형태, 캐릭터
  오버레이 오라는 세로로 긴 형태. (캔버스 크기 기준표는 §3 참고)
- **배경**: 완전 투명(RGBA), 절대 배경을 채우지 않음.
- **네이밍**: PascalCase, `캐릭터/테마 + 이펙트이름` 형식 (예: `KnightSwordSlash_01.png`). 사용자가
  이펙트 이름을 명시적으로 지정한 경우(예: `KnightRage`), 이후 모든 수정 작업에서도 그 이름을
  그대로 유지한다 — 이름을 바꾸지 말고 덮어쓴다.

## 2. 생성 스크립트는 독립 파일로 작성

모든 이펙트는 인라인으로 프레임을 만들지 않고, 현재 프로젝트 안의 스크래치 디렉토리(예:
`vfx-output/<EffectName>/_gen/`)에 파이썬 스크립트 하나로 작성한다. 이렇게 해야 수정이 빠르다:
사용자는 색상, 속도, 두께, 프레임 수, 실루엣 등 파라미터 하나를 자주 수정 요청하는데, 이때
기존 스크립트를 편집하고 재실행하면 된다 — 처음부터 다시 만들지 않는다.

**작업을 시작하기 전에**, 아래 코드를 그 스크래치 디렉토리에 `vfx_common.py`라는 이름으로 한 번
써두고, 이후 모든 생성 스크립트에서 `from vfx_common import ...`로 임포트해서 재사용한다.
(이미 같은 프로젝트에 이 파일이 있다면 다시 쓸 필요 없이 그대로 임포트한다.)

```python
"""
유니티 픽셀아트 VFX 스프라이트 애니메이션을 절차적으로 생성할 때 쓰는 공용 헬퍼 함수 모음.
"""

import hashlib
import os
import zipfile

import numpy as np
from PIL import Image


def hash01(*args) -> float:
    """어떤 값이든 인자로 받아 [0, 1) 범위의 결정론적 의사난수 float를 반환한다.

    random.random() 대신 항상 이 함수를 쓴다: 재실행해도 동일한 결과가 나와야
    (재현 가능해야) 하는데, 이펙트는 자주 수정되고 여러 번 재실행되기 때문에
    이 재현성이 중요하다. 서로 관련 없는 용도에서 노이즈가 서로 얽히지 않도록
    사용 위치마다 문자열 태그로 salt를 준다
    (예: hash01(x, y, idx, "edge_dropout")).
    """
    h = hashlib.md5("_".join(map(str, args)).encode()).hexdigest()
    return int(h[:8], 16) / 0xFFFFFFFF


def color_gradient(t: float, stops):
    """비율 t(0~1)에 따라 N개의 색상 스톱 사이를 블렌딩한다.

    stops: (위치, (r,g,b)) 튜플의 리스트, 위치는 0~1 사이 오름차순.
    예: [(0.0,(255,250,210)), (0.25,(255,210,80)), (0.55,(255,140,30)),
         (1.0,(220,60,15))]

    (r,g,b) numpy float 배열을 반환한다. 화염/냉기/번개/에너지 이펙트에 쓰이는
    "뜨거운 중심부 -> 차가운 외곽부" 그라데이션 패턴이며, 단색 채우기보다
    항상 이 방식을 우선한다.
    """
    t = float(np.clip(t, 0.0, 1.0))
    stops = sorted(stops, key=lambda s: s[0])
    for i in range(len(stops) - 1):
        p0, c0 = stops[i]
        p1, c1 = stops[i + 1]
        if p0 <= t <= p1:
            local = 0.0 if p1 == p0 else (t - p0) / (p1 - p0)
            c0 = np.array(c0, dtype=float)
            c1 = np.array(c1, dtype=float)
            return c0 * (1 - local) + c1 * local
    return np.array(stops[-1][1], dtype=float)


def puff_trail(draw, head_x, head_y, origin_x, idx, color_fn, n_puffs=None,
               puff_every=5, max_size=6, base_alpha=220, wobble_amp=3.0,
               wobble_freq=0.15):
    """가로로 이동하는 투사체 머리 뒤에 옅어지는 퍼프(puff) 트레일을 그린다.

    color_fn: callable(트레일을 따라간 비율: float) -> (r,g,b).
        0 = 머리 부분(가장 뜨거움), 1 = 발사 지점 부근(가장 오래되고 차가움).
    머리 부분이 트레일 위에 그려지도록, 머리를 그리기 전에 이 함수를 먼저 호출한다.
    """
    if head_x <= origin_x:
        return
    if n_puffs is None:
        n_puffs = max(1, int((head_x - origin_x) / puff_every))
    for i in range(n_puffs, 0, -1):
        frac = i / max(1, n_puffs)
        px = head_x - frac * (head_x - origin_x)
        wob = wobble_amp * np.sin(2 * np.pi * (wobble_freq * px / 8 + idx * 0.15))
        py = head_y + wob * 0.5
        size = 3 + max_size * (1 - frac)
        col = color_fn(frac * 0.6)
        a = int(base_alpha * (1 - frac * 0.4))
        if a <= 0:
            continue
        draw.ellipse([px - size, py - size * 0.65, px + size, py + size * 0.65],
                     fill=(*np.array(col).astype(int), a))


def build_jagged_path(start_xy, angle_deg, length, n_seg=8, amp=6, seed_tag="path"):
    """start_xy에서 angle_deg 방향으로 뻗어나가는 들쭉날쭉한 랜덤워크 폴리라인을 만든다.

    PIL의 draw.line(pts, ...)에 바로 넘길 수 있는 (x, y) 좌표 리스트를 반환한다.
    번개, 바닥 균열처럼 진폭이 팁으로 갈수록 커지는 거친 경로에 사용한다.
    """
    x0, y0 = start_xy
    theta = np.radians(angle_deg)
    dx, dy = np.cos(theta), np.sin(theta)
    pts = [(x0, y0)]
    seg_len = length / n_seg
    x, y = x0, y0
    for s in range(n_seg):
        local_amp = amp * min(1.0, (s + 1) / (n_seg * 0.6))
        jitter = (hash01(seed_tag, s, "jx") - 0.5) * 2 * local_amp
        x += dx * seg_len + jitter * (-dy)
        y += dy * seg_len + jitter * dx
        pts.append((x, y))
    return pts


def save_frames_and_package(make_frame_fn, num_frames, out_dir, prefix,
                             zip_path=None, sheet_cols=10):
    """모든 프레임에 대해 make_frame_fn(idx, num_frames)을 실행하고, 번호가 매겨진
    PNG로 저장한 뒤, 그리드 스프라이트 시트를 만든다. zip_path를 주면 zip으로도 묶는다
    (Claude Code 환경에서는 프로젝트에 바로 통합할 거라면 zip이 필요 없을 수 있다 —
    사용자에게 필요한지 먼저 물어봐도 된다).

    (frames, sheet_path, zip_path)를 반환한다.
    """
    os.makedirs(out_dir, exist_ok=True)
    frames = []
    for i in range(num_frames):
        im = make_frame_fn(i, num_frames)
        fname = f"{out_dir}/{prefix}_{i + 1:02d}.png"
        im.save(fname)
        frames.append(im)

    w, h = frames[0].size
    sheet_rows = (num_frames + sheet_cols - 1) // sheet_cols
    sheet = Image.new("RGBA", (w * sheet_cols, h * sheet_rows), (0, 0, 0, 0))
    for i, f in enumerate(frames):
        r, c = divmod(i, sheet_cols)
        sheet.paste(f, (c * w, r * h), f)
    sheet_path = f"{out_dir}/{prefix}_SpriteSheet.png"
    sheet.save(sheet_path)

    if zip_path:
        with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
            for i in range(num_frames):
                p = f"{out_dir}/{prefix}_{i + 1:02d}.png"
                zf.write(p, arcname=os.path.basename(p))
            zf.write(sheet_path, arcname=os.path.basename(sheet_path))

    return frames, sheet_path, zip_path


def verify_content(png_path, min_alpha=10):
    """(0이 아닌 픽셀 수, (x_min,x_max), (y_min,y_max))를 반환한다. 프레임이
    비어있으면 (0, None, None)을 반환한다."""
    im = np.array(Image.open(png_path).convert("RGBA"))
    alpha = im[:, :, 3]
    mask = alpha > min_alpha
    if not mask.any():
        return 0, None, None
    ys, xs = np.where(mask)
    return int(mask.sum()), (int(xs.min()), int(xs.max())), (int(ys.min()), int(ys.max()))


def mean_color(png_path, min_alpha=100):
    """min_alpha보다 큰 픽셀들의 평균 (r,g,b)를 반환한다. 색상 팔레트가 요청과
    맞는지 확인할 때 사용 (예: 파란색 이펙트라면 B 채널이 가장 높아야 함)."""
    im = np.array(Image.open(png_path).convert("RGBA"))
    alpha = im[:, :, 3]
    mask = alpha > min_alpha
    if not mask.any():
        return None
    return im[:, :, :3][mask].mean(axis=0)


def loop_seam_check(out_dir, prefix, num_frames):
    """N번째 프레임 -> 1번째 프레임 사이의 픽셀 차이를, 1번째 -> 2번째 프레임 사이의
    차이와 비교한다. 완전한 루프(§4)라면 두 값이 같은 자릿수여야 한다.
    (seam_diff, adjacent_diff)를 반환한다."""
    f1 = np.array(Image.open(f"{out_dir}/{prefix}_01.png").convert("RGBA")).astype(int)
    f2 = np.array(Image.open(f"{out_dir}/{prefix}_02.png").convert("RGBA")).astype(int)
    fN = np.array(Image.open(f"{out_dir}/{prefix}_{num_frames:02d}.png").convert("RGBA")).astype(int)
    seam_diff = float(np.abs(fN - f1).mean())
    adjacent_diff = float(np.abs(f2 - f1).mean())
    return seam_diff, adjacent_diff
```

모든 생성 스크립트는 다음과 같은 동일한 구조를 따른다:
1. 캔버스 크기, 스케일 배율, 프레임 수, 출력 디렉토리, 파일명 접두사를 상단에 상수로 정의.
2. 프레임별 그리기 로직을 담은 `make_frame(idx, num_frames) -> PIL.Image` 함수.
3. `save_frames_and_package(make_frame, N, out_dir, prefix, zip_path)` 한 줄로 저장+시트+압축까지 처리.
4. 이펙트별로 고유한 지오메트리(초승달 밴드, 불꽃 형태 엔벨로프, 균열 프랙탈, 컨페티 물리 등)는
   매번 새로 작성한다 — 이 부분은 정말로 이펙트마다 다르다.

작은 **네이티브 픽셀 그리드**(캔버스 형태에 따라 대략 80~230px — §3 참고)에 그린 뒤 마지막에
`Image.NEAREST`로 업스케일한다 (보통 3~6배). 이 업스케일 과정이 각진 픽셀아트 느낌을 만드는
핵심이다 — 픽셀 그리드를 직접 손으로 그리지 않는다.

## 3. 캔버스 크기 & 색상 팔레트 기준표

### 캔버스 방향

| 이펙트 유형 | 형태 | 네이티브 크기 예시 | 스케일 |
|---|---|---|---|
| 방사형 폭발 / 폭발 / 스테이지 클리어 중앙 이펙트 | 정사각형 | 220x220 (또는 130x130 등) | 3~4배 |
| 투사체 / 빔 / 이동형 검기 | 가로로 긴 형태 | 약 200~240 x 90~130 | 4배 |
| 전신 캐릭터 오버레이 (버프, 오라, 레벨업 광휘) | 세로로 긴 형태 | 약 90~110 x 160~170 | 4배 |
| 근접 아크 스윙 (검/도끼 궤적) | 대체로 정사각형, 피벗이 좌측으로 치우침 | 약 160~180 x 160~200 | 3배 |
| 지면 레벨 소품/이펙트 (흙먼지, 모닥불, 균열) | 짧고 넓은 형태 | 약 100~220 x 50~140 | 4배 |
| UI 요소 (스피너, 아이콘 이펙트) | 작은 정사각형 | 64x64 | 6배 |

### 색상 팔레트 (RGB) — 원소/테마별

같은 원소의 이펙트는 항상 **동일한** 그라데이션을 재사용해서 프로젝트의 VFX 전체가 하나의
일관된 세트처럼 보이게 한다.

**화염 / 불꽃**:
```
CORE  = (255, 250, 210)   # 가장 뜨거움, 거의 흰색
INNER = (255, 210, 80)    # 밝은 노랑-주황
MID   = (255, 140, 30)    # 주황
OUTER = (220, 60, 15)     # 짙은 붉은 주황
EMBER = (120, 30, 12)     # 식어가는 잔불 (소멸 프레임용 선택적 5단계)
```

**냉기 / 얼음**:
```
CORE = (235, 250, 255)
ICE  = (170, 225, 250)
MID  = (100, 180, 230)
DEEP = (55, 120, 185)
MIST = (225, 240, 250)    # 은은하게 피어오르는 안개, 낮은 알파(~25~30)만 사용
```

**번개 / 전기**: 글로우 `(90, 190, 255)`, 코어 `(255,255,255)` — 매끄러운 곡선이 아니라
`build_jagged_path()`로 만든 들쭉날쭉한 랜덤워크 경로 사용.

**푸른 에너지 / 검기(劍氣)** — 냉기와 구분되는, 조금 더 짙고 채도 높은 파랑:
```
CORE = (235, 248, 255)
ICE  = (150, 210, 255)
MID  = (70, 150, 235)
DEEP = (30, 90, 180)
```

**신성 / 골드 / 특수한 힘** (필살기, 처형/정밀 스킬, 레벨업, 각성):
```
CORE  = (255, 250, 225) / (255,255,250)
GOLD  = (255, 215, 90) / (255, 224, 140)
OUTER = (235, 160, 40)
```

**물리 / 충격 / 흙먼지** (돌진, 강타, 화살 착지, 걷기 먼지) — 화염/마법 색을 쓰지 않고
중성적/흙빛 팔레트만 사용:
```
DUST     = (196, 172, 128)
DUST_DK  = (150, 122, 88)
DUST_LT  = (215, 195, 155)
DEBRIS   = (110~120, 100~118, 95~122)
SHOCK/FLASH = (255,255,250) 코어, (210~235, 200~222, 175~222) 충격파 링
```

**축하 / 스테이지 클리어** — 모든 전투 이펙트와 구분되는, 다양한 색조를 쓰는 유일한 경우:
```
CONFETTI_COLORS = [
    (240,70,70), (255,160,40), (255,220,60), (110,200,90),
    (70,160,230), (150,110,230), (240,110,190), (255,235,180),
]
GOLD = (255,210,100); FLASH = (255,255,245)
```

**UI (로딩 스피너 등)**: 사용자가 요청한 강조 색을 그대로 사용하되(예: "붉은색" → 빨강
`BRIGHT=(255,90,90)`, `DARK=(120,15,15)`), 코멧-테일(comet-tail) 페이드 기법을 적용한다.

각진 픽셀아트 테두리를 만들려면(매끄러운 안티앨리어싱 곡선이 아니라) 테두리 픽셀의 약
30~40%를 `hash01(x, y, frame_idx, salt)`로 랜덤 드롭아웃시킨다. 이게 매끈한 벡터 테두리 대신
손으로 찍은 듯한 거친 픽셀 느낌을 만든다.

## 4. 완전한 루프 만들기 (버프, 오라, UI, 반복 이펙트)

지속형/반복형으로 묘사된 이펙트(버프, 상시 오라, UI 스피너, 걷기 주기 먼지)는 애니메이션이
1번 프레임부터 다시 재생될 때 **반드시** 눈에 띄는 끊김이나 깜빡임 없이 이어져야 한다. 이건
프레임 블렌딩이 아니라 순수하게 수학으로 해결한다:

- 모든 주기적 움직임(흔들림, 스웨이, 회전, 상승하는 불티 등)은 `sin(2*pi*(k * idx/N + phase))`
  형태로 구동해야 하며, 이때 **k는 정수**, **N은 전체 프레임 수**여야 한다. `idx = 0, 1, ..., N-1`로
  샘플링하면 완벽하게 균일한 주기적 시퀀스가 만들어져서, 마지막 프레임(`N-1`)에서 첫 프레임(`0`)으로
  돌아갈 때의 변화량이 다른 어떤 프레임 간 변화량과도 수학적으로 동일해지므로 이음새가 생기지
  않는다.
- 이산적으로 반복되는 이벤트(발걸음 펄스, 스피너 눈금 등)는 전체 프레임 수를 **정확히 나누는**
  주기를 선택한다 (예: 30프레임짜리 2주기 걷기 루프라면 15가 30을 나눔).
- 상승하는 파티클: `pos = (idx/N + 입자별_phase) % 1.0` 형태를 사용해서 각 입자의 주기가
  깔끔하게 감싸지도록 한다.
- **항상 수치로 검증한다** (§5) — 눈으로 보고 판단하지 않는다.

## 5. 검증 (결과를 보여주기 전에 반드시 수행)

렌더링된 이미지 미리보기 도구가 세션에 따라 제대로 안 보일 수 있다 — 미리보기가 안 보인다고 해서
이펙트가 잘못됐다는 증거는 아니며, 반대로 미리보기가 괜찮아 보인다고 해서 데이터 검증을 생략해도
되는 것도 아니다. 위 §2의 `verify_content()`, `mean_color()`, `loop_seam_check()`를 써서 매번
실제 픽셀 배열을 수치로 확인한다:

- **콘텐츠 확인**: 알파값이 0이 아닌 픽셀 수가 0보다 큰지, 그리고 바운딩 박스가 타임라인
  의도대로 움직이는지(예: 투사체는 프레임이 진행될수록 x 범위가 오른쪽으로 이동해야 하고,
  방향성 있는 흙먼지는 이동 방향의 반대쪽으로 무게중심이 이동해야 함) 확인.
- **색상 확인**: 알파값 100 이상인 픽셀들의 평균 RGB가 의도한 팔레트와 맞는지 확인.
- **루프 이음새 확인** (§4에 해당하는 모든 이펙트에 필수): `loop_seam_check()`의 두 값이 같은
  자릿수인지 확인 — 이음새 차이가 훨씬 크다면 루프가 깨진 것이며, 거의 항상 k가 정수가
  아니거나 주기가 프레임 수를 나누지 못하는 것이 원인이다.
- **지속성 확인** ("반드시 남아있어야 하는" 요소, 예: 바닥 균열): 마지막으로 생성된 프레임에서
  해당 색상/마스크를 샘플링해서 픽셀 수가 0이 아닌지 확인.

## 6. 출력 및 전달 (Claude Code / 로컬 파일시스템 기준)

Claude Code는 사용자의 실제 로컬 파일시스템에서 동작하므로, 고정된 특수 출력 경로는 없다 —
**현재 프로젝트 기준 상대 경로**에 결과물을 저장한다.

- 사용자가 이미 이펙트/에셋을 모아두는 폴더(예: `Assets/VFX/`, `art/effects/` 등)를 프로젝트에서
  확인할 수 있으면 그 규칙을 따른다.
- 그런 폴더가 없거나 프로젝트 구조를 모르면, 작업 시작 전에 어디에 저장할지 한 번 물어보거나
  합리적인 기본값(`./vfx-output/<EffectName>/`)을 제안하고 진행한다.

모든 이펙트 전달물은 다음을 포함한다:
1. 개별 프레임: `<출력경로>/Prefix_01.png` … `Prefix_NN.png`
2. 스프라이트 시트: `<출력경로>/Prefix_SpriteSheet.png` (10열 그리드, 남은 프레임은 추가 행으로)
3. zip 압축파일 (선택 사항 — 프로젝트에 바로 통합할 계획이면 사용자에게 필요한지 먼저 물어봐도
   된다): `<출력경로>/EffectName.zip`

파일을 다 만든 뒤에는 **생성된 파일들의 전체 경로를 텍스트로 알려준다** — 예: "다음 경로에
30개 프레임과 스프라이트 시트를 생성했습니다: `vfx-output/KnightRage/`". 대표 프레임 2~4장의
경로만 짚어서 언급하고, 30장 전부를 나열하지 않는다.

"반드시 포함되어야 한다"는 요구사항이 있다면(예: "바닥 균열은 무조건 포함") 요구된 범위의
**모든** 프레임, 특히 마지막 프레임까지 그 요소가 남아있는지 §5의 방법으로 검증한다.

## 7. 수정 요청 처리하기

사용자는 이런 이펙트를 재색상, 리사이즈, 실루엣 변경, 방향성 오류 수정 등으로 많이 반복
수정한다. 수정 요청이 들어오면:
- 사용자가 이펙트를 이름으로 지칭했다면 동일한 출력 파일명/접두사를 재사용한다 — 이미 프로젝트에
  연결했을 수 있는 파일명을 바꾸지 않는다.
- 처음부터 다시 작성하지 말고 기존 생성 스크립트를 수정한다 — 대부분의 수정은 파라미터 하나 또는
  함수 하나의 지오메트리 변경으로 끝난다 (예: 불꽃 테이퍼 폭 프로파일을 항아리 모양으로 바꾸는
  것은 함수 하나만 교체하면 되는 작업이지, 새 스크립트가 아니다).
- 수정할 때마다 루프 이음새 검증과 콘텐츠 검증을 다시 실행한다 — 지오메트리 변경이 이전에
  완벽했던 루프를 조용히 깨뜨릴 수 있다.
- 사용자가 방향/물리적 논리 오류를 지적하면(예: "이건 캐릭터가 카메라 쪽으로 달려오는 연출
  같은데, 내 캐릭터는 옆으로 이동한다"), 겉모습만 살짝 고치지 말고 근본적인 벡터 수학(각도,
  오프셋, 편향)을 고친 뒤 §5와 동일한 바운딩 박스/무게중심 검증으로 확인한다.

## 8. 유니티 연동 시 사용자에게 전달할 내용

관련이 있을 때만 언급하고, 묻지 않았는데 과도하게 설명하지 않는다:
- Sprite (2D and UI)로 임포트, **Filter Mode: Point (no filter)**, Compression: None.
- 번호가 매겨진 PNG들을 그대로 Hierarchy로 드래그하면 애니메이션 클립이 자동 생성된다 — 슬라이싱
  불필요. 스프라이트 시트는 드로우콜 절감을 위해 배칭/아틀라스가 필요할 때만 사용 (Sprite Editor
  → Slice → Grid By Cell Count).
- 애니메이션 클립의 `Loop Time`: 버프/오라/UI/반복 이펙트는 켜고, 1회성 공격/충돌 이펙트는 끈다.
- 오버레이 이펙트(오라, 레벨업 광휘)는 캐릭터 위치를 따라가도록 캐릭터 Transform의 자식으로
  두고, 지면 이펙트는 충돌/타겟 지점의 월드 좌표에 인스턴스화한다.
