# 픽셀 아이템 아이콘 생성기

2D RPG 게임의 아이템, 장비, 제작 소재, 스킬, UI를 픽셀 아트 스타일의 정사각형(또는 정사각형에 가까운)
투명 PNG로 생성하는 스킬입니다. 모든 아이콘은 코드(Python + PIL + numpy)로만 만들며, 외부 이미지 생성
모델은 전혀 사용하지 않습니다. 모든 요청을 다음과 같이 처리하세요: "이 모양/테마에 맞는 작은 절차적
생성 스크립트를 작성하고, 실행하고, 수치로 검증한 다음, 사용자가 준 이름 그대로 저장하고 보여준다."

## 반드시 지켜야 할 핵심 규칙

1. **출력 형식**: RGBA PNG, 투명 배경(실루엣 밖은 알파 0). 절대 흰색/단색 배경으로 렌더링하지 말 것.
2. **파일명은 사용자가 입력한 텍스트와 완전히 동일해야 함** (보통 한글), **띄어쓰기 포함** — 공백을
   언더바로 바꾸지 말고, 번역/음역하지 말 것. 예를 들어 아이템명이 `강철 대검`이면 저장 파일명도
   `강철 대검.png`여야 하며, `steel_greatsword.png`나 `강철_대검.png`가 되어서는 안 됨.
   - 스크립트나 명령어에서 파일명을 만들 때 **기억에 의존해서 `\uXXXX` 이스케이프를 직접 손으로
     타이핑하지 말 것** — 이것이 이 작업에서 가장 흔한 실수의 원인임 (예: `강화석` 대신 `강화 석`,
     `치명확률` 대신 `치명확뜁`처럼 잘못된 코드포인트를 입력하는 경우). 대신 (a) 셸 명령어/파일 경로에
     UTF-8 한글 텍스트를 직접 그대로 작성하거나, (b) 코드포인트를 꼭 확인해야 한다면 실제 문자열에서
     프로그래밍적으로 생성할 것. 예:
     `python3 -c "print(['0x%x' % ord(c) for c in '강화석'])"` 로 만들려는 이름과 대조 확인 — 임의로
     16진수 값을 지어내지 말 것.
   - 환경이 사용자에게 노출하는 공유 출력 디렉토리에 바로 저장할 것 (claude.ai 환경에서는
     `/mnt/user-data/outputs/`, **이 프로젝트(Claude Code)에서는 아래 "기본 출력 경로"의
     `Assets/Art/Icon/`**). 저장 후에는 눈으로만 보지 말고 디렉토리 목록(`ls`)으로 파일명을 반드시
     재확인할 것.
3. **요청 하나당 아이콘 하나**, 같은 "세트"(예: 한 등급의 장비 전체, 혹은 한 번에 배치 생성한 스킬
   아이콘들) 안에서는 인벤토리/스킬 그리드에서 잘 어울리도록 크기와 스타일을 일관되게 유지할 것.
4. **렌더링된 PNG를 시각적으로 확인할 수 있다고 절대 가정하지 말 것.** 이 환경의 이미지 미리보기
   도구는 실제로 픽셀을 모델에게 보여주지 못하는 경우가 잦음. 모든 생성 결과는 아래 "검증" 섹션의
   수치 검사를 통과하기 전까지는 미확인 상태로 취급할 것. 미리보기만 보고 "확인했습니다, 정상입니다"
   라고 말하지 말 것.
5. **기본 출력(다운로드) 경로는 `Assets/Art/Icon/`.** 아래 "기본 출력 경로" 섹션 참고 — 사용자가
   경로를 지정하지 않으면 이 경로에 저장하고, **어디에 저장할지 되묻지 말 것.**

## 기본 출력 경로 (이 프로젝트 고정값)

이 프로젝트에서 생성되는 모든 아이콘의 **기본 저장 경로는 Unity 클라이언트의
`com2us-taskbar-hero-client/Assets/Art/Icon/`** 이다. 사용자가 다른 경로를 명시하지 않는 한 이곳에
저장하며, **매번 저장 위치를 되묻지 않는다.**

- 절대 경로 예: `C:\Users\com2us29\projects\com2us-taskbar-hero\com2us-taskbar-hero-client\Assets\Art\Icon\<아이템명>.png`
- 이 폴더에는 이미 카테고리 하위 폴더(`Combat/`, `Item/`, `Rune/`)가 있다. **사용자가 하위 카테고리를
  명시하면** 그 하위 폴더(예: `Assets/Art/Icon/Item/`)에 저장하고, 명시하지 않으면 `Assets/Art/Icon/`
  루트에 바로 저장한다. 새 하위 폴더를 임의로 만들지 말 것.
- 여기는 Unity `Assets/` 안이므로 **PNG만 저장하고 `.meta` 파일은 만들지 말 것** — Unity 에디터가
  다음 임포트 시 자동 생성한다. 임시 스크립트·중간 산출물은 `Assets/` 안에 남기지 말고 스크래치패드
  디렉토리에 둘 것.
- 사용자가 다른 경로를 요청하면 그때만 그 경로에 저장하고, 아래 레지스트리 파일의 `_output_dir` 값을
  갱신한다.

## 0. 환경 준비 (Claude Code에서 세션 시작 시 한 번)

이 스킬은 Pillow(PIL)와 numpy가 있어야 동작합니다. 프로젝트/머신에 따라 없을 수 있으므로, 이 스킬로
첫 아이콘을 만들기 전에 항상 먼저 확인할 것:

```bash
python3 -c "import PIL, numpy" 2>&1 || pip install pillow numpy --break-system-packages
```
(`--break-system-packages`가 실패하거나 관리형 환경이면 가상환경을 만들어 그 안에 설치할 것:
`python3 -m venv .venv && . .venv/bin/activate && pip install pillow numpy`.)

저장 위치는 **이미 정해져 있다** — `Assets/Art/Icon/` (위 "기본 출력 경로" 참고). 사용자에게 묻지
말고, 폴더가 있는지만 확인하고(없으면 생성) 바로 아래 워크플로우로 들어갈 것.

## 출력 위치와 세트 일관성 유지 (여러 세션에 걸쳐 중요)

이 환경(claude.ai)과 달리 Claude Code는 **세션이 끝나면 대화 맥락이 사라질 수 있음** — 그래서
"이전에 만든 형제 아이템의 팔레트를 대화 기록에서 찾아 재사용"이라는 규칙만으로는 다음 세션에서
깨짐. 대신 **프로젝트 안에 작은 레지스트리 파일을 두고 세션과 무관하게 참조**할 것:

- 레지스트리 파일은 **`.claude/skills/pixel-item-icons/palettes.json`** (이 스킬 파일과 같은 폴더)에 유지한다.
  Unity가 스캔하는 `Assets/` 안에 두면 불필요한 `.meta`가 생기므로 `Assets/` 밖에 둘 것. 각 아이콘을
  만들 때마다:
  1. 이 파일이 있으면 먼저 읽어서, 요청받은 아이템과 같은 세트/테마 키(예: `"강철"`, `"미스릴"`,
     `"용비늘"`)가 이미 있는지 확인하고 있으면 그 팔레트·외곽선 색을 그대로 재사용.
  2. 새로운 세트/테마라면 다 만든 뒤 그 팔레트를 이 파일에 새 키로 추가해서 저장.
  - 값 형식은 자유롭지만, 예를 들어 `{"강철": {"ring_dark": [105,112,122], ...}, "미스릴": {...}}`
    처럼 스크립트의 팔레트 딕셔너리를 그대로 JSON으로 직렬화하면 다음에 곧바로 재사용 가능.
- 아이콘 파일 자체가 이미 프로젝트 안에 있다면(예: `Assets/Art/Icon/강철 검.png`), 레지스트리가 없어도
  기존 파일들을 눈으로 참고할 수 있지만, 정확한 RGB 값까지 복원하긴 어려우므로 레지스트리 쪽이
  더 안정적임.
- **저장 경로도 레지스트리 파일에 함께 적어둘 것** — 기본값은
  `{"_output_dir": "Assets/Art/Icon"}` 이며, 사용자가 명시적으로 다른 경로를 요청할 때만 그 값을
  갱신한다. 이 값이 있으므로 다음 세션에서도 저장 위치를 사용자에게 다시 묻지 않는다.

## 아이콘 1개를 만드는 전체 워크플로우

1. **아이템/스킬 이름을 읽고 카테고리 + 테마를 추론.** 카테고리는 어떤 모양 템플릿을 쓸지 결정
   (아래 "카테고리별 모양 템플릿" 참고). 테마(속성, 소재 등급, 세력 등)는 색 팔레트를 결정 — 이름에서
   추론할 것 (예: `불꽃/화염` → 화염 팔레트, `얼음/서리` → 얼음, `미스릴` → 옅은 은청색 + 글로우,
   `그림자/암흑` → 보이드 보라-검정, `용/드래곤` → 비늘 텍스처 + 빨강/금색, `성/천공/신성` → 흰색-금색
   성스러운 톤, `사슬` → 사슬 갑옷 고리 메쉬, `가죽` → 가죽, `판금/강철` → 강철 판금, `대마법사/현자` →
   화려한 로브형 마법사 색감 등). 정말 애매하면 가장 자연스러운 해석을 골라 진행할 것 — 요청이 정말로
   수행 불가능한 경우가 아니면 멈추고 되묻지 말 것.
2. **이미 만들어진 세트가 있는지 확인.** 사용자가 이미 형제 아이템을 만든 적이 있다면(예: `강철 검`을
   만든 뒤 `강철 방패`를 요청), 그 세트의 팔레트, 외곽선 색, 비율을 재사용해서 세트 전체가 어울리도록
   할 것. 같은 세션 안이면 대화 기록에서 이전 팔레트 딕셔너리를 찾아도 되지만, **1순위는 항상
   "출력 위치와 세트 일관성 유지" 섹션의 팔레트 레지스트리 파일을 먼저 읽는 것** — 세션이 바뀌어도
   깨지지 않는 유일한 방법임. 색을 새로 지어내지 말 것.
3. **작고 일회성인 Python 스크립트를 작성.** (아래 템플릿 참고) `N x N` numpy RGBA 그리드를 만들고,
   실루엣을 픽셀별 노이즈로 셰이딩해서 채우고, 외곽선을 추가하고, `Image.resize(..., Image.NEAREST)`로
   업스케일한 뒤 PNG로 저장. 각 스크립트는 독립적으로 완결되게 작성 — 공용 라이브러리를 만들 필요 없이
   가장 비슷한 템플릿을 복사/수정할 것.
4. **실행 후 반드시 수치로 검증.** (아래 "검증" 참고) 검사가 실패하면 코드를 반복 수정할 것.
5. **사용자가 입력한 이름 그대로 기본 출력 경로(`Assets/Art/Icon/`)에 저장**, 디렉토리 목록으로
   파일명이 정확히 맞는지 확인한 뒤 사용자에게 파일 경로를 제시할 것.
6. **디자인 선택에 대한 짧은 불릿 설명**을 제공할 것 — 이는 스스로 신뢰성 있게 얻을 수 없는 시각적
   확인을 대신하는 역할을 함.

## 캔버스 해상도 기준

기본값은 **촘촘한 그리드 + 넉넉한 최종 해상도**로, 세션 중반에 사용자가 화질 향상을 요청하면서 확립된
표준입니다:

- 그리드 크기 `N`: 대부분의 아이콘에 **64~90** 칸 정도 (보물상자나 텍스처가 많은 갑옷처럼 복잡한
  모양은 더 크게 ~80~90; 단일 UI 글리프처럼 아주 단순한 실루엣만 ~40~48 허용).
- 칸당 `scale`: 최종 이미지가 한 변 기준 **700~850px** 정도가 되도록 선택 (예: `N=64, scale=12` →
  768px; `N=80, scale=10` → 800px; `N=88, scale=9` → 792px).
- 사용자가 명시적으로 작고 단순한 것을 요청하지 않는 한, 예전의 저해상도 기본값(`N≈32-40,
  scale≈15-20`, 최종 ≈600-640px)으로 되돌아가지 말 것.
- 화살표, 체크마크, 햄버거 메뉴 같은 단순 UI 글리프는 세밀한 텍스처가 필요 없으므로 작은 그리드
  (`N=48`)를 사용해도 됨.

## 여백 / 잘림 방지 규칙

실루엣은 **캔버스 가장자리에 절대 닿으면 안 됨** — 이번 작업에서 반복적으로 나온 버그였음
("이미지가 우측에서 잘린듯 함"). 그리드를 만든 뒤에는 항상 다음을 확인할 것:

```python
arr = np.array(final_image)
mask = arr[:, :, 3] > 0
border_touch = (mask[0, :].any() or mask[-1, :].any() or
                mask[:, 0].any() or mask[:, -1].any())
```

`border_touch`가 `True`면 모양을 줄이거나, 중앙 쪽으로 이동시키거나, 캔버스(`N`)를 키운 뒤 다시
실행할 것 — `border_touch == True`인 결과물을 그대로 내보내지 말 것. 대각선 무기 아이콘의 경우 칼끝과
폼멜 주변에 최소 2~3칸의 여백을 남길 것; 활, 날개, 석궁처럼 넓게 퍼지는 모양은 곡선/부채꼴 요소가 더
멀리 뻗어나갈 수 있으므로 더 넉넉한 여백(4~6칸)이 필요함.

## 검증 (이미지를 확실히 볼 수 없으므로)

저장한 뒤에는 사용자에게 결과를 설명하기 전에 항상 다음 두 가지를 실행할 것:

1. **여백/잘림 체크** (위 내용).
2. **색상 분포 체크** — 의도한 모든 팔레트 색이 실제로 그럴듯한 비율로 렌더링됐는지 확인 (조건문이
   한 번도 실행되지 않는 등의 조용한 로직 버그를 잡아냄):

```python
arr = np.array(Image.open(path))
mask = arr[:, :, 3] > 0
print('filled:', mask.sum())
colors, counts = np.unique(arr[mask].reshape(-1, 4), axis=0, return_counts=True)
order = np.argsort(-counts)
for i in order[:16]:
    print(colors[i], counts[i])
```

출력된 색을 스크립트의 팔레트 딕셔너리와 대조 확인할 것 — 외곽선, 기본 톤들, 강조/글로우 색, 특수
소재 색 등 주요 색상이 모두 유의미한 픽셀 수로 나타나야 함. 예상한 색이 0에 가깝게 나온다면 조건문이
깨진 것임.

3. **복잡한 다부품 모양에는 선택적으로 구조적 ASCII 체크**를 추가 (예: 석궁에 활대+시위+스코프가 모두
   보이는지, 왕관에 뾰족한 첨탑 5개가 뚜렷이 있는지 확인). 그리드 해상도로 다운샘플한 뒤, 색상 버킷으로
   픽셀을 분류하는 대략적인 문자 맵을 출력해서 그 결과(항상 텍스트로 렌더링되므로 이미지 미리보기와
   달리 확실히 보임)를 눈으로 확인할 것.

이 검사들을 통과한 뒤에만 아이콘이 준비됐다고 사용자에게 말할 것.

## 공통 렌더링 기법

모든 아이콘은 동일한 저수준 레시피를 사용합니다:

1. `grid = np.zeros((N, N, 4), dtype=np.uint8)` 할당 (RGBA, 기본값은 투명).
2. 각 픽셀마다 어느 영역에 속하는지(칼날/손잡이/가드, 혹은 꽃잎/링/광선 등) 단순 기하로 판단: 직선과의
   거리, 점과의 거리, 타원/다각형 소속 여부, 혹은 아래의 대각선 axis/perp 시스템.
3. **평면 채우기가 아니라 픽셀별 랜덤 노이즈로 셰이딩** — 이것이 "픽셀 아트 텍스처" 느낌을 만드는
   핵심. 어디서나 쓰이는 패턴:
   ```python
   n = rng.random()
   val = COLOR_MID if n > 0.5 else COLOR_DARK
   if n > 0.85:
       val = COLOR_LIGHT       # 드문드문 나타나는 하이라이트 반점
   if n > 0.95:
       val = ACCENT_COLOR      # 더 드문 강조 요소 (글로우 반짝임, 룬, 불씨, 리벳 등)
   ```
   버그 수정을 위해 다시 실행해도 텍스처 전체가 다시 섞이지 않도록, 아이콘마다 **고정 시드**
   (`np.random.default_rng(<정수>)`)를 사용할 것.
4. **외곽선 처리** — 모양과 무관하게 항상 마지막에 적용: 채워진 픽셀에 인접(4방향 또는 8방향)한
   투명 픽셀은 외곽선 색이 됨.
   ```python
   filled = grid[:, :, 3] > 0
   outline_grid = grid.copy()
   for r in range(N):
       for c in range(N):
           if not filled[r, c]:
               if any(filled[r+dr, c+dc] for dr, dc in NEIGHBORS if in_bounds(r+dr, c+dc)):
                   outline_grid[r, c] = OUTLINE_COLOR
   grid = outline_grid
   ```
   기본 외곽선은 거의 검정(`(20-35, 20-35, 20-35, 255)`)이지만, 테마에 맞으면 색조를 바꿀 것: 화염/
   나무 아이템은 따뜻한 갈색-검정, 미스릴/얼음은 남색, 그림자/보이드는 짙은 보라, 성스러운 아이템은
   따뜻한 금갈색. 미스릴 세트에서 실제로 이렇게 요청받은 적 있음 ("외곽선을 검정 대신 짙은 남색으로").
5. 업스케일: `Image.fromarray(grid, 'RGBA').resize((N*scale, N*scale), Image.NEAREST)` — 픽셀의
   각진 경계를 유지하기 위해 항상 `NEAREST`를 쓸 것, bilinear/bicubic은 절대 사용하지 말 것.

## 카테고리별 모양 템플릿

### A. 대각선 무기 (검, 단검, 도끼, 완드, 지팡이)

원시 (x, y) 대신 **axis/perp 좌표계**를 사용: 크기 `N`의 그리드에서 상수 `K`(보통 `= N`)로,

```python
axis = c                  # 칼날/자루를 따라가는 위치, 0 = 좌하단, N = 우상단
perp = r + c - K           # 대각선 중심선으로부터의 부호 있는 수직 거리
```

무기는 좌하단 → 우상단으로 45도로 뻗음. `abs(perp) <= half_width(axis)`를 테스트해서 실루엣을 만들며,
`half_width`는 구간(손잡이, 가드, 칼날 테이퍼, 폼멜)마다 정의하는 함수. 한손검류의 전형적인 구간
배치(axis 값은 `N`에 비례):

- 폼멜: axis가 작은 쪽 끝에 작은 원
- 그립/손잡이: 일정한 half-width, 1~2 axis 스텝마다 밴드 색을 바꿔 감긴 손잡이처럼 보이게 함
- 가드/크로스가드: 짧은 axis 구간에서 훨씬 큰 half_width (화려한 변형은 중앙 1~2개 열에서만 추가로
  더 뻗어나가게 해서 크로스가드 팔이 펼쳐진 것처럼 위장)
- 칼날: `half_width`가 밑동에서 거의 0인 끝까지 선형(또는 이징 커브)으로 좁아짐 → 날카로운 뾰족함;
  뭉툭한/연습용 무기는 일부만 좁히고 끝을 둥글게 마감

**도끼**는 좁아지는 칼날 대신 초승달형으로: `outer(axis)`와 `inner(axis)` 반지름을(`sqrt(1 - t²)`
불룩함 함수로) 정의하고, `inner <= abs(perp) <= outer`인 곳을 자루 한쪽(외날 도끼)이나 양쪽(양날/
labrys)에 채움.

**오브나 홀더가 있는 지팡이/완드**의 경우, 홀더는 작은 방사형 "케이지"(중심점 주위로 각도별로 샘플링한
곡선 갈빗대 몇 개) + 적도 타원 고리로 만들고, 오브 자체는 각도 소용돌이 셰이딩이 있는 작은 원으로 만듦
(아래 오브 항목 참고).

**흔한 버그 주의**: 장식 요소(그립 감김, 크로스가드)를 곡선 모양의 *전역* axis 방향으로 그리면
찌그러지거나 뒤틀려 보임. 기본 모양이 곡선이라면(활 참고), 감김/밴드의 방향은 항상 그 지점에서의
곡선 자체의 *로컬* 접선에서 계산할 것, 고정된 전역 방향을 쓰지 말 것.

### B. 활

axis/perp 시스템이 아니라 **실제 (x, y) 공간의 매개변수 곡선**으로 표현 (곡선이므로):

```python
def curve_point(t):                      # t는 [0, 1], tip_bottom -> tip_top
    base = tip_bottom + t * (tip_top - tip_bottom)
    bulge = A * math.sin(math.pi * t)     # 단일 매끈한 곡선 — 기본값
    return base + perp_dir * bulge
```

- **기본값은 단일 매끈한 불룩함**(`bulge = A*sin(π·t)`)이며, 깔끔한 ')' 모양을 만듦 — 사용자가 일반
  활에 리커브(S자 굴곡) 모양을 거부하고 참고 이미지 "사냥용 활"처럼 보이길 요청하면서 명시적으로
  확립된 표준값. 컴포지트/리커브 활을 사용자가 구체적으로 요청할 때만
  (`bulge = A*sin(π·t) - B*sin(2π·t)`) 리커브를 사용할 것.
- 곡선을 촘촘히(300~500개 점) 샘플링하고, 각 픽셀에서 가장 가까운 샘플을 찾아 색/방향을 정하고,
  `np.gradient`를 샘플링된 점들에 적용해 **로컬 접선과 법선**을 구할 것 — 그립 밴드의 방향을 잡거나
  활 배(belly)와 등(back)을 다르게 셰이딩할 때 전역 axis가 아니라 이 값을 사용할 것.
- **활줄**은 동일한 불룩함 공식을 작은 진폭으로 적용한 훨씬 납작한 자체 곡선 (예: `STRING_BULGE ≈
  2~3` vs 활대 `A ≈ 10~12`)로, 자체 얇은 두께로 그릴 것 — 직선(팽팽한 현이 직선이면 사용자 피드백상
  "찌그러진/잘못된" 것으로 읽힘)도 아니고 활대와 같은 곡선도 아님.
- 그립: `t=0.5`에 가장 가까운 샘플 인덱스를 찾아, 그 샘플의 로컬 접선/법선(전역 대각선이 아니라)을
  사용해 수직 밴드 감김을 배치할 것 — 이것이 "손잡이가 찌그러진" 버그의 해결책.

### C. 화살통 / 가방 / 파우치 / 자루 (용기형 아이템)

몸체 = 무기와 같은 axis/perp 대각선 시스템을 따라 테이퍼된 모양, `half_width`가 좁은 밑동에서 넓은
상단 입구까지 커짐. 몸체를 가로지르는 대각선 스트랩(어떤 각도로 교차하는 얇은 밴드)을 추가하고,
화살통이라면 상단으로 삐져나온 화살 2~3대를 서로 다른 수직 오프셋으로 추가하며, 각각 뚜렷이 다른
색의 깃털(fletching)로 마무리 (여러 화살이 별개 사물로 읽히도록 2~3가지 다른 강조색을 쓸 것).

드로스트링/플랩 가방/인벤토리 아이콘(대각선이 아닌, 세워진 형태)은 실제 (x,y)로 만들 것: 아래로
갈수록 둥근 몸체(`y`에 대한 half-width 함수), 위쪽의 타원형 플랩, 스트랩 손잡이 고리(각도별 샘플링),
버클. "더 세분화/자세히" 요청에는: 이음매/박음질 라인(1픽셀 폭 경로), 리벳(대칭 위치의 작은 원),
자체 테두리를 가진 보조 미니 포켓, 좌/우 명암 분리(`dx < 0` vs `dx > 0`)로 저비용 입체감을 추가할 것.

### D. 방패

두 가지 계열:
- **원형 방패**: 반지름 `R`의 원, `dist >= R - rim_w`인 테두리 밴드, 중앙 보스 원, 그 사이 몸체 채움.
  "낡은" 테마라면 어두운 균열 반점을 흩뿌리고 테두리 몇 군데를 실제로 잘라낼 것(테두리를 따라 작은
  원형 패치의 알파를 0으로 설정). 비늘 갑옷 테마라면 몸체를 평면 채움 대신 아래 F항목의 겹친 비늘
  텍스처로 대체.
- **카이트/문장 방패**: `half_width(y)` 함수로 만듦 — 위쪽 1/3은 반원/사인 테이퍼, 아래쪽 2/3은 한
  점으로 선형 테이퍼. 사각형 몇 개를 합쳐 중앙 문장(십자 등)을 추가하고, 테두리를 따라 균일한 간격의
  리벳을 배치.

### E. 투구 / 모자 (정면 머리 방어구)

돔 = 타원(`(dx/rx)² + (dy/ry)² <= 1`), 위쪽 부분으로 제한; 넥가드/플레어 = 그 아래 결합된 더 넓고
낮은 두 번째 타원. T자형 바이저는 두 개의 사각형(가로 눈 밴드 + 세로 코 가드)을 돔 위에 어두운
색으로 덧그려 만듦. 장식: 테두리를 따라가는 트림 색(돔 자체 타원 경계를 따라 `1 - dist² ≈ 작음`을
테스트), 균일한 각도 간격의 리벳, 돔 정수리 위 가는 물결형 세로 밴드로 만든 선택적 크레스트/깃털.
투구 대신 부드러운/챙 있는 모자를 만들려면, 넓고 납작한 타원(챙) + 그 위에 얹힌 작은 돔(크라운),
크라운 밑단에 가로 밴드 + 버클을 사용.

### F. 몸통 갑옷 / 의복

`y` 범위에 걸친 `half_width(y)` 함수로 만듦(어깨는 넓게 → 허리는 좁게 → 밑단은 살짝 퍼짐), 어깨를
둥글게 하는 작은 타원 캡 추가. 상단 근처 삼각형/원형 영역의 알파를 0으로 만들어 V넥이나 둥근 목선을
자를 것. 소재별 텍스처:
- **천**: 평면 노이즈 채움, 중앙에 간단한 여밈 점.
- **가죽**: 노이즈 채움 + 대각선 밴돌리어 스트랩 + 버클 있는 허리 벨트.
- **사슬**: 겹친 작은 고리 메쉬 — 각 픽셀마다 홀수 행을 반 칸씩 오프셋(벽돌 패턴)하고, 각 칸 내
  로컬 좌표를 계산해서 칸의 로컬 중심까지 거리로 고리 vs 틈을 셰이딩 (아래 비늘 갑옷과 같은 기법,
  다만 칸이 훨씬 작고 스캘럽 대신 원형).
- **판금**: 거친 가로 패널 밴딩(`(y // 4) % 2` 교대) + 몇 행마다 명시적 이음매 라인 + 각 이음매의
  중앙에서 고정 오프셋만큼 떨어진 리벳 + 세로 중앙 능선; 견갑(폴드론) = 상단 양 모서리의 작은 타원 2개.
- **용비늘**: 아래 항목 참고.

### G. 장갑 / 건틀릿

손바닥 = 사각형; 손가락 4개 = 손바닥 위에 놓인 별개의 얇은 사각형들로, 길이를 조금씩 다르게 함
(예: `[7, 9, 8.5, 6.5]` 칸으로 스태거해서 검지/중지/약지/새끼가 자연스럽게 보이게), 각 손가락 끝
행 근처에서 바깥쪽 모서리를 잘라 둥근 손끝을 만듦; 엄지 = 회전된 axis(`thumb_dir`, `perp_dir` 단위
벡터)를 사용해 손바닥 옆에 대각선으로 배치한 짧은 사각형. 손목 커프 = 손바닥 아래의 살짝 더 넓은
사각형. 소재별 렌더링은 몸통 갑옷과 같은 등급별 로직을 따름(천/가죽/사슬 메쉬/관절 이음매가 있는
판금). 세트 내 모든 장갑/건틀릿에 동일한 기하 구조를 재사용하고 셰이딩 함수만 바꿀 것 — 이렇게 하면
장비 등급 사다리 전체에서 손 모양이 일관되게 유지됨.

### H. 신발 / 부츠 / 샌들

측면 프로필 실루엣: 발볼 타원 + 발목축 박스(짧으면 신발, 길면 부츠) + 바닥을 따라가는 납작한 밑창
스트립. 카테고리를 구분하려면 **발목 박스의 높이**를 다르게 할 것(낮은 신발 vs 목이 긴 부츠 vs
낮게 잘린 샌들). 끈은 발목 박스를 가로지르는 몇 개의 가로 행으로 그릴 것; 버클형 부츠는 2~3개의
가로 버클 밴드 + 작은 버클 사각형 하나로 대체. 날개 달린 부츠(속도/헤르메스 아이템)는 부츠
실루엣은 수수하게 유지하고 발뒤꿈치/발목 지점에만 **작은** 깃털 부채꼴 날개를 붙일 것 — 날개가
아이콘 전체를 지배하게 하지 말고, 양쪽 날개의 깃털 각도가 대칭(`side = ±1`을 *동일한* 확산 공식에
곱함)이 되도록 할 것, 각각 독립적으로 계산하면 대칭적으로 바깥쪽으로 펼쳐지는 대신 서로 교차하게 됨
(이번 세션에서 두 번 발생한 버그). 오픈 샌들은 발가락 근처에 가는 세로 슬릿 몇 개를 자르고, 닫힌
갑피 대신 발등 위에 교차하는 스트랩 1~2개를 명시적으로 그릴 것.

### I. 오브 / 보석 / 크리스탈 / 정수

- **오브(마력/마나/현자/시공)**: 채워진 원; 픽셀별 각도+반지름이 소용돌이 패턴을 만듦
  (`swirl = sin(angle * k + dist * f) * 0.5 + 0.5`, 2~3단계로 임계값 분할), 중심 근처의 밝은 코어,
  선택적으로 얇은 타원형 "헤일로" 링이나 금장 케이지(각도별 샘플링한 갈빗대 + 적도 타원 하나)를 바깥에
  추가. "떠다니는 마력" 느낌을 위해 오브 밖에 별개의 작은 반짝임 점 몇 개를 흩뿌릴 것.
- **패싯 보석(강화석)**: 명시적 꼭짓점 목록으로 육각형/다이아몬드 다각형을 정의하고, point-in-polygon
  테스트로 채우고, 내부의 "광원" 점으로부터의 거리로 셰이딩하되 각도에 따른 패싯 밴딩
  (`int((angle+π)/(π/3)) % 2`)을 적용한 다음, 중심에서 각 꼭짓점까지 직선을 더 어두운 색으로 다시
  그려 패싯 컷 모서리로 만듦. 상위 등급: 팔레트를 바꾸고(예: 빨강 → 보라) 오브와 똑같이 떠다니는
  반짝임 점을 추가.
- **정수/물방울**: 물방울 모양 = 원형 몸체 + 위쪽으로 갈수록 좁아지는 뾰족한 부분(원 위에서 `t` 기반
  half-width 함수), 오브처럼 소용돌이 셰이딩, 끝부분 근처에 추가로 밝은 하이라이트 밴드.
- **단일 소재(비늘/돌 등)**: 완벽한 원 대신 각도에 따른 반지름
  (`radius(θ) = base + Σ Aᵢ·sin(iθ+φᵢ)`, 몇 개의 하모닉 합)으로 불규칙한 덩어리 모양을 만들어
  자연스러운 돌/비늘 느낌을 줄 것; 필요하면 새겨진 룬이나 나이테 디테일을 추가.

### J. 용비늘 텍스처 (방패/갑옷/낱장 아이템에 재사용)

겹친 스캘럽 패턴: 표면을 벽돌 오프셋 그리드로 나누고(`cell_h`, `cell_w`, 홀수 행을 반 칸 오프셋),
각 픽셀의 칸 내 로컬 `(x, y)`를 계산하고, 타원형 "스캘럽" 지표
`(local_x/(w·0.55))² + (max(0,local_y)/(h·0.65))² <= 1`를 테스트. 비늘의 둥근 모서리로부터의 거리
`1 - scallop`으로 셰이딩(안쪽으로 말린 모서리는 어둡게, 노출된 끝은 밝게)하고 위에 통상의 노이즈
반점을 얹을 것.

### K. 해골 / 왕관 / 코인 / 상자 / 봉투 / 조준경 (기타 아이콘형 소품)

대개 앞서 설명한 2~4개의 기본 도형으로 구성됨(두개골/턱을 위한 타원, 눈구멍을 위한 작은 타원, 코/
스파이크/화살촉을 위한 삼각형, 별을 위한 다각형, 링/코인/조준경을 위한 중첩 원, 상자 뚜껑+몸체를 위한
타원 상단 사각형). "타원/사각형/삼각형/다각형으로 분해하고, 픽셀별 소속을 테스트하고, 표준 노이즈로
셰이딩하고, 마지막에 외곽선"이라는 원칙 외에 특별한 시스템은 없음. 위의 가장 비슷한 예시를 보고
적용할 것.

### L. 스킬 아이콘 (원형 뱃지 포맷)

아이템 아이콘과는 구분됨 — 이 게임의 스킬 아이콘은 자유로운 실루엣이 아니라 항상 **원형 뱃지**임:

```python
R = 29                      # N=64 기준
ring_w = 5
# 링: dist가 [R-ring_w, R] 사이  -> 테두리 색 (화려한 스타일은 각도 섹터별로 2색 교대)
# 본체: dist < R-ring_w         -> 배경 채움, 선택적으로 방사형 "에너지 광선" 섹터
#        ray = abs(sin(angle * n_rays / 2)); 임계값을 넘는 곳에 강조색 칠하기
# 그 위에 중앙 심볼(검/방패/단검/주먹/눈/번개/시계/별 등)을 그림
```

- **등급형 스킬** (예: `공격력1/2/3`, `치명확률1/2`, `방어력1/2`)은 하나의 심볼을 공유하고 등급마다
  팔레트를 승급함: 1등급 = 은색/강철 링 + 차가운 강조색, 2등급 = 금색 링 + 따뜻한 강조색, 3등급(있는
  경우) = 붉은 링 + 강렬한 주황 강조색. 등급이 올라갈수록 `n_rays`/글로우 임계값을 살짝 늘려 상위
  등급이 확실히 "더 시끄럽게" 보이게 할 것. 중앙 심볼의 기하는 등급 간에 동일하게 유지하고 색상 +
  광선 수만 바꿔서, 세트가 명확한 등급 진행으로 읽히게 할 것.
- **독자적인 개별 스킬** (`정밀 사격`, `필살`, `광폭화`, `불굴`, `응징`, `매의 눈`, `예지`, `원소
  폭발`, `재사용 단축`)은 이름의 컨셉에 맞는 고유 심볼을 가짐(조준경+화살, 3중 참격, 주먹+화염,
  금이 갔지만 빛나는 방패, 충격 지점으로 내리치는 번개, 깃털 있는 매의 눈, 소용돌이치는 제3의 눈,
  다색 원소 파편 폭발, 시계+빨리감기 화살) — 그 컨셉으로 가장 즉각적으로 읽히는 것을 고를 것;
  모든 걸 검/방패 틀에 억지로 끼워맞추지 말 것.
- 뱃지 테두리/배경 색은 대체로 어둡고 채도를 낮춰서 중앙 심볼과 그 글로우/강조색이 돋보이게 할 것.

## 수정 요청 대응하기

이 작업에서 자주 나온 피드백 패턴과 대응 방법:

- **"잘린 것 같다 / 잘리지 않게 해줘"** → 여백/잘림 체크를 실행할 것; 실제로 `False`라면 진짜 문제는
  캔버스 물리적 잘림이 아니라 대개 내부 비율 문제(예: 두 요소가 이상하게 겹침)이므로, 무작정 여백만
  늘리지 말고 기하 구조를 점검할 것.
- **"손잡이/그립이 찌그러졌다"** → 거의 항상 장식용 밴드를 그 지점의 로컬 접선이 아니라 고정된 전역
  방향으로 그렸기 때문 (활 항목 참고). 가장 가까운 곡선 샘플 자체의 그래디언트에서 방향을 구하도록
  고칠 것.
- **"더 세분화/자세히"** → 추가할 것: 이음매/박음질 라인, 리벳, 보조 하위 요소(미니 포켓, 추가 밴드),
  좌우 또는 상하 명암 분리로 가짜 입체감, 그리고/또는 두 번째 강조색 — 단순히 노이즈만 더 넣지 말 것.
- **"A 부분 크기를 키우고/줄이고 B가 부각되도록"** → 전체 대비 해당 구간의 길이 비율을 조정
  (예: 손잡이의 axis 구간을 줄이고, 겨냥부의 axis 구간을 늘림), 여백을 재확인하고 재생성할 것.
- **"픽셀을 더 작게, 화질을 올려줘"** → 새로운 표준값을 설정하는 요청: 위 "캔버스 해상도 기준" 섹션에
  따라 그리드 `N`과 최종 해상도를 대략 2배로 늘리고, 다른 지시가 없는 한 이후 모든 아이콘에도 계속
  적용할 것.
- 어떤 수정이든 재제시하기 전에 항상 두 검증을 다시 실행할 것.

        pass

    for c in range(N):

            if any(0 <= nr < N and 0 <= nc < N and filled[nr, nc] for nr, nc in neighbors):

# 기본 출력 경로 = Assets/Art/Icon (사용자가 다른 경로를 지정하지 않았을 때)

- **세션 시작 시 항상 "0. 환경 준비"부터 실행할 것** (의존성 확인 + 출력 경로/레지스트리 파일 확인).
  이걸 건너뛰면 이 스킬은 claude.ai 세션에서만 잘 동작하고 Claude Code에서는 어긋나기 쉬움.
- `present_files` 같은 도구는 없음 — 대신 저장된 경로를 사용자에게 보고할 것 (사용자의 에디터/IDE가
  이미지 미리보기를 지원한다면 열어볼 수도 있음).
- 내장된 `view` 이미지 미리보기 도구도 없음; 이 환경에는 시각적 확인 대체 수단이 전혀 없으므로 위의

  렌더링을 보여주지 않는 경우가 있었으므로, 두 환경 모두 수치 검증이 유일하게 믿을 수 있는 확인

- Pillow/numpy가 프로젝트에 이미 있다는 보장이 없음 — 매 세션 처음에 확인하고, 없으면 설치할 것
