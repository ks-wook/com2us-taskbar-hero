# 사운드 리소스 정의서

Taskbar Hero 모작 클라이언트가 사용하는 **BGM·효과음 목록과 재생 위치**를 정의한다. 에셋 사양과 트리거 지점을 확정하는 문서이며, 재생 코드(`SoundManager`)·씬 배선 등 실제 구현은 클라이언트 작업 범위다.

- 대상: `com2us-taskbar-hero-client/Assets/Sound/`
- 총 **69종** — **전부 생성 완료(69/69)**, **클라 적용 69/69**
- **생성여부**: ☑ 에셋 파일 있음 · ☐ 생성 필요
- **클라적용**: ☑ 클라이언트에 배선돼 실제로 재생됨 · ☐ 미적용. 이 칼럼 갱신은 **클라이언트 세션에서** 한다(서버 세션은 생성여부만 관리).

## 2. 규칙

### 2.1 폴더 구조

**카테고리 폴더까지만 나누고 그 안에서 더 쪼개지 않는다.** 파일명(ID)이 곧 식별자다.

```
Assets/Sound/
├── BGM/                  # 배경음 루프 + 연출 징글 (§3)
└── SFX/
    ├── UI/               # 버튼·패널·모달 공통 (§4.1)
    ├── System/           # 타이틀·계정·씬 전환·캐릭터 생성 (§4.2)
    ├── Battle/
    │   ├── Common/       # 입장·피격·사망·레벨업·보상 (§5.1)
    │   ├── Knight/       # 기사 (§5.2)
    │   ├── Archer/       # 레인저 (§5.3)
    │   ├── Mage/         # 마법사 (§5.4)
    │   ├── Slayer/       # 슬레이어 (§5.5)
    │   └── Monster/      # 몬스터·보스 (§5.6)
    ├── Growth/           # 인벤토리·스킬·룬·큐브·메일·출석 (§6)
    └── Gacha/            # 뽑기 시전·슬롯 공개·등급 연출 (§7)
```

재생성 변주가 필요하면 폴더를 파지 말고 파일명으로 구분한다(`bgm_title_v2.mp3`).

### 2.2 네이밍

- 소문자 스네이크 케이스 + ASCII: `bgm_title`, `sfx_knight_power_strike`
- 접두사: `bgm_`(배경음) / `jingle_`(연출 징글) / `sfx_`(효과음) / `amb_`(앰비언트 루프)

### 2.3 포맷

전 항목 **`.mp3` 128kbps CBR**(생성 도구 출력 포맷). Unity가 MP3를 정상 임포트하므로 변환 없이 사용한다.

| 종류 | Unity Import 설정 | 길이 |
| --- | --- | --- |
| BGM | Streaming, Load in Background | 90초 루프 |
| 징글 | Compressed in Memory | 3~4초 |
| 효과음 | Decompress on Load | 1~2초 |
| 앰비언트 루프 | Streaming | 30초 루프 |

- **효과음 길이가 1초 이상인 이유**: 생성 모델의 최소 길이가 1초다. 실제 소리는 앞 0.1~0.3초에 몰려 있고 뒤는 무음·잔향이라 재생에 지장은 없다. 정밀하게 맞추려면 임포트 시 트리밍하거나 재생 후 조기 정지한다.
- **루프 이음매**: MP3는 인코더 패딩 때문에 완전 무결 루프가 어렵다. 붙여 들었을 때 튀면 크로스페이드 루프로 처리하거나 OGG로 재인코딩한다.

### 2.4 볼륨 카테고리

`Master` / `BGM` / `SFX` 3채널. 이 게임은 **작업표시줄에 상주하는 항상-위 소형 창**(`TaskbarWindow.cs`)이라 장시간 켜두는 사용 패턴이므로:

- 기본 마스터 볼륨을 낮게(0.4~0.5) 잡는다.
- 창 포커스 아웃 시 자동 감쇠·뮤트 옵션을 둔다.

| `sfx_slayer_cleave` | 403 강한일격(주변 광역 참격) | `CastSkill()` → `DealAreaDamageAfter()` | 2초 | ☑ | ☑ |
- **내려찍기만 발동음과 임팩트음을 나눈다.** `slamAirTime`(기본 0.46초) 동안 캐릭터가 공중에 떠 있고 데미지·이펙트는 착지 후에 나므로, 한 파일로 처리하면 소리와 그림이 반 박자 어긋난다. 도약 whoosh는 시전 순간, 충격음은 `SlamImpactAfter` 콜백에 붙인다.
- **`sfx_slayer_berserk`는 "얻는 소리"가 아니라 "대가를 치르는 소리"** 다 — 시전 순간 현재 체력의 일정 비율을 잃고(20%→12%) 6초간 공격 속도·흡혈을 얻는 고위험 버프이므로, 기사의 `sfx_knight_rage`(순수 강화)와 달리 **살점이 찢기는 저음 + 광기 어린 상승**으로 구분한다.
- **흡혈 회복(coefType 5)에는 전용음을 두지 않는다.** `ScheduleLifesteal()`은 타격마다 회복을 걸어 공격 속도 버프 중 초당 여러 번 발생하므로, 소리를 붙이면 청각 피로가 크다. 회복은 **초록 힐 숫자(시각)** 로만 표현한다.
- **무기 잔상 색 변화**(`WeaponAfterimage` 노랑 → 광폭화 중 붉은색)도 시각 전용이며 별도 사운드를 두지 않는다.

## 6. 효과음 — 성장·편의

`SFX/Growth/` — 7종 **전부 생성 완료**. 결과의 무게가 다른 것만 전용음을 두고, 나머지 성장 액션은 §8의 공용 UI음을 쓴다.

| ID | 상황 | 트리거 지점 | 길이 | 생성여부 | 클라적용 |
| --- | --- | --- | --- | --- | --- |
| `sfx_item_equip` | 장비 장착·해제 | `InventoryTooltip.OnEquip()` / `OnUnequip()` | 1초 | ☑ | ☑ |
| `sfx_gold_spend` | 골드 차감(인벤토리 확장·캐릭터 생성·룬 강화·큐브 제작) | 골드 차감을 동반한 모든 성공 응답 | 1초 | ☑ | ☑ |
| `sfx_upgrade_success` | 스킬 레벨업 · 룬 강화 · 큐브 레벨업 · 인벤토리 확장 | `SkillPanelController.OnLevelUp()` · `RunePanelController.OnUpgrade()` · `InventoryPanelController.OnExpandSuccess()` | 2초 | ☑ | ☑ |
| `sfx_cube_combine` | 큐브 조합·제작 성공 | `CubePanelController.OnAction()` (Combine·Craft) | 2초 | ☑ | ☑ |
| `sfx_reward_claim` | 메일 수령 · 출석 도장 · 오프라인 보상 수령 | `MailPanelController.OnClaim()` · `AttendancePanelController.OnClaim()` · `OfflineRewardPanelController` | 1초 | ☑ | ☑ |
| `sfx_enhance_hammer` | **장비 강화 — 망치질**(모루 타격 1타. 실측: 앞 0.18초 무음 + 0.7초 꼬리) | 강화 버튼 → `POST /api/game/inventory/enhance` **요청 시작 시**(응답을 기다리지 않는다). 이펙트의 3타(6·16·26프레임)에 맞춰 **3번 재생** — `EnhanceFxOverlay.PlayHammer()` | 2초 | ☑ | ☑ |
| `sfx_enhance_success` | **장비 강화 성공 — 촤라랑 빛나는 완성음** | 강화 성공 응답(`enhanceLevel` 상승) 수신 후, 망치질이 끝나는 시점 — `EnhanceFxOverlay.PlaySuccess()` | 2초 | ☑ | ☑ |

**장비 강화는 두 소리를 순서대로 쓴다(확정).** 강화는 [인벤토리/아이템/큐브 기획서](inventory-item-cube-기획서.md) 5.3대로 **실패·하락·파괴가 없어** 결과 분기가 없다. 그래서 "성공/실패를 알리는 소리"가 아니라 **작업 → 완성**의 2단 연출로 잡는다.

```
강화 버튼 클릭
  → sfx_enhance_hammer × 3   # 이펙트가 내려찍는 3타에 각각 1번(요청과 동시에 시작 — 응답 지연을 기다리는 공백을 메운다)
  → 성공 응답 + 망치질 종료
      → sfx_enhance_success  # 촤라랑 빛나는 완성음 + 강화 단계 텍스트 갱신
```

- **망치음을 요청 시작에 붙이는 이유**: 응답을 받은 뒤 소리를 내면 왕복 지연만큼 조작이 무반응으로 느껴진다. 강화는 결과가 확정 상승이라 **소리를 먼저 내도 결과와 어긋날 위험이 없다**(가챠처럼 결과에 따라 소리가 갈리는 연출과 다르다).
- **파일은 1타이고, 3타는 클라이언트가 3번 재생해 만든다(실측 확정).** `sfx_enhance_hammer`는 길이 2.06초지만 실제 내용은 **타격 1회**다(앞 0.18초 무음 → 0.20초 피크 → 약 0.7초 꼬리, 이후 무음). 반면 이펙트(`EquipEnhanceHammer` 30프레임)는 10프레임 주기로 **3번** 내려찍으므로(스파크 폭발 = 6·16·26프레임), `EnhanceFxOverlay`가 각 타격 프레임마다 이 소리를 1번씩 재생한다. 파일 앞 무음 0.18초만큼 **앞당겨 트리거**해 소리의 타격이 스파크와 같은 순간(오차 20ms)에 오게 한다.
- **다만 실패 응답이 오면 망치음을 끊고 `sfx_ui_error`로 덮는다**(골드 부족 `InsufficientCurrency`·상한 도달 `MaxEnhanceReached`). 정지는 `SoundManager.StopSfx`(연출 스킵용, §1)를 그대로 쓴다.
- **`sfx_upgrade_success`를 재사용하지 않는 이유**: 그 소리는 스킬·룬·큐브·확장이 공유하는 **가벼운 상승 차임**이라, 골드를 크게 쓰고 장비 스탯이 오르는 강화의 무게를 담지 못한다. 강화는 **금속을 두드리는 물리적 작업감**이 핵심이라 음색 계열 자체가 다르다.
- **강화 비용 골드 차감음은 생략한다.** `sfx_gold_spend`가 망치음과 같은 순간에 겹쳐 탁해지므로, 가챠 시전음과 같은 규칙(§7)을 따라 **전용음이 있으면 골드음을 내지 않는다**.
- **단계별로 소리를 바꾸지 않는다.** +1과 +10의 차이는 강화 단계 텍스트·이펙트(시각)로 표현하고, 사운드는 두 종을 그대로 재사용한다(파일 수 증가 대비 체감 이득이 작다).

## 7. 효과음 — 가챠(뽑기)

`SFX/Gacha/` — 6종 **전부 생성 완료**. 가챠는 [가챠(뽑기) 기획서](gacha-기획서.md) 5.2의 `pull` 응답 하나로 결과가 전부 확정되고, 클라이언트는 그 결과를 **연출로 풀어 보여 주기만 한다** — 사운드도 이 연출 타임라인에 얹힌다. 다른 화면과 달리 **등급이 곧 감정의 크기**라, 성장·UI 공용음으로는 "전설이 떴다"를 표현할 수 없어 별도 카테고리를 둔다.

| ID | 상황 | 트리거 지점 | 길이 | 생성여부 | 클라적용 |
| --- | --- | --- | --- | --- | --- |
| `sfx_gacha_pull_single` | 1연 뽑기 시전(`pullType=1`) | 뽑기 버튼 → `pull` 성공 응답 수신 후 연출 시작 | 2초 | ☑ | ☑ |
| `sfx_gacha_pull_multi` | 10연 뽑기 시전(`pullType=2`) | 위와 동일, `pullType=2` 분기 | 2초 | ☑ | ☑ |
| `sfx_gacha_slot_reveal` | 결과 슬롯 1칸 공개(순차 오픈) | `results[]`를 `seq` 순으로 여는 각 슬롯(`gacha_result_slot`) | 1초 | ☑ | ☑ |
| `sfx_gacha_grade3` | **희귀(등급 3)** 결과 연출 | `Art/UI/Gacha/3성연출.mp4` 재생 시작 | 2초 | ☑ | ☑ |
| `sfx_gacha_grade4` | **영웅(등급 4)** 결과 연출 | `Art/UI/Gacha/4성연출.mp4` 재생 시작 | 3초 | ☑ | ☑ |
| `sfx_gacha_grade5` | **전설(등급 5)** 결과 연출 | `Art/UI/Gacha/5성연출.mp4` + `Art/Effect/UI/FiveStarSlotGlow` 스프라이트 시퀀스 | 4초 | ☑ | ☑ |

**등급 연출음은 3·4·5등급만 둔다(확정).** 노말(1)·고급(2)은 연출 영상 자체가 없고 슬롯이 그냥 열리므로 `sfx_gacha_slot_reveal`로 끝낸다. 등급이 올라갈수록 길이(2→3→4초)와 무게가 커져 **소리만 듣고도 무엇이 떴는지 안다**.

**10연 연출 순서와 사운드**

```
sfx_gacha_pull_multi          # 뽑기 시전(1회)
  → seq 1..10 순차 공개
      등급 1·2 → sfx_gacha_slot_reveal
      등급 3   → sfx_gacha_slot_reveal + sfx_gacha_grade3
      등급 4   → sfx_gacha_slot_reveal + sfx_gacha_grade4
      등급 5   → sfx_gacha_slot_reveal + sfx_gacha_grade5 (+ FiveStarSlotGlow)
  → 결과 요약판 표시: sfx_ui_panel_open (§8)
```

- **최고 등급 연출은 하나만 재생한다.** 10연에서 3등급이 여러 번 나오면 등급 연출음을 매번 겹쳐 울리지 말고, **묶음 안 최고 등급 1회**만 크게 내고 나머지는 슬롯 공개음으로 처리한다(같은 SFX 연타 방지는 §9.3과 동일한 이유).
- **천장·보장 회차에 전용음을 두지 않는다.** `isPity`(하드 천장 확정)·`isGuaranteed`(10연 보장 대체)는 결국 그 등급으로 나오므로 **등급 연출음이 그 역할을 한다**. 천장으로 받았다는 사실은 슬롯의 시각 배지와 천장 게이지(`remainingToPity`)로 표시한다.
- **비용 차감음은 `sfx_gold_spend`(§6)를 재사용**하고, 뽑기 시전음과 겹치므로 **시전음이 있으면 생략**한다.
- **뽑기 결과는 서버가 확정한 값이다.** 클라이언트가 연출 도중 등급을 다시 굴리지 않으므로, 사운드는 응답을 받은 뒤 **한 번에 스케줄링**하면 된다(연출 중 결과가 바뀔 일이 없다).
- **연출 스킵**을 지원하면 재생 중인 등급 연출음을 **함께 정지**한다(영상만 끊고 소리가 남으면 다음 슬롯 소리와 겹친다).

- 스킬 SFX는 `PartyMemberConfig.EffectFor(skillCode)`처럼 **스킬 코드 → 클립** 매핑을 두면 이펙트 배선과 대칭이 된다.

| 지점 | 주의 |

| 가챠 등급 연출 영상 | 등급 연출은 `Art/UI/Gacha/{3,4,5}성연출.mp4`(`VideoPlayer`)다. **오디오 트랙 없는 영상 + 별도 SFX** 조합이므로 재생 시작 프레임에 사운드를 함께 걸고, 스킵 시 둘 다 정지한다. |

## 10. 생성 방법

`tools/poe-sfx/generate_sound.py`(Poe OpenAI 호환 API). 키는 `tools/poe-sfx/.env`의 `POE_API_KEY` — `.gitignore` 제외 대상이라 커밋되지 않는다.

```bash
python tools/poe-sfx/generate_sound.py "<영어 프롬프트>" \
  "com2us-taskbar-hero-client/Assets/Sound/SFX/Battle/Knight/sfx_knight_basic.mp3" --duration 1
```

- **모델**: 기본값 `stable-audio-2.5`(텍스트→오디오). **TTS 봇(`elevenlabs-v3`·`*-tts` 등)은 프롬프트를 낭독한 음성을 반환하므로 쓰지 않는다** — 스크립트가 모델명으로 감지해 경고한다.
- **길이**: `--duration`을 반드시 지정한다. 미지정 시 약 190초가 나온다. 비용이 길이에 비례하므로 효과음은 1~2초로 잡는다.
- **검증**: 스크립트가 저장 후 MP3 프레임을 훑어 길이·비트레이트를 출력하고, 요청 길이의 2배를 넘으면 TTS 낭독 의심으로 경고한다.
- **병렬 실행**: 셸에서 `&`로 3~4개씩 묶으면 대기 시간이 크게 준다.
- **라이선스**: 전 트랙이 이 도구로 생성한 오리지널 오디오다. 외부 소스를 추가할 경우 상용 제약이 없는 것(CC0 등)만 쓰고 확보처를 여기에 기록한다.

### 10.1 일괄 생성·재생성

여러 개를 만들 때는 `<경로>\t<초>\t<프롬프트>` 목록(부록의 표를 그대로 옮긴 TSV)을 만들어 **동시 4개**로 돌린다. 그 이상 늘려도 봇 대기열에서 막히고, 실패 시 어느 항목인지 찾기만 어려워진다.

```bash
# 한 줄 = 한 파일. 이미 있고 크기가 0이 아니면 건너뛴다(중단 후 재실행 안전).
cat sfx_list.tsv | xargs -d '\n' -P 4 -I{} bash -c 'gen "$@"' _ {}
```

- **재생성**: 마음에 안 드는 소리는 **대상 파일을 지우고** 같은 목록을 다시 돌리면 그 항목만 새로 만든다. 변주를 남겨 비교하려면 §2.1대로 `_v2` 파일명을 쓴다.
- **검증**: 생성 후 `generate_sound.probe_mp3()`로 전 파일 길이를 훑어 **요청 길이의 2배를 넘는 것이 없는지** 확인한다(넘으면 TTS 낭독 의심). 현재 67종 모두 요청 길이 +0.07초 이내다.
- **Unity 반영**: 파일만 두면 되고, 에디터를 열 때 임포트되며 `SoundDatabaseBuilder`가 §9.1 로드 설정을 교정한다. 배선(클립 참조·재생 호출)은 별개 작업이다.
