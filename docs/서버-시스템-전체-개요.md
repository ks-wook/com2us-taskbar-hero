## 1. 게임 개요

**TBH: Task Bar Hero**는 Windows 작업표시줄에 붙는 작은 창에서 돌아가는 방치형(idle) RPG다. 플레이어가 다른 일을 하는 동안 픽셀 아트 파티가 던전을 자동 전투로 진행하며 레벨업·전리품 획득이 자동으로 이루어진다.

- **핵심 특징**: 항상 실행되는 백그라운드 앱, 자동 전투, 방치 중 성장(경험치/골드/전리품 자동 획득)
- **콘텐츠 규모(원작 기준)**: 3개 Act × 4개 난이도, 50종 이상 몬스터, 500종 이상 아이템, 6개 직업(클래스)
- **경제 특징(원작)**: 전리품을 스팀 마켓에 실제 지갑 자금으로 판매 가능 → 봇/골드 파밍/치트가 극심했고 서버 부하·오탐지 밴 문제 발생 (동시 접속 14만 사례)
- **본 프로젝트**: 위 게임의 **모작 서버**. 클라이언트는 Unity, 서버는 .NET 10 (AccountServer + GameServer + 공통 라이브러리 TaskbarHero.Common)

## 2. 핵심 게임플레이 루프

```
방치(자동 전투) → 몬스터 처치 → 골드·경험치·전리품·재료 획득
   → 성장(장비/스킬/룬/큐브) → 더 강한 스테이지 진행 → 반복
   └ (오프라인 동안에도 진행) → 재접속 시 그동안의 보상 정산
```

방치형 장르 특성상 **오프라인 진행 보상 계산**이 서버 권위(server-authoritative)로 이루어져야 하며, 이것이 서버 설계의 핵심 축이다.

## 3. 게임 시스템 요약 (원작 기준)

| 시스템 | 내용 |
|---|---|
| 직업(클래스) | Knight, Ranger, Priest 등 6종. 일부는 해금/유료 |
| 장비/아이템 | 500종 이상, 슬롯 장착, 등급(Cosmic 등 고등급 존재) |
| 스킬 | 경험치로 얻는 포인트로 레벨업 |
| 룬(Rune Tree) | 골드로 구매, 장기 성장 축 |
| 큐브(Hero-dric Cube) | 합성(등급 상승)·분해(골드 전환)·제작. 사용할수록 성장 |
| 스테이지 | 3 Act × 2 난이도 × 3 스테이지(=18), 벽에 막히면 이전 스테이지 재파밍 가능(하드월 없음) |
| 전리품/드롭 | 골드, 장비, 제작 재료 |
| 재화 | 골드(주 재화), (원작) 스팀 지갑 자금 |
| 거래 | 교역선(Trade Ship)을 통한 플레이어 간 아이템 거래소 (원작은 스팀 마켓 연동) |

## 4. 서버 개발 영역

아래는 서버가 책임져야 할 기능 도메인의 큰 분류다. 세부 명세는 도메인별 기획서로 분리한다.

### 4.1 계정 / 인증 — `AccountServer`
- 계정 생성·로그인·인증 토큰 발급
- 세션 관리, GameServer 접근 인가
- (모작에서 스팀 연동 대체 방식 결정 필요 — 자체 계정 / 플랫폼 계정)
- 📄 세부 기획: [계정/로그인 기획서](세부/account-login-기획서.md)

### 4.2 게임 데이터 저장·로드 — `GameServer`
- 플레이어의 진행 상태(스테이지, 직업, 레벨, 재화, 인벤토리, 성장 트리) 영속화
- 저장 주기/시점 정책(주기적 자동 저장, 주요 이벤트 시 저장)
- 📄 세부 기획: [세이브 데이터 구조/저장 정책 기획서](세부/save-data-기획서.md)

### 4.3 방치형(오프라인) 보상 정산 — `GameServer`
- 마지막 접속 시각 기준 경과 시간 계산 → 골드·경험치·전리품 산출
- **서버 권위 계산**으로 클라이언트 조작 차단
- 상한(캡)·시간당 산출량·오프라인 최대 누적 시간 정책
- 📄 세부 기획: [오프라인 보상 정산 기획서](세부/offline-reward-기획서.md)

### 4.4 인벤토리 / 아이템 — `GameServer`
- 아이템 획득·장착·삭제, 인벤토리 용량 관리
- 큐브 시스템(합성/분해/제작) 결과의 서버 검증 및 반영
- 📄 세부 기획: [인벤토리/아이템/큐브 기획서](세부/inventory-item-cube-기획서.md)

### 4.5 성장 시스템 — `GameServer`
- 직업/스킬/룬/장비 강화 등 성장 요소의 상태 관리와 재화 소모 검증
- 📄 세부 기획: [성장 시스템(직업/스킬/룬) 기획서](세부/growth-기획서.md) (장비 강화는 각 도메인 문서 참조)

### 4.6 스테이지 / 전투 결과 — `GameServer`
- 스테이지 진행도, 난이도, 클리어 기록 관리
- 자동 전투 결과의 무결성 검증(클라이언트 보고 vs 서버 규칙), 클리어 보상 서버 지급
- 📄 세부 기획: [스테이지/전투 결과 기획서](세부/stage-battle-기획서.md)

### 4.7 거래소 / 교역선(Trade Ship) — `GameServer` **(필수)**
- 원작의 스팀 마켓을 대체하는 **플레이어 간 아이템 거래소**. 필수 구현 대상
- **거래 형태**: 원작은 아이템을 스팀 마켓에 팔아 실제 스팀 지갑 자금을 얻는 구조지만, 본 모작에서는 **플레이어 간 아이템을 거래하고 그 대가가 게임 머니(골드 등 인게임 재화)로 판매자에게 들어오는 형태**로 구현한다. (실물 화폐 연동 없음)
- 아이템 등록(판매 등록)·구매·취소, 거래 시 소유권 이전과 재화 정산의 **원자성** 보장
- 등록은 **에스크로**(아이템을 인벤토리에서 거래소 보관으로 이동), 판매 대금은 **메일(4.8) 경유**로 판매자에게 지급
- 중복 판매·아이템 복제·거래 취소 경합 등에 대한 서버측 검증
- 📄 세부 기획: [거래소 / 교역선 기획서](세부/trade-기획서.md)

### 4.8 메일(보상) 수신 시스템 — `GameServer`
- 운영/보상/거래 결과 등을 우편함으로 지급하고 플레이어가 수령
- 첨부(재화·아이템) 수령 처리, 만료·읽음/미읽음 상태, 일괄 수령
- 지급-수령의 원장 관리(중복 수령 방지)
- 📄 세부 기획: [메일 기획서](세부/mail-기획서.md)

### 4.9 출석부 보상 시스템 — `GameServer`
- 일자별 접속 보상(출석 체크). 날짜 경계는 **서버 KST(UTC+9) 자정**, 현황은 **월 단위**
- 하루 1회 수령 제한의 서버측 검증(중복 수령 방지)
- 지급은 **메일(4.8) 경유**로 확정(출석 획득 시 보상 메일 발급 → 우편함 수령 시 계정 반영). 발급 메일은 **7일 후 만료**
- 연속/누적 출석 보너스·과거일 소급 수령·다른 달 조회는 **범위에서 제외**
- 📄 세부 기획: [출석부 보상 시스템 기획서](세부/attendance-기획서.md)

### 4.10 정적 게임(기획) 데이터 제공
- 아이템/몬스터/스테이지/수치 테이블 등 마스터 데이터의 정의·적재
- 본 프로젝트(학습 목적)는 마스터 데이터를 **클라이언트 빌드에 번들**로 포함하고 서버도 같은 원천을 기동 시 자체 로드한다(런타임 다운로드·버전 협상 API 없음)
- 📄 세부 기획: [마스터(기획) 데이터 & 클라이언트 연동 기획서](세부/master-data/master-data-기획서.md) — 마스터 테이블 정의 + 클라가 보유·소비하는 데이터 범위·스키마·Unity 연동 코드

## 5. 아키텍처 관점

- **2개 서버 분리**: 계정/인증(AccountServer)과 게임 로직(GameServer)을 분리. 인증과 게임 트래픽의 책임·확장 경로를 분리한다.
- **서버 권위 원칙**: 재화·성장·오프라인 보상 등 이득이 되는 모든 계산은 서버가 최종 확정한다. 클라이언트 보고는 신뢰하지 않는다.
- **공통 계약(`TaskbarHero.Common`)**: 서버-클라이언트가 공유하는 에러 코드(`ErrorCode`), DTO 등을 여기에 둔다. `netstandard2.0` 유지(Unity 호환).
- **상태 영속성**: 방치형 특성상 "마지막 저장 시각"이 곧 보상 계산의 기준점이므로 저장 정책이 게임성과 직결된다.

### 마스터 데이터로 정의해야 할 항목 (콘텐츠·밸런스)

문서 구조는 [마스터 데이터 기획서](세부/master-data/master-data-기획서.md)(위 10번)에 정의돼 있으나, 실제 **종류·수치 값**은 아직 채워야 한다. 각 마스터 테이블별로 정리한다:

| 항목(종류) | 마스터 테이블 | 정의할 내용 |
|---|---|---|
| 재화 종류 | `item_master`(item_type=3) | 골드 등 재화 목록(유료 재화 도입 여부 포함) |
| 직업 종류 | `class_master` | 기사·레인저·마법사(현재 3종, 추후 추가)·기본 스탯 |
| 레벨 곡선 | `level_master` | 레벨별 요구 경험치·스탯·스킬 포인트 |
| 장비/아이템 종류 | `item_master` | 무기·보조무기·투구·갑옷·장갑·신발·재료, 클래스/레벨 제한 |
| 장착 슬롯 | `equip_slot_master` | 장비 슬롯 정의 |
| 강화 규칙 | `enhance_master` | 강화 단계별 비용·효과 |
| 스킬 종류 | `skill_master` (+`skill_coefficient`) | 직업별 액티브/패시브 스킬 정의, 레벨·타입별(공격/버프/디버프) 계수·지속시간은 자식 테이블 |
| 룬 | `rune_master` | 룬 트리·선행·레벨별 비용·효과 |
| 큐브 | `cube_master` | 큐브 레벨별 규칙·합성/분해/제작 |
| 몬스터 | `monster_master` | 몬스터 전투 스탯 |
| 스테이지 | `stage_master` | Act×난이도×스테이지 보상 |
| 스테이지 보상 | `stage_reward` | 클리어 골드·경험치·등급별 아이템 드롭 확률 |
